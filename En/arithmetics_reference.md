# arithmetics — module reference

> **Import:** no explicit `import` is needed — every procedure and operator in this module is part of `system` and is available in any Nim file without an import declaration.
> **Scope:** the language's basic arithmetic: ordinal operations (succ/pred/inc/dec), signed and unsigned integer operators, division and remainder, bitwise operations and shifts, compound assignment operators, floating-point arithmetic, and a separate group of "wrap-around" operations that never raise an overflow exception.

Almost every procedure in this module is declared with the `{.magic: "...".}` pragma — this means the actual implementation is built directly into the compiler (the code generator emits a machine instruction), and the `proc` body, where present, exists only for documentation and `runnableExamples`. The module's general convention: for signed integers the operations `+`, `-`, `*`, `div`, `mod`, `inc`, `dec`, `succ`, `pred` raise `OverflowDefect` when the result falls outside the type's range (or produce a compile-time error for constants), whereas the unsigned (`uint`) versions of the same operations, and a separate group of operators with `%` in their name (`+%`, `-%`, `*%`, `/%`, `%%`), implement modular (wrap-around) arithmetic and never raise an overflow exception.

## I. Ordinal arithmetic: succ, pred, inc, dec

### 1. `succ`

```nim
proc succ*[T: Ordinal, V: SomeInteger](x: T, y: V = 1): T
```

**What it does.** Returns the `y`-th successor of value `x` within its ordinal type (by default the next value, `y = 1`). Works for any `Ordinal` type: integers, `char`, `bool`, `enum`. If the result falls outside the upper bound of the type's range (for example `succ(high(int8))`), `OverflowDefect` is raised; for constant expressions the compiler reports an error at compile time instead.

**Implementation notes.** The procedure is marked `{.magic: "Succ".}` — the actual code is generated by the compiler directly as a machine addition instruction with overflow checking; the Nim body exists only for documentation.

**Parameters:**
- `x: T` — the immutable source value of any ordinal type.
- `y: V` — how many steps forward to take, default `1`; can be negative, in which case `succ` effectively behaves like `pred`.

**Examples:**

```nim
assert succ(5) == 6
assert succ(5, 3) == 8
assert succ('a') == 'b'
doAssertRaises(OverflowDefect):
  discard succ(high(int8))
```

---

### 2. `pred`

```nim
proc pred*[T: Ordinal, V: SomeInteger](x: T, y: V = 1): T
```

**What it does.** Returns the `y`-th predecessor of value `x` (by default the previous value). Symmetric to `succ`: going below the type's lower bound raises `OverflowDefect`.

**Implementation notes.** Also `{.magic: "Pred".}` — a direct machine subtraction instruction with overflow checking.

**Parameters:**
- `x: T` — the source value of an ordinal type.
- `y: V` — how many steps back to take, default `1`.

**Examples:**

```nim
assert pred(5) == 4
assert pred(5, 3) == 2
doAssertRaises(OverflowDefect):
  discard pred(low(uint8))
```

---

### 3. `inc`

```nim
proc inc*[T: Ordinal, V: SomeInteger](x: var T, y: V = 1)
```

**What it does.** The mutating counterpart of `succ` — increments `x` in place instead of returning a new value. Shorthand for `x = succ(x, y)`. The same overflow conditions apply as for `succ`.

**Parameters:**
- `x: var T` — the mutable variable of an ordinal type.
- `y: V` — the increment amount, default `1`.

**Examples:**

```nim
var i = 2
inc(i)
assert i == 3
inc(i, 3)
assert i == 6
```

---

### 4. `dec`

```nim
proc dec*[T: Ordinal, V: SomeInteger](x: var T, y: V = 1)
```

**What it does.** The mutating counterpart of `pred` — decrements `x` in place. Shorthand for `x = pred(x, y)`.

**Parameters:**
- `x: var T` — the mutable variable of an ordinal type.
- `y: V` — the decrement amount, default `1`.

**Examples:**

```nim
var i = 2
dec(i)
assert i == 1
dec(i, 3)
assert i == -2
```

## II. Signed arithmetic operators for integers

This group covers `int`, `int8`, `int16`, `int32`, `int64` — each operator has a separate overload for each of these five types, all implementing the same semantics; the examples below show `int`.

### 1. `+` (unary)

```nim
proc `+`*(x: int): int
```

**What it does.** Unary plus, does not change the value — it exists only for symmetry with unary minus and to make the sign explicit in expressions like `+5`.

**Examples:**

```nim
assert +5 == 5
assert `+`(-5) == -5
```

---

### 2. `-` (unary)

```nim
proc `-`*(x: int): int
```

**What it does.** Negates `x`. Edge case: for `int64` unary minus has a separate overload with the `"UnaryMinusI64"` magic, because `-low(int64)` does not fit into `int64` and must raise `OverflowDefect` instead of silently overflowing.

**Examples:**

```nim
assert -5 == 0 - 5
assert -(-5) == 5
doAssertRaises(OverflowDefect):
  discard -low(int64)
```

---

### 3. `+` (binary)

```nim
proc `+`*(x, y: int): int
```

**What it does.** Adds two integers. Raises `OverflowDefect` if the sum falls outside the type's range.

**Examples:**

```nim
assert 2 + 3 == 5
doAssertRaises(OverflowDefect):
  discard high(int8) + 1'i8
```

---

### 4. `-` (binary)

```nim
proc `-`*(x, y: int): int
```

**What it does.** Subtracts `y` from `x`. Like addition, it raises `OverflowDefect` when the result goes outside the type's range.

**Examples:**

```nim
assert 5 - 3 == 2
doAssertRaises(OverflowDefect):
  discard low(int8) - 1'i8
```

---

### 5. `*` (binary)

```nim
proc `*`*(x, y: int): int
```

**What it does.** Multiplies two integers, with the same overflow check.

**Examples:**

```nim
assert 3 * 4 == 12
doAssertRaises(OverflowDefect):
  discard high(int32) * 2'i32
```

---

### 6. `div`

```nim
proc `div`*(x, y: int): int
```

**What it does.** Integer division truncated toward zero — the result is always rounded toward zero, not downward. This distinguishes `div` from `floorDiv` in the `math` module. Dividing by `0` raises `DivByZeroDefect`.

**Implementation notes.** A rough equivalent is `math.trunc(x / y).int`, but without an intermediate pass through floating-point numbers and without losing precision on large values.

**Examples:**

```nim
assert (1 div 2) == 0
assert (7 div 3) == 2
assert (-7 div 3) == -2
assert (7 div -3) == -2
assert (-7 div -3) == 2
doAssertRaises(DivByZeroDefect):
  discard 7 div 0
```

---

### 7. `mod`

```nim
proc `mod`*(x, y: int): int
```

**What it does.** The remainder of integer division, consistent with `div` via the identity `x == (x div y) * y + (x mod y)`. The sign of the result always matches the sign of `x` (unlike a mathematical modulo, where the sign matches `y`). Dividing by `0` raises `DivByZeroDefect`.

**Examples:**

```nim
assert (7 mod 5) == 2
assert (-7 mod 5) == -2
assert (7 mod -5) == 2
assert (-7 mod -5) == -2
doAssertRaises(DivByZeroDefect):
  discard 7 mod 0
```

## III. Arithmetic for unsigned integers

### 1. `+`, `-`, `*` for uint

```nim
proc `+`*(x, y: uint): uint
proc `-`*(x, y: uint): uint
proc `*`*(x, y: uint): uint
```

**What it does.** The same three operations as in section II, but for `uint`/`uint8`/`uint16`/`uint32`/`uint64`. The key difference from the signed versions: unsigned arithmetic in Nim performs modular (wrap-around) addition/subtraction/multiplication and never raises `OverflowDefect` — overflow simply "wraps" around the type's range, as in C.

**Implementation notes.** The `"AddU"`, `"SubU"`, `"MulU"` magics correspond to unsigned machine instructions on the processor, for which the very notion of overflow is undefined at the hardware level — so the compiler does not insert a check.

**Examples:**

```nim
assert 3'u8 + 4'u8 == 7'u8
assert 0'u8 - 1'u8 == 255'u8       # wraps below the range's lower bound
assert high(uint8) + 1'u8 == 0'u8 # wraps past the range's upper bound
```

---

### 2. `div`, `mod` for uint

```nim
proc `div`*(x, y: uint): uint
proc `mod`*(x, y: uint): uint
```

**What it does.** Integer division and remainder for unsigned numbers. Since both operands are non-negative by definition of the type, truncation toward zero and truncation downward coincide here, and the sign of the remainder is not an issue — the result is always non-negative. Dividing by `0` still raises `DivByZeroDefect`.

**Examples:**

```nim
assert 7'u8 div 2'u8 == 3'u8
assert 7'u8 mod 2'u8 == 1'u8
doAssertRaises(DivByZeroDefect):
  discard 7'u8 div 0'u8
```

## IV. Bitwise operations and shifts

### 1. `not`

```nim
proc `not`*(x: int): int
```

**What it does.** The bitwise complement (inversion of every bit) of `x`. Exists for all signed and unsigned integer types. The edge case shows up clearly on small types: `not 0'u8` gives `255`, because in an unsigned byte all bits become ones, whereas `not 0'i8` gives `-1`, because the same bit pattern `0b1111_1111` is read as minus one in a signed type's two's-complement representation.

**Examples:**

```nim
assert not 0'u8 == 255
assert not 0'i8 == -1
assert not 1000'u16 == 64535
assert not 1000'i16 == -1001
```

---

### 2. `and`

```nim
proc `and`*(x, y: int): int
```

**What it does.** Bitwise AND: a bit is set in the result only where it is set in both `x` and `y`. Often used as a mask for extracting specific bits or checking parity (see "Practical recipes").

**Examples:**

```nim
assert (0b0011 and 0b0101) == 0b0001
assert (0b0111 and 0b1100) == 0b0100
```

---

### 3. `or`

```nim
proc `or`*(x, y: int): int
```

**What it does.** Bitwise OR: a bit is set if it is set in at least one of the operands. Typically used to set flags in a bit mask.

**Examples:**

```nim
assert (0b0011 or 0b0101) == 0b0111
assert (0b0111 or 0b1100) == 0b1111
```

---

### 4. `xor`

```nim
proc `xor`*(x, y: int): int
```

**What it does.** Bitwise exclusive OR: a bit is set if it is set in exactly one of the operands, but not in both. Often used to toggle bits and to combine hash values.

**Examples:**

```nim
assert (0b0011 xor 0b0101) == 0b0110
assert (0b0111 xor 0b1100) == 0b1011
```

---

### 5. `shr`

```nim
proc `shr`*(x: int, y: SomeInteger): int
```

**What it does.** Shifts the bits of `x` right by `y` positions. The value of `y` is reduced modulo `sizeof(x) * 8`, so `15'i32 shr 35` is equivalent to `15'i32 shr 3`. For signed types (when the `nimOldShiftRight` compile-time flag is not set), the shift is arithmetic: bits vacated on the left are filled with a copy of the sign bit, so shifting a negative number right preserves its sign.

**Implementation notes.** By default `shr` for signed types is implemented via the same `"AshrI"` magic as the separate `ashr` function — meaning that in current Nim versions this is effectively the same machine code. The only difference is that `shr`'s behavior depends on the `nimOldShiftRight` compile-time flag (when set, `shr` reverts to the deprecated logical shift that does not preserve the sign), whereas `ashr` is guaranteed to be arithmetic regardless of compile-time flags. For unsigned types, `shr` is implemented via the `"ShrI"` magic — a logical shift that fills vacated bits with zeros, since `uint` has no sign bit that would need preserving.

**Parameters:**
- `x` — the value being shifted, of any signed or unsigned integer type.
- `y: SomeInteger` — the number of positions to shift, reduced modulo the bit width of `x`.

**Examples:**

```nim
assert 0b0001_0000'i8 shr 2 == 0b0000_0100'i8
assert 0b1000_0000'i8 shr 4 == 0b1111_1000'i8   # sign bit preserved
assert -1 shr 5 == -1
assert 16 shr 2 == 4
```

---

### 6. `shl`

```nim
proc `shl`*(x: int, y: SomeInteger): int
```

**What it does.** Shifts the bits of `x` left by `y` positions, filling bits vacated on the right with zeros. As with `shr`, the value of `y` is reduced modulo `sizeof(x) * 8`. Behaves identically for signed and unsigned types, since filling with zeros on the right has nothing to do with a number's sign.

**Examples:**

```nim
assert 1'i32 shl 4 == 0x0000_0010
assert 1'i64 shl 4 == 0x0000_0000_0000_0010
```

---

### 7. `ashr`

```nim
proc ashr*(x: int, y: SomeInteger): int
```

**What it does.** An explicit arithmetic right shift: bits vacated on the left are always filled with a copy of the sign (highest) bit, regardless of compile-time flags. Unlike `shr`, this is not an operator but an ordinary procedure, so it must be called through normal function-call syntax rather than infix notation.

**Implementation notes.** Uses the same `"AshrI"` magic as `shr` by default — `ashr` exists so the arithmetic shift semantics can be pinned down explicitly, independent of the `nimOldShiftRight` flag.

**Examples:**

```nim
assert ashr(0b0001_0000'i8, 2) == 0b0000_0100'i8
assert ashr(0b1000_0000'i8, 8) == 0b1000_0000'i8
assert ashr(0b1000_0000'i8, 1) == 0b1100_0000'i8
```

## V. Compound assignment operators for integers

### 1. `+=`

```nim
proc `+=`*[T: SomeInteger](x: var T, y: T)
```

**What it does.** Increments `x` by `y` in place — shorthand for `x = x + y`, with the same overflow conditions as binary `+`.

**Implementation notes.** Implemented via the same `"Inc"` magic as the `inc` procedure — the compiler substitutes the same machine addition instruction with overflow checking.

**Examples:**

```nim
var a = 5
a += 3
assert a == 8
```

---

### 2. `-=`

```nim
proc `-=`*[T: SomeInteger](x: var T, y: T)
```

**What it does.** Decrements `x` by `y` in place — shorthand for `x = x - y`.

**Examples:**

```nim
var a = 5
a -= 3
assert a == 2
```

---

### 3. `*=`

```nim
proc `*=`*[T: SomeInteger](x: var T, y: T) {.inline.} =
  x = x * y
```

**What it does.** Multiplies `x` by `y` in place.

**Implementation notes.** Unlike `+=`/`-=`, there is no separate compiler magic here — the procedure is marked only `{.inline.}` and literally consists of the body `x = x * y`, reusing the already overflow-checked `*` operator. Notably, the module has no `/=` procedure for integers at all: the `/` operator is not defined for integer types (it exists only for floating-point numbers), so divide-and-assign for integers must be written explicitly via `div`: `x = x div y`.

**Examples:**

```nim
var a = 5
a *= 3
assert a == 15
```

## VI. Floating-point arithmetic

Every procedure in this section exists in two overloads — for `float32` and for `float`/`float64` — and, unlike integer arithmetic, never raises `OverflowDefect`: going outside the range produces `Inf`/`-Inf`, and undefined operations such as `0.0 / 0.0` produce `NaN`.

### 1. Unary `+` and `-`

```nim
proc `+`*(x: float): float
proc `-`*(x: float): float
```

**What it does.** Unary plus does not change the value; unary minus negates a floating-point number, including correct handling of `+0.0`/`-0.0` and infinities.

**Examples:**

```nim
assert +3.5 == 3.5
assert -3.5 == 0.0 - 3.5
```

---

### 2. Binary `+`, `-`, `*`, `/`

```nim
proc `+`*(x, y: float): float
proc `-`*(x, y: float): float
proc `*`*(x, y: float): float
proc `/`*(x, y: float): float
```

**What it does.** Standard floating-point operations following the IEEE 754 standard. Dividing by `0.0` does not raise an exception (unlike integer `div`), but produces `Inf`, `-Inf`, or `NaN` depending on the sign and value of the dividend.

**Examples:**

```nim
assert 2.5 + 1.5 == 4.0
assert 5.0 / 2.0 == 2.5
assert 1.0 / 0.0 == Inf
```

---

### 3. `+=`, `-=`, `*=`, `/=`

```nim
proc `+=`*[T: float|float32|float64](x: var T, y: T) {.inline.} =
  x = x + y
proc `-=`*[T: float|float32|float64](x: var T, y: T) {.inline.} =
  x = x - y
proc `*=`*[T: float|float32|float64](x: var T, y: T) {.inline.} =
  x = x * y
proc `/=`*(x: var float64, y: float64) {.inline.} =
  x = x / y
```

**What it does.** Compound assignment operators for floating-point numbers — shorthand for `x = x + y` and similar. Unlike the integer `+=`/`-=`, all four operators here are implemented uniformly as `{.inline.}` procedures with the body `x = x op y`, without a separate compiler magic, since floating-point numbers need no overflow check.

**Examples:**

```nim
var price = 10.0
price *= 1.2
assert price == 12.0
price /= 4.0
assert price == 3.0
```

## VII. Wrap-around arithmetic

All five operators in this section treat their operands as unsigned numbers regardless of their actual signed type, perform a modular operation, and never raise an overflow exception — the result is always truncated to the type's bit width. This is useful for hash functions, pseudo-random number generators, and low-level code where overflow is an expected part of the algorithm rather than an error.

### 1. `+%`

```nim
proc `+%`*(x, y: int): int {.inline.} =
  cast[int](cast[uint](x) + cast[uint](y))
```

**What it does.** Adds `x` and `y` as if both were unsigned numbers, and returns the result reinterpreted as a signed number of the same size — with no risk of `OverflowDefect`.

**Implementation notes.** The implementation is literally "cast to uint, add modulo the bit width, cast back" — three `cast` operations, each of which does not change the number's bit representation, only reinterprets it.

**Examples:**

```nim
assert high(int8) +% 1'i8 == low(int8)  # wraps past the range's upper bound
```

---

### 2. `-%`

```nim
proc `-%`*(x, y: int): int {.inline.} =
  cast[int](cast[uint](x) - cast[uint](y))
```

**What it does.** Subtracts `y` from `x` following the same unsigned modular rules as `+%`.

**Examples:**

```nim
assert low(int8) -% 1'i8 == high(int8)  # wraps below the range's lower bound
```

---

### 3. `*%`

```nim
proc `*%`*(x, y: int): int {.inline.} =
  cast[int](cast[uint](x) * cast[uint](y))
```

**What it does.** Multiplies `x` and `y` following the same unsigned modular rules.

**Examples:**

```nim
assert 200'i8 *% 2'i8 == cast[int8](cast[uint8](200'i8) * cast[uint8](2'i8))
```

---

### 4. `/%`

```nim
proc `/%`*(x, y: int): int {.inline.} =
  cast[int](cast[uint](x) div cast[uint](y))
```

**What it does.** Integer division that treats both operands as unsigned numbers. Useful when a signed variable holds a bit pattern that should logically be interpreted as unsigned (for example, a value received from a network protocol).

**Examples:**

```nim
assert (-2) /% 2 == cast[int](high(uint) div 2'u + 1'u)
```

---

### 5. `%%`

```nim
proc `%%`*(x, y: int): int {.inline.} =
  cast[int](cast[uint](x) mod cast[uint](y))
```

**What it does.** The remainder of division, treating both operands as unsigned numbers — the unsigned counterpart of `/%`.

**Examples:**

```nim
assert 10 %% 3 == 10 mod 3   # for non-negative numbers this matches ordinary mod
```

## VIII. Practical recipes

### 1. Round-robin task scheduler

```nim
type
  Scheduler = object
    tasks: seq[string]
    current: int

proc next(s: var Scheduler): string =
  ## Returns the next task and advances the pointer in a circle.
  result = s.tasks[s.current]
  s.current = (s.current + 1) mod len(s.tasks)

var sched = Scheduler(tasks: @["A", "B", "C"], current: 0)
echo next(sched)  # prints "A"
echo next(sched)  # prints "B"
echo next(sched)  # prints "C"
echo next(sched)  # prints "A" — mod wrapped the pointer back to the start
```

---

### 2. Parity check via a bit mask

```nim
proc isEven(x: int): bool =
  ## Checks parity via the lowest bit instead of dividing mod 2.
  (x and 1) == 0

assert isEven(4) == true
assert isEven(7) == false
```

---

### 3. Saturating counter

```nim
proc incSaturating(x: var int8, step: int8) =
  ## Increments x by step, but caps at high(int8) instead of raising
  ## OverflowDefect — a typical need for game health counters.
  try:
    inc(x, step)
  except OverflowDefect:
    x = high(int8)

var health = 120'i8
incSaturating(health, 20'i8)
echo health  # prints 127 — saturation instead of an error
```

---

### 4. Combining hashes without overflow risk

```nim
proc combineHash(a, b: int): int =
  ## Combines two hashes via xor and a wrap-around multiplication,
  ## the way algorithms like the FNV hash typically do.
  (a xor b) *% 16777619

echo combineHash(123, 456)
```

---

### 5. A set of bit flags

```nim
const
  FlagRead = 1
  FlagWrite = 2
  FlagExec = 4

var perms = 0
perms = perms or FlagRead
perms = perms or FlagWrite
assert (perms and FlagExec) == 0        # flag not set
perms = perms or FlagExec
assert (perms and FlagExec) == FlagExec # flag set
perms = perms and not FlagWrite         # clear the write flag
assert (perms and FlagWrite) == 0
```

## IX. Quick reference table

| Task | Mutates the argument | What to use |
|---|---|---|
| Get the next/previous value | no | `succ`, `pred` |
| Increment/decrement a variable in place | yes | `inc`, `dec`, `+=`, `-=` |
| Add/subtract/multiply signed integers (with overflow checking) | no | `+`, `-`, `*` |
| Add/subtract/multiply without exceptions on overflow | no | `+%`, `-%`, `*%` |
| Integer division truncated toward zero | no | `div` |
| Remainder with the sign of the dividend | no | `mod` |
| Division/remainder treating numbers as unsigned | no | `/%`, `%%` |
| Test/set/clear one or more bits | no | `and`, `or`, `xor`, `not` |
| Shift bits left | no | `shl` |
| Shift bits right, preserving the sign | no | `shr` (by default), `ashr` |
| Shift bits right for unsigned numbers | no | `shr` on `uint` |
| Floating-point arithmetic | no | `+`, `-`, `*`, `/` for `float` |
| Compound assignment for floating-point numbers | yes | `+=`, `-=`, `*=`, `/=` |

## X. Summary: which procedure to choose

- Need the neighboring value of an ordinal type without touching the variable → use `succ`/`pred`.
- Need to change a variable in place by one step forward/backward → use `inc`/`dec`.
- Need integer addition/subtraction/multiplication with a guarantee that an overflow error won't go unnoticed → use plain `+`, `-`, `*`.
- Need arithmetic where overflow is expected behavior (hashes, generators, raw bit manipulation) → use `+%`, `-%`, `*%`, `/%`, `%%`.
- Need integer division rounded toward zero → use `div`; need the matching remainder → use `mod`.
- Need to treat a value as unsigned for division/remainder regardless of its declared type → use `/%`/`%%`.
- Need to work with individual bits (masks, flags, inversion) → use `and`, `or`, `xor`, `not`.
- Need a left shift → `shl`; need a right shift that preserves the sign regardless of compile flags → `ashr`; need the ordinary right-shift operator → `shr`.
- Need floating-point arithmetic → use `+`, `-`, `*`, `/` for `float`/`float32`, and for in-place assignment — `+=`, `-=`, `*=`, `/=`.
- Need compound assignment for integers, but specifically division — remember that `/=` does not exist for integers; write `x = x div y` explicitly.
