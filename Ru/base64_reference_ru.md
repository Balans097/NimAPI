# base64 — справочник модуля

> **Импорт:** `import std/base64`
> **Область применения:** кодирование произвольных бинарных данных (или строк) в ASCII-совместимый текстовый формат Base64 и обратное декодирование.

Модуль реализует классическую схему Base64: каждые три байта исходных данных (24 бита) преобразуются в четыре символа выходного алфавита (по 6 бит на символ). Модуль поддерживает как обычный алфавит (RFC 4648, символы `+` и `/`), так и URL-safe/filesystem-safe вариант (символы `-` и `_`), а также построчную MIME-кодировку для писем. Общая конвенция модуля: параметр `safe: bool` во всех процедурах кодирования отвечает за выбор алфавита, а декодирование во всех случаях автоматически определяет использованный алфавит по самим символам.

## Вспомогательные средства

### `initDecodeTable`

```nim
proc initDecodeTable*(): array[256, char]
```

**Что делает.** Строит таблицу обратного отображения: для каждого из 256 возможных байтовых значений вычисляет, какому 6-битному коду base64 оно соответствует. Результат используется как статическая таблица поиска (`decodeTable`) при декодировании — вместо того чтобы на каждый символ входной строки заново проверять, к какому диапазону алфавита (`A-Z`, `a-z`, `0-9`, `+`/`-`, `/`/`_`) он относится, декодер просто обращается по индексу `ord(символ)` в готовый массив.

**Разбор реализации.** Таблица заполняется значением `invalidChar` (255) по умолчанию — это служит маркером «недопустимый символ base64». Затем для каждого диапазона символов (`A-Z`, `a-z`, `0-9`) вычисляется код через смещение от кодовой точки ASCII, а символы `+`/`-` и `/`/`_` из обоих алфавитов (обычного и URL-safe) отображаются на одни и те же коды 62 и 63 соответственно — поэтому декодер одинаково успешно читает данные, закодированные любым из двух алфавитов, без явного указания, какой из них использовался. Процедура вызывается один раз на этапе компиляции (см. константу `decodeTable` ниже), так что во время выполнения программы построение таблицы не стоит ничего.

- Параметров нет.
- Возвращает `array[256, char]` — таблицу соответствия «код символа → 6-битное значение», где 255 означает «символ не входит в алфавит base64».

**Пример:**

```nim
const decodeTable = initDecodeTable()
echo ord(decodeTable[ord('A')])  # выводит 0 — 'A' это первый символ алфавита
echo ord(decodeTable[ord('/')])  # выводит 63 — последний символ обычного алфавита
echo ord(decodeTable[ord(' ')])  # выводит 255 — пробел не является частью алфавита
```

## Кодирование данных

### `encode` (из byte/char)

```nim
proc encode*[T: byte|char](s: openArray[T], safe = false): string
```

**Что делает.** Кодирует последовательность байтов или символов `s` в строку base64. Если `safe` равен `true`, используется URL-safe и filesystem-safe алфавит (символы `-` и `_` вместо `+` и `/`); в противном случае — стандартный алфавит RFC 4648. Пустой входной массив даёт пустую строку.

**Разбор реализации.** Данные обрабатываются группами по три байта: каждая группа «упаковывается» в 24-битное целое число (три операции `shl` последовательно сдвигают байты в старшие позиции 32-битного буфера), после чего это число «разбирается» обратно на четыре 6-битных фрагмента через `shr` и маску `and 63`, и каждый фрагмент превращается в символ через таблицу алфавита. Если длина `s` не кратна трём, последняя неполная группа (1 или 2 байта) дополняется символами `=` — это стандартный механизм выравнивания base64, позволяющий декодеру понять, сколько «настоящих» байт было в последней группе. Сложность — O(n) по длине входа, буфер результата выделяется заранее одним вызовом `setLen`, чтобы избежать постепенного расширения строки.

- `s: openArray[T]` — последовательность байтов (`byte`) или символов (`char`) для кодирования; не изменяется.
- `safe: bool` — если `true`, используется URL-safe алфавит (`-`, `_`); по умолчанию `false` (стандартный алфавит `+`, `/`).

**Примеры:**

```nim
# типичный случай — кодирование строки
echo encode("Hello World")  # выводит "SGVsbG8gV29ybGQ="

# кодирование массива целых чисел (байтов) и символов
echo encode([1'u8, 2, 3])          # выводит "AQID"
echo encode(['h', 'e', 'y'])       # выводит "aGV5"

# граничный случай — пустой вход
echo encode("")  # выводит ""

# разница между обычным и URL-safe алфавитом на одних и тех же данных
echo encode("c\xf7>", safe = false)  # выводит "Y/c+"
echo encode("c\xf7>", safe = true)   # выводит "Y_c-"

# практический сценарий: кодирование пароля для базовой HTTP-аутентификации
let credentials = "user:secret"
echo encode(credentials)  # выводит "dXNlcjpzZWNyZXQ="
```

### `encode` (устаревший вариант для целых чисел)

```nim
proc encode*[T: SomeInteger and not byte](s: openArray[T], safe = false): string
  {.deprecated: "use `byte` or `char` instead".}
```

**Что делает.** То же самое кодирование base64, что и основная процедура `encode`, но принимает последовательность произвольных целочисленных типов (`int`, `uint16` и т.п.), а не только `byte`/`char`. Помечена как устаревшая: компилятор Nim выдаёт предупреждение при её использовании.

**Разбор реализации.** Использует тот же внутренний шаблон `encodeImpl`, что и основной вариант — реализация полностью совпадает, отличается только ограничение типа параметра `T` в сигнатуре. Так как элементы более широкого целочисленного типа неявно приводятся к байту при упаковке, использование типов шире `byte` может приводить к потере данных или неожиданному результату — поэтому вариант и признан нежелательным.

- `s: openArray[T]` — последовательность целых чисел любого типа, кроме `byte`; не изменяется.
- `safe: bool` — то же значение, что и в основном варианте `encode`.

**Пример:**

```nim
# компилируется, но даёт предупреждение об устаревании
{.push warning[Deprecated]: off.}
echo encode([1, 2, 3])  # выводит "AQID" — тот же результат, что и через byte-вариант
{.pop.}
```

### `encodeMime`

```nim
proc encodeMime*(s: string, lineLen = 75.Positive, newLine = "\r\n",
                 safe = false): string
```

**Что делает.** Кодирует строку `s` в base64, но разбивает результат на строки фиксированной длины `lineLen`, разделённые последовательностью `newLine` — именно так требует формат MIME (RFC 2045) при передаче вложений в электронной почте. Если исходная строка пуста, возвращается пустая строка без выделения памяти под перенос строк.

**Разбор реализации.** Сначала выполняется обычное кодирование через `encode`, затем результат «нарезается» на куски по `lineLen` символов с вставкой `newLine` между ними. Итоговый буфер выделяется одним вызовом `newString` точного размера (длина закодированной строки плюс количество переносов строк, необходимых для этой длины), после чего копирование выполняется через внутренний шаблон `cpy`, двигающий индексы `i` (позиция в результате) и `j`/`k` (позиции в источниках) без промежуточных конкатенаций строк.

- `s: string` — исходная строка для кодирования; не изменяется.
- `lineLen: Positive` — максимальная длина одной строки закодированного вывода (без учёта символов переноса); по умолчанию 75, как предписывает MIME.
- `newLine: string` — последовательность символов, разделяющая строки вывода; по умолчанию `"\r\n"` (стандарт для e-mail).
- `safe: bool` — выбор алфавита кодирования, как в `encode`.

**Примеры:**

```nim
# типичный случай — короткая длина строки для наглядности
echo encodeMime("Hello World", 4, "\n")
# выводит:
# SGVs
# bG8g
# V29y
# bGQ=

# граничный случай — пустая строка
echo encodeMime("")  # выводит ""

# граничный случай — результат короче lineLen: перенос строки не добавляется
echo encodeMime("Hi", 75, "\n")  # выводит "SGk="

# практический сценарий — кодирование тела письма по умолчанию (75 символов, CRLF)
let body = "Полный текст письма, который нужно передать как MIME-вложение."
let mimeBody = encodeMime(body)
echo mimeBody
```

## Декодирование данных

### `decode`

```nim
proc decode*(s: string): string
```

**Что делает.** Декодирует строку `s`, закодированную в base64 (любым из двух алфавитов — обычным или URL-safe), обратно в исходные байты/строку. Ведущие пробельные символы пропускаются, а завершающие пробельные символы и символы выравнивания `=` отбрасываются автоматически. Пустая входная строка даёт пустой результат. Если во входной строке встречается символ, не входящий в алфавит base64, процедура поднимает `ValueError` с указанием символа и его позиции.

**Разбор реализации.** Декодирование идёт группами по четыре входных символа, каждый из которых через таблицу `decodeTable` превращается в 6-битный код; четыре 6-битных кода (24 бита) собираются обратно в три байта операциями `shl`/`shr`/`or`. Основной цикл — «горячий путь» — обрабатывает блоки по 4 символа без учёта пробелов внутри них ради скорости; отдельная проверка на пробельные символы (`\n`, `\r`, ' ') выполняется перед каждым блоком, что позволяет декодировать base64-строки, разбитые на несколько строк (например, результат `encodeMime`). Последняя неполная группа (2 или 3 значащих символа) обрабатывается отдельной веткой после основного цикла — это соответствует случаям, когда исходные данные не были кратны трём байтам и получили один или два символа `=` при кодировании.

- `s: string` — строка в формате base64 (обычный или URL-safe алфавит, возможны пробелы/переносы строк и завершающие `=`); не изменяется.
- Исключение: `ValueError`, если строка содержит символ вне алфавита base64.

**Примеры:**

```nim
# типичный случай
echo decode("SGVsbG8gV29ybGQ=")  # выводит "Hello World"

# начальные пробелы пропускаются
echo decode("  SGVsbG8gV29ybGQ=")  # выводит "Hello World"

# граничный случай — пустая строка
echo decode("")  # выводит ""

# декодирование результата URL-safe кодирования — таблица одинаково понимает оба алфавита
echo decode("Y_c-")  # выводит "c\xf7>"

# ошибочный случай — недопустимый символ поднимает исключение
doAssertRaises(ValueError):
  discard decode("не_base64!")

# практический сценарий — декодирование многострочного MIME-вложения
let mimeEncoded = "SGVs\nbG8g\nV29y\nbGQ="
echo decode(mimeEncoded)  # выводит "Hello World"
```

## Практические рецепты

### Заголовок HTTP Basic Auth
<a id="рецепт-basic-auth"></a>

Схема HTTP Basic Auth требует передавать логин и пароль, соединённые двоеточием и закодированные в base64, в заголовке `Authorization`.

```nim
proc buildBasicAuthHeader(username, password: string): string =
  let credentials = username & ":" & password
  result = "Basic " & encode(credentials)

echo buildBasicAuthHeader("admin", "s3cr3t")
# выводит "Basic YWRtaW46czNjcjN0"
```

### Безопасный для URL токен
<a id="рецепт-url-токен"></a>

Если закодированное значение нужно передать как часть URL (например, токен восстановления пароля), используется URL-safe алфавит — он не содержит символов `+`, `/`, требующих дополнительного экранирования в URL.

```nim
import std/random

proc generateUrlSafeToken(byteLen: int): string =
  var bytes = newSeq[byte](byteLen)
  for i in 0 ..< byteLen:
    bytes[i] = byte(rand(255))
  result = encode(bytes, safe = true)

let token = generateUrlSafeToken(16)
echo token  # например, "3F9k_Q-1mZaC7bXpNvR8sw"
```

### Кодирование бинарного файла для встраивания в JSON
<a id="рецепт-json-встраивание"></a>

Бинарные данные (например, содержимое небольшого изображения) нельзя напрямую поместить в JSON-строку — их предварительно кодируют в base64.

```nim
import std/[json, os]

proc fileToJsonField(path: string): JsonNode =
  let raw = readFile(path)
  let payload = encode(raw)
  result = %*{"filename": extractFilename(path), "data": payload}

let node = fileToJsonField("logo.png")
echo pretty(node)
```

### MIME-вложение для e-mail
<a id="рецепт-mime-вложение"></a>

Классическая задача: подготовить вложение письма согласно MIME — с построчным разбиением по 76 символам (де-факто стандарт многих почтовых клиентов) и CRLF-переносами.

```nim
proc buildMimeAttachment(content: string): string =
  result = encodeMime(content, lineLen = 76, newLine = "\r\n")

let attachment = buildMimeAttachment("Содержимое вложения, которое может быть сколь угодно длинным.")
echo attachment
```

### Безопасное декодирование внешних данных
<a id="рецепт-безопасное-декодирование"></a>

Данные, пришедшие извне (из сети, от пользователя), нельзя декодировать вслепую — входная строка может оказаться не валидным base64, и `decode` в этом случае поднимает исключение, которое нужно перехватить.

```nim
proc tryDecodeBase64(s: string): tuple[ok: bool, value: string] =
  try:
    result = (ok: true, value: decode(s))
  except ValueError:
    result = (ok: false, value: "")

let (ok1, value1) = tryDecodeBase64("SGVsbG8=")
echo ok1, " ", value1  # выводит "true Hello"

let (ok2, value2) = tryDecodeBase64("не валидные данные!!!")
echo ok2  # выводит "false"
```

## Сводка: какую процедуру выбрать

- Нужно закодировать байты, символы или строку в base64 → используйте `encode`.
- Нужно, чтобы результат годился для вставки прямо в URL или имя файла без экранирования → используйте `encode(..., safe = true)`.
- Нужно подготовить длинный base64-текст для e-mail-вложения (MIME) с переносами строк → используйте `encodeMime`.
- Нужно кодировать последовательность целых чисел, отличных от `byte` → используйте `encode`, предварительно приведя данные к `byte` или `char` (устаревший целочисленный вариант не рекомендуется).
- Нужно восстановить исходные данные из base64-строки (в любом из двух алфавитов) → используйте `decode`.
- Нужно самостоятельно построить таблицу соответствия символов base64 их 6-битным кодам (например, для собственной реализации) → используйте `initDecodeTable`.
