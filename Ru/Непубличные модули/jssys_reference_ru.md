# system/jssys — справочник модуля

> **Импорт:** этот файл не импортируется вручную пользовательским кодом — он часть системного модуля `system`, который компилятор Nim подключает автоматически при компиляции в бэкенд JavaScript (`nim js`). Большинство процедур помечены прагмой `compilerproc` и вызываются самим генератором кода, а не из обычных программ.
> **Область применения:** рантайм-поддержка бэкенда JS — исключения и трассировка стека, конвертация строк Nim/JavaScript, операции над множествами (`set`), целочисленная арифметика с проверкой переполнения, глубокое копирование значений (`nimCopy`), проверка индексов и типов объектов, вывод через `echo`.

Модуль состоит из низкоуровневых процедур, каждая из которых обслуживает одну конкретную операцию языка Nim в сгенерированном JS-коде (например, `a + b` для `int` компилируется в вызов `addInt`). Общая конвенция модуля: почти всё реализовано через блоки `{.emit: "...".}` — вставки "сырого" JavaScript, а сигнатура Nim описывает только типы входа/выхода. Вторая конвенция — парные "быстрая/полная" версии: например, у арифметики есть 32-битные (`addInt`) и 64-битные (`addInt64`) варианты с идентичной структурой.

## I. Типы и инфраструктура исключений

### 1. `SafePoint` / `PSafePoint`

```nim
type
  PSafePoint = ptr SafePoint
  SafePoint {.compilerproc, final.} = object
    prev: PSafePoint
    exc: ref Exception
```

**Что делает.** Узел односвязного списка "точек безопасности" — мест в стеке, куда можно вернуться при обработке исключения (аналог кадра `try`). Поле `prev` указывает на предыдущую точку, `exc` хранит перехваченное исключение для текущего блока.

**Разбор реализации.** Список растёт и схлопывается вместе с вложенными блоками `try`: вход в `try` добавляет новый `SafePoint` в начало списка, выход убирает его. Такой подход даёт O(1) на вход/выход блока и O(глубина вложенности) в худшем случае поиска обработчика.

**Список параметров.**
* `prev: PSafePoint` — указатель на внешний (родительский) `try`-блок; `nil`, если текущий блок — самый внешний.
* `exc: ref Exception` — исключение, активное в рамках этой точки безопасности.

---

### 2. `PJSError`

```nim
type
  PJSError = ref object
    columnNumber {.importc.}: int
    fileName {.importc.}: cstring
    lineNumber {.importc.}: int
    message {.importc.}: cstring
    stack {.importc.}: cstring
```

**Что делает.** Nim-проекция на встроенный объект ошибки JavaScript (`Error`/`TypeError`/и т.п.), позволяющая читать его поля (`message`, `fileName`, `stack`) из Nim-кода, даже если исключение было выброшено самим движком JS, а не Nim-программой.

**Разбор реализации.** Все поля помечены `{.importc.}` — то есть у объекта нет собственной раскладки в памяти, компилятор просто обращается к одноимённым полям существующего JS-объекта. Благодаря этому один и тот же указатель `lastJSError` можно интерпретировать и как `PJSError` (нативная ошибка), и как `ref Exception` (ошибка Nim) — выбор зависит от результата `isNimException()`.

**Список параметров.**
* `columnNumber: int` — номер столбца, где произошла ошибка (если движок предоставляет).
* `fileName: cstring` — имя файла с ошибкой.
* `lineNumber: int` — номер строки.
* `message: cstring` — текст сообщения об ошибке.
* `stack: cstring` — сырая трассировка стека движка JS.

## II. Работа с текущим исключением

### 1. `getCurrentException`

```nim
proc getCurrentException*(): ref Exception {.compilerRtl, gcsafe.}
```

**Что делает.** Возвращает текущее "активное" исключение — то, которое сейчас обрабатывается в блоке `except`. Если активного исключения нет либо оно пришло из недр JS-движка, а не из Nim (см. `isNimException`), возвращает `nil`.

**Разбор реализации.** Функция не хранит собственное состояние — она читает глобальную переменную `lastJSError` и просто перетолковывает её как `ref Exception`, если `isNimException()` подтвердил, что это Nim-объект, а не сырая ошибка JS.

**Список параметров.** Параметров нет.

**Примеры.**

```nim
try:
  raise newException(ValueError, "что-то пошло не так")
except ValueError:
  let e = getCurrentException()
  echo e.msg  # выводит "что-то пошло не так"
```

```nim
# Граничный случай: вне блока except возвращает nil
let e = getCurrentException()
doAssert e.isNil  # снаружи try/except активного исключения нет
```

---

### 2. `getCurrentExceptionMsg`

```nim
proc getCurrentExceptionMsg*(): string
```

**Что делает.** Возвращает текст сообщения текущего исключения в виде обычной Nim-строки — без необходимости самому проверять, Nim это исключение или нативная ошибка JavaScript.

**Разбор реализации.** Работает в две ветки: если `isNimException()` истинно — просто читает поле `.msg` Nim-исключения; иначе достаёт поле `message` у сырого JS-объекта через `{.emit.}` (потому что тип `PJSError` не гарантированно определён для произвольного значения `lastJSError`). Если сообщения нет вовсе — возвращает пустую строку, а не `nil`.

**Список параметров.** Параметров нет.

**Примеры.**

```nim
try:
  raise newException(IOError, "файл не найден")
except IOError:
  echo getCurrentExceptionMsg()  # выводит "файл не найден"
```

```nim
# Граничный случай: сообщение отсутствует
try:
  raise newException(ValueError, "")
except ValueError:
  let msg = getCurrentExceptionMsg()
  echo len(msg)  # выводит 0, а не ошибку доступа к nil
```

---

### 3. `setCurrentException`

```nim
proc setCurrentException*(exc: ref Exception)
```

**Что делает.** Принудительно устанавливает переданное исключение как "текущее" на уровне рантайма. Используется внутренними механизмами компилятора (например, при работе с closure-итераторами), а не в обычном пользовательском коде.

**Разбор реализации.** Просто перезаписывает глобальную переменную `lastJSError`, приводя `exc` к внутреннему представлению `PJSError`. Никакой проверки согласованности со стеком `try/except` не выполняется — вызывающий код обязан сам следить за корректностью состояния.

**Список параметров.**
* `exc: ref Exception` — исключение, которое станет "текущим" для последующих вызовов `getCurrentException`/`getCurrentExceptionMsg`.

**Примеры.**

```nim
let customExc = newException(ValueError, "искусственно установленное")
setCurrentException(customExc)
echo getCurrentExceptionMsg()  # выводит "искусственно установленное"
```

## III. Возбуждение исключений и трассировка стека

### 1. `getStackTrace` / `writeStackTrace`

```nim
proc getStackTrace*(): string
proc getStackTrace*(e: ref Exception): string
proc writeStackTrace()
```

**Что делает.** Первый вариант возвращает текстовую трассировку текущего стека вызовов (по данным `framePtr`). Второй вариант возвращает уже сохранённую трассировку конкретного исключения (поле `e.trace`, заполненное в момент `raise`). `writeStackTrace` — то же самое, что первый вариант, но сразу печатает результат через `echo`, обрезая завершающий перевод строки.

**Разбор реализации.** Трассировка строится обходом связного списка `CallFrame` (поле `prev`), причём буфер кадров ограничен 64 записями (`array[0..63, TempFrame]`) — это оптимизация, чтобы не аллоцировать динамическую структуру на каждый вызов; если кадров больше 64, старые (нижние) кадры сворачиваются в строку вида `(N calls omitted) ...`. Сложность — O(глубина стека), но не более 64 итераций на формирование буфера.

**Список параметров.**
* `e: ref Exception` — исключение, чья сохранённая трассировка (`e.trace`) возвращается без повторного обхода стека.

**Примеры.**

```nim
proc levelB() =
  echo getStackTrace()  # выводит многострочную трассировку с именами levelA, levelB

proc levelA() =
  levelB()

levelA()
```

```nim
# Граничный случай: стек пуст (framePtr == nil)
# rawWriteStackTrace в этом случае возвращает "No stack traceback available"
```

### 2. `raiseException`

```nim
proc raiseException(e: ref Exception, ename: cstring) {.compilerproc, asmNoStackFrame.}
```

**Что делает.** Основная точка входа для оператора `raise` в сгенерированном JS-коде: присваивает исключению имя типа, при отсутствии активного обработчика (`excHandler == 0`) сразу считает его необработанным и завершает программу, иначе сохраняет трассировку стека и выбрасывает исключение как нативный JS `throw`.

**Разбор реализации.** Переменная `excHandler` — счётчик вложенности `try`-блоков; `excHandler == 0` означает, что исключение выброшено вне какого-либо `try`, и его некому поймать — поэтому вызывается `unhandledException`, которая печатает сообщение и тоже делает `throw`, но уже с текстом ошибки для консоли/среды выполнения.

**Список параметров.**
* `e: ref Exception` — объект исключения, который нужно выбросить.
* `ename: cstring` — имя типа исключения (записывается в `e.name` для последующей диагностики).

**Примеры.**

```nim
# Типичный случай — компилятор сам вставляет вызов raiseException при raise:
try:
  raise newException(KeyError, "ключ не найден")
except KeyError as e:
  echo e.name  # выводит "KeyError"
```

---

### 3. `raiseDefect` / `reraiseException`

```nim
proc raiseDefect()
proc reraiseException()
```

**Что делает.** `raiseDefect` проверяет, является ли текущее исключение потомком `Defect` (то есть не предназначенным для перехвата обычным `except`), и если да — принудительно его выбрасывает повторно, минуя штатную обработку. `reraiseException` реализует оператор `raise` без аргументов внутри блока `except` — повторно выбрасывает уже пойманное исключение; если перевыбрасывать нечего, поднимает `ReraiseDefect`.

**Разбор реализации.** Обе процедуры полагаются на `isNimException()`, чтобы отличить Nim-исключение от сырой ошибки движка JS — в противном случае обращение к полям вроде `.name` привело бы к ошибке доступа к несуществующему свойству.

**Список параметров.** Параметров нет.

**Примеры.**

```nim
try:
  try:
    raise newException(ValueError, "внутренняя ошибка")
  except ValueError:
    raise  # это и есть reraiseException — перевыбрасывает то же исключение
except ValueError as e:
  echo e.msg  # выводит "внутренняя ошибка"
```

```nim
# Ошибочный случай: перевыброс без активного исключения
doAssertRaises(ReraiseDefect):
  reraiseException()
```

### 4. `raiseOverflow` / `raiseDivByZero` / `raiseRangeError` / `raiseIndexError` / `raiseFieldError2`

```nim
proc raiseOverflow() {.noreturn.}
proc raiseDivByZero() {.noreturn.}
proc raiseRangeError() {.noreturn.}
proc raiseIndexError(i, a, b: int) {.noreturn.}
proc raiseFieldError2(f: string, discVal: string) {.noreturn.}
```

**Что делает.** Пять "именованных точек" для стандартных runtime-ошибок Nim: переполнение целого (`OverflowDefect`), деление на ноль (`DivByZeroDefect`), выход значения за допустимый диапазон (`RangeDefect`), выход индекса за границы контейнера (`IndexDefect`) и обращение к недоступному полю варианта (`FieldDefect`). Каждая из них никогда не возвращает управление вызывающему коду (`noreturn`) — она либо выбрасывает исключение, либо (если оно не поймано) завершает программу.

**Разбор реализации.** Это тонкие обёртки над `raise newException(...)`; вся содержательная логика (форматирование сообщения) вынесена в `formatErrorIndexBound`/`formatFieldDefect` из `system/indexerrors`. Компилятор вставляет вызовы этих процедур автоматически перед арифметикой, индексацией и доступом к полям — писать их вручную в обычном коде не требуется.

**Список параметров.**
* `i, a, b: int` (для `raiseIndexError`) — фактический индекс `i` и допустимые границы `a..b`.
* `f, discVal: string` (для `raiseFieldError2`) — имя запрашиваемого поля и текущее значение дискриминанта варианта.

**Примеры.**

```nim
# Типичный случай — вставляется компилятором автоматически:
var a = [1, 2, 3]
doAssertRaises(IndexDefect):
  discard a[10]  # компилятор вставит вызов raiseIndexError(10, 0, 2)
```

## IV. Конвертация строк между Nim и JavaScript

### 1. `nimBoolToStr` / `nimCharToStr`

```nim
proc nimBoolToStr(x: bool): string {.compilerproc.}
proc nimCharToStr(x: char): string {.compilerproc.}
```

**Что делает.** Приводят простейшие скалярные значения к строковому представлению Nim: `bool` — к `"true"`/`"false"`, `char` — к строке из одного символа. Используются компилятором при интерполяции значений в `$x` и `echo`.

**Разбор реализации.** Прямолинейная реализация без обращения к JS: для `bool` — условная ветка, для `char` — выделение строки длиной 1 через `newString(1)` и запись символа по индексу.

**Список параметров.**
* `x: bool` / `x: char` — исходное значение для преобразования.

**Примеры.**

```nim
echo nimBoolToStr(true)   # выводит "true"
echo nimCharToStr('Z')    # выводит "Z"
```

---

### 2. `makeNimstrLit`

```nim
proc makeNimstrLit(c: cstring): string {.asmNoStackFrame, compilerproc.}
```

**Что делает.** Превращает строковый литерал JavaScript (`cstring`) в представление строки Nim для генератора кода JS-бэкенда — массив кодов символов. Используется компилятором при вставке строковых констант в сгенерированный код, напрямую в пользовательских программах не вызывается.

**Разбор реализации.** Строит новый JS-массив и копирует в него `charCodeAt` каждого символа исходной строки — то есть работает на уровне 16-битных code unit'ов UTF-16, без учёта суррогатных пар. Для полной поддержки Юникода (в частности, символов вне BMP) есть более сложная процедура `cstrToNimstr`.

**Список параметров.**
* `c: cstring` — исходная строка JavaScript, чьи коды символов нужно перенести в представление Nim.

---

### 3. `cstrToNimstr`

```nim
proc cstrToNimstr(c: cstring): string {.asmNoStackFrame, compilerproc.}
```

**Что делает.** Конвертирует JS-строку в Nim-строку с полноценным перекодированием в UTF-8, включая символы вне базовой многоязыковой плоскости (BMP), закодированные в UTF-16 суррогатными парами.

**Разбор реализации.** Реализует ручную кодировку UTF-8 "на лету": для code point'ов до 128 — один байт как есть; до 2048 — два байта со стандартными битовыми масками (`>> 6 | 192` и `& 63 | 128`); для суррогатных пар (диапазон `0xD800..0xDFFF`) — код собирается из двух 16-битных единиц по формуле `65536 + ((high & 1023) << 10 | (low & 1023))` и раскладывается на четыре байта UTF-8. Это классический алгоритм кодирования UTF-8 по битовым маскам, повторённый вручную, поскольку на момент написания модуля не на все окружения JS можно было положиться в вопросах кодировок.

**Список параметров.**
* `c: cstring` — исходная строка JavaScript (UTF-16), подлежащая перекодированию в UTF-8-представление Nim.

**Примеры.**

```nim
# Практический сценарий: получение строки из DOM/API браузера и обратная
# конвертация в Nim-строку выполняется компилятором автоматически при
# присваивании cstring в string, вручную вызывать не требуется.
```

### 4. `toJSStr`

```nim
proc toJSStr(s: string): cstring {.compilerproc.}
```

**Что делает.** Обратное преобразование: превращает Nim-строку (массив байтов UTF-8) в строку JavaScript, корректно раскодируя многобайтовые последовательности UTF-8 обратно в code point'ы.

**Разбор реализации.** Для ASCII-байтов (`< 128`) используется прямое `String.fromCharCode`. Для остальных байтов накапливается последовательность `%XX`-эскейпов (в стиле `encodeURIComponent`) до тех пор, пока не встретится байт-начало следующего символа, а затем вся накопленная последовательность передаётся в `decodeURIComponent`, который и восстанавливает исходный юникодный символ. Если `decodeURIComponent` выбрасывает исключение (некорректная последовательность байт), функция откатывается к простой конкатенации эскейпов без декодирования — это защита от аварийного завершения на повреждённых данных.

**Список параметров.**
* `s: string` — Nim-строка (байтовая последовательность UTF-8), которую нужно представить как строку JavaScript.

**Примеры.**

```nim
let s = "Привет"
echo toJSStr(s)  # возвращает cstring "Привет", пригодный для передачи в JS-API
```

```nim
# Граничный случай: пустая строка
doAssert len($toJSStr("")) == 0
```

## V. Операции над множествами (`set`)

### 1. `setConstr`

```nim
proc setConstr() {.varargs, asmNoStackFrame, compilerproc.}
```

**Что делает.** Строит представление литерала `set` в виде JS-объекта, где ключи — элементы множества. Вызывается компилятором при компиляции конструкций вида `{1, 2, 5..8}`.

**Разбор реализации.** Каждый аргумент — либо одиночный элемент, либо пара `[first, last]`, задающая диапазон (компилятор передаёт диапазоны как вложенный массив из двух чисел). Для диапазона все значения от `first` до `last` включительно записываются в результат как ключи со значением `true`; представление множества — это, по сути, hash-set на JS-объекте, а не битовый вектор.

**Список параметров.** Принимает произвольное число аргументов (`varargs`) — одиночные значения элементов множества либо двухэлементные массивы `[first, last]` для диапазонов.

**Примеры.**

```nim
# Компилятор превращает литерал множества в вызов setConstr:
let s = {1, 2, 5..8}
echo SetCard(cast[int](s))  # выводит 6 (1, 2, 5, 6, 7, 8)
```

---

### 2. `SetCard`

```nim
proc SetCard(a: int): int {.compilerproc, asmNoStackFrame.}
```

**Что делает.** Возвращает мощность множества — количество элементов в нём. Тип параметра `int` — фиктивный (реально передаётся объект-множество), это особенность представления множеств в этом бэкенде.

**Разбор реализации.** Простой обход `for...in` по ключам JS-объекта с подсчётом — O(размер множества), поскольку множество здесь не битовый вектор фиксированного размера, а разреженная хеш-структура.

**Список параметров.**
* `a` — множество, чью мощность нужно посчитать (фиктивный тип `int` в сигнатуре).

**Примеры.**

```nim
let s = {2, 4, 6}
echo SetCard(cast[int](s))  # выводит 3
```

```nim
# Граничный случай: пустое множество
let empty: set[0..7] = {}
echo SetCard(cast[int](empty))  # выводит 0
```

---

### 3. `SetEq` / `SetLe` / `SetLt`

```nim
proc SetEq(a, b: int): bool {.compilerproc, asmNoStackFrame.}
proc SetLe(a, b: int): bool {.compilerproc, asmNoStackFrame.}
proc SetLt(a, b: int): bool {.compilerproc.}
```

**Что делает.** Реализуют операторы сравнения множеств: `SetEq` — равенство (`a == b`), `SetLe` — нестрогое включение (`a` является подмножеством `b`, оператор `<=`), `SetLt` — строгое включение (`a <= b` и `a != b`, оператор `<`).

**Разбор реализации.** `SetEq` проверяет включение в обе стороны — если каждый элемент `a` есть в `b` и наоборот, множества равны. `SetLe` делает только одну из этих двух проверок — только "все элементы `a` есть в `b`". `SetLt` не дублирует логику, а выражается через уже определённые `SetLe` и `SetEq` — идиоматичное переиспользование более простых операций для построения более сложной.

**Список параметров.**
* `a, b` — сравниваемые множества (фиктивный тип `int` в сигнатуре).

**Примеры.**

```nim
let x = {1, 2, 3}
let y = {1, 2, 3, 4}
echo SetLe(cast[int](x), cast[int](y))  # выводит true — x является подмножеством y
echo SetLt(cast[int](x), cast[int](y))  # выводит true — включение строгое
echo SetEq(cast[int](x), cast[int](y))  # выводит false — множества не равны
```

---

### 4. `SetMul` / `SetPlus` / `SetMinus` / `SetXor`

```nim
proc SetMul(a, b: int): int {.compilerproc, asmNoStackFrame.}
proc SetPlus(a, b: int): int {.compilerproc, asmNoStackFrame.}
proc SetMinus(a, b: int): int {.compilerproc, asmNoStackFrame.}
proc SetXor(a, b: int): int {.compilerproc, asmNoStackFrame.}
```

**Что делает.** Четыре теоретико-множественные операции, реализующие операторы `*` (пересечение), `+` (объединение), `-` (разность) и `xor` (симметрическая разность) для типа `set`.

**Разбор реализации.** Все четыре — новая, неизменяющая операция: создаётся пустой объект `result`, а дальше он заполняется по своим правилам — `SetMul` берёт элементы `a`, которые есть и в `b`; `SetPlus` объединяет все ключи обоих; `SetMinus` берёт элементы `a`, которых нет в `b`; `SetXor` берёт элементы, присутствующие ровно в одном из двух множеств. Все операции работают за O(размер `a` + размер `b`).

**Список параметров.**
* `a, b` — операнды теоретико-множественной операции (фиктивный тип `int`).

**Примеры.**

```nim
let x = {1, 2, 3}
let y = {2, 3, 4}
echo SetCard(cast[int](SetMul(cast[int](x), cast[int](y))))    # выводит 2 ({2, 3})
echo SetCard(cast[int](SetPlus(cast[int](x), cast[int](y))))   # выводит 4 ({1,2,3,4})
echo SetCard(cast[int](SetMinus(cast[int](x), cast[int](y))))  # выводит 1 ({1})
echo SetCard(cast[int](SetXor(cast[int](x), cast[int](y))))    # выводит 2 ({1, 4})
```

## VI. Сравнение строк

### 1. `cmpStrings` / `cmp`

```nim
proc cmpStrings(a, b: string): int {.asmNoStackFrame, compilerproc.}
proc cmp(x, y: string): int
```

**Что делает.** Возвращают отрицательное число, ноль или положительное число в зависимости от того, меньше, равна или больше строка `a` строки `b` в лексикографическом порядке — стандартный контракт компаратора трёхзначного сравнения.

**Разбор реализации.** `cmpStrings` — прямое посимвольное сравнение с ранним выходом при первом несовпадении; если общая часть совпала, короткая строка считается "меньше" (сравниваются длины). `cmp` — обёртка на уровне языка: во время компиляции (`nimvm`, то есть в compile-time VM) использует встроенные операторы `==`/`<` для строк, а в скомпилированном JS-коде делегирует работу в `cmpStrings` — это нужно, потому что во время компиляции `cmpStrings` (с её `{.emit.}`-телом) недоступна.

**Список параметров.**
* `a, b` / `x, y: string` — сравниваемые строки.

**Примеры.**

```nim
echo cmp("apple", "banana")  # выводит отрицательное число ("apple" < "banana")
echo cmp("banana", "apple")  # выводит положительное число
echo cmp("nim", "nim")       # выводит 0
```

---

### 2. `eqStrings`

```nim
proc eqStrings(a, b: string): bool {.asmNoStackFrame, compilerproc.}
```

**Что делает.** Проверяет строки на равенство. Реализует оператор `==` для `string` в сгенерированном коде.

**Разбор реализации.** Отдельно обрабатывает случай, когда одна из строк — `nil` (в представлении JS-бэкенда это `null`, а не пустой массив кодов), а другая — пустая строка: они по соглашению Nim считаются равными. Это тонкость реализации, отличающая поведение от "наивного" сравнения `a === b`, которое дало бы `false` для пары `null` и `[]`.

**Список параметров.**
* `a, b: string` — сравниваемые строки.

**Примеры.**

```nim
echo eqStrings("hello", "hello")  # выводит true
```

```nim
# Граничный случай: nil-строка и пустая строка считаются равными
var a: string
let b = ""
echo eqStrings(a, b)  # выводит true
```

## VII. Арифметика с проверкой переполнения

### 1. `checkOverflowInt` и `addInt` / `subInt` / `mulInt` / `divInt` / `modInt`

```nim
proc checkOverflowInt(a: int) {.asmNoStackFrame, compilerproc.}
proc addInt(a, b: int): int {.asmNoStackFrame, compilerproc.}
proc subInt(a, b: int): int {.asmNoStackFrame, compilerproc.}
proc mulInt(a, b: int): int {.asmNoStackFrame, compilerproc.}
proc divInt(a, b: int): int {.asmNoStackFrame, compilerproc.}
proc modInt(a, b: int): int {.asmNoStackFrame, compilerproc.}
```

**Что делает.** Реализуют арифметические операторы `+`, `-`, `*`, `div`, `mod` для 32-битного `int` так, как того требует семантика Nim: с проверкой переполнения (выброс `OverflowDefect`) и с проверкой деления на ноль (выброс `DivByZeroDefect`) — в отличие от "сырых" операторов JavaScript, которые молча работают с плавающей точкой double.

**Разбор реализации.** JavaScript не имеет нативных 32-битных целых — числа представлены как `double`, поэтому после каждой операции результат нужно явно проверить границами `[-2147483648, 2147483647]` через `checkOverflowInt`. Для `div`/`mod` дополнительно проверяется классический граничный случай переполнения при целочисленном делении — деление `INT_MIN` на `-1`, которое не помещается в диапазон `int32`. Округление в сторону нуля обеспечивается через `Math.trunc`, а не через `Math.floor`, чтобы соответствовать семантике Nim (в отличие от Python-подобного деления с округлением вниз).

**Список параметров.**
* `a: int` (в `checkOverflowInt`) — значение, чьи границы проверяются.
* `a, b: int` (в остальных) — операнды арифметической операции.

**Примеры.**

```nim
echo addInt(2, 3)   # выводит 5
echo divInt(7, 2)    # выводит 3 (округление к нулю через Math.trunc)
echo modInt(-7, 2)   # выводит -1 (знак результата — как у делимого)
```

```nim
# Ошибочный случай: переполнение верхней границы int32
doAssertRaises(OverflowDefect):
  discard addInt(2147483647, 1)
```

```nim
# Ошибочный случай: деление на ноль
doAssertRaises(DivByZeroDefect):
  discard divInt(10, 0)
```

### 2. 64-битные варианты

```nim
proc checkOverflowInt64(a: int64) {.asmNoStackFrame, compilerproc.}
proc addInt64(a, b: int64): int64 {.asmNoStackFrame, compilerproc.}
proc subInt64(a, b: int64): int64 {.asmNoStackFrame, compilerproc.}
proc mulInt64(a, b: int64): int64 {.asmNoStackFrame, compilerproc.}
proc divInt64(a, b: int64): int64 {.asmNoStackFrame, compilerproc.}
proc modInt64(a, b: int64): int64 {.asmNoStackFrame, compilerproc.}
```

**Что делает.** Полный аналог группы `addInt`/`subInt`/`mulInt`/`divInt`/`modInt`, но для 64-битного `int64` — с той же семантикой проверки переполнения и деления на ноль.

**Разбор реализации.** Отличие от 32-битных версий только в используемом JS-типе: вместо обычных чисел `double` используется нативный `BigInt` (литералы с суффиксом `n`, например `9223372036854775807n`), поскольку `double` не может точно представить весь диапазон `int64`. Границы переполнения и особый случай `INT64_MIN / -1` проверяются по тем же принципам, что и для 32-битной версии, только со значениями диапазона `int64`.

**Список параметров.** Аналогичен группе `int`-вариантов, но с типом `int64`.

**Примеры.**

```nim
echo addInt64(1000000000000'i64, 1'i64)  # выводит 1000000000001
```

```nim
# Ошибочный случай: переполнение int64
doAssertRaises(OverflowDefect):
  discard addInt64(9223372036854775807'i64, 1'i64)
```

### 3. `negInt` / `absInt` / `nimMin` / `nimMax`

```nim
proc negInt(a: int): int {.compilerproc.}
proc negInt64(a: int64): int64 {.compilerproc.}
proc absInt(a: int): int {.compilerproc.}
proc absInt64(a: int64): int64 {.compilerproc.}
proc nimMin(a, b: int): int {.compilerproc.}
proc nimMax(a, b: int): int {.compilerproc.}
```

**Что делает.** `negInt`/`negInt64` — унарный минус; `absInt`/`absInt64` — модуль числа; `nimMin`/`nimMax` — минимум и максимум пары значений.

**Разбор реализации.** В отличие от предыдущей группы, здесь нет проверки переполнения (поэтому нет и версии с `{.emit.}` — реализация выражена обычным Nim-кодом): унарный минус и модуль в 32-/64-битных границах не могут выйти за пределы диапазона иначе, чем через отдельно проверяемое сложение/умножение, а `min`/`max` вообще не может переполниться, так как просто возвращает один из входных аргументов без вычислений.

**Список параметров.**
* `a: int` / `a: int64` — значение, для которого вычисляется отрицание или модуль.
* `a, b: int` — пара значений для сравнения.

**Примеры.**

```nim
echo negInt(5)       # выводит -5
echo absInt(-12)     # выводит 12
echo nimMin(3, 7)    # выводит 3
echo nimMax(3, 7)    # выводит 7
```

## VIII. Копирование значений (`nimCopy`)

### 1. `isFatPointer`

```nim
proc isFatPointer(ti: PNimType): bool
```

**Что делает.** Определяет, является ли указатель данного типа "толстым" — то есть представленным в JS не одним значением, а парой `[объект, смещение]` (это нужно для указателей на поля составных типов, а не только на начало объекта).

**Разбор реализации.** Проверяет вид базового типа (`ti.base.kind`): если базовый тип — объект, массив, кортеж, открытый массив, множество, `var` или другой указатель, считается, что достаточно обычной ссылки; для остальных (в первую очередь примитивов) требуется толстый указатель, чтобы можно было адресовать конкретное поле/элемент.

**Список параметров.**
* `ti: PNimType` — информация о типе указателя времени выполнения (RTTI).

---

### 2. `nimCopy` / `nimCopyAux`

```nim
proc nimCopy(dest, src: JSRef, ti: PNimType): JSRef
proc nimCopyAux(dest, src: JSRef, n: ptr TNimNode)
```

**Что делает.** `nimCopy` реализует глубокое (значимое) копирование Nim-значений с учётом их типа — это то, что стоит за присваиванием `a = b` для типов с семантикой значения (объекты, кортежи, массивы, последовательности, строки, множества), в отличие от простого копирования ссылки, как это делает "сырой" JavaScript при `a = b`. `nimCopyAux` — вспомогательный обход полей составного типа (объекта/кортежа) по дереву `TNimNode`.

**Разбор реализации.** Реализация — большой `case` по виду типа (`ti.kind`):
- указатели/`ref`/`var` копируются как ссылка либо, если это "толстый" указатель, как новая пара `[obj, offset]`;
- множества (`tySet`) копируются переносом всех ключей в существующий или новый JS-объект, с очисткой старого содержимого `dest`;
- объекты и кортежи копируются полем за полем через `nimCopyAux`, которая рекурсивно проходит структуру типа (`nkSlot` — один слот, `nkList` — список слотов, `nkCase` — вариантная часть с обходом активной ветки);
- массивы, открытые массивы и последовательности копируются поэлементно, с переиспользованием существующего буфера `dest`, если его длина уже совпадает — это избегает лишних аллокаций при повторном копировании в один и тот же приёмник;
- строки копируются через `slice(0)` — быстрый неглубокий, но для строк (неизменяемых наборов кодов) этого достаточно.

Общий инвариант всей процедуры: `dest` по возможности переиспользуется (а не создаётся заново), что важно для производительности при копировании в цикле.

**Список параметров.**
* `dest: JSRef` — приёмник, в который копируются данные (может быть `nil`, тогда будет создан новый объект).
* `src: JSRef` — источник копирования.
* `ti: PNimType` — RTTI-описание типа копируемого значения, определяющее, какая ветка `case` применяется.
* `n: ptr TNimNode` (для `nimCopyAux`) — узел дерева полей типа, обрабатываемый на этом шаге рекурсии.

**Примеры.**

```nim
# Типичный случай — компилятор вставляет nimCopy при присваивании объектов:
type Point = object
  x, y: int

var a = Point(x: 1, y: 2)
var b = a  # под капотом — nimCopy(nil, a, ...)
b.x = 99
echo a.x  # выводит 1 — a не изменился, копия была глубокой
```

### 3. `arrayConstr`

```nim
proc arrayConstr(len: int, value: JSRef, typ: PNimType): JSRef {.asmNoStackFrame, compilerproc.}
```

**Что делает.** Строит новый массив длины `len`, где каждый элемент — независимая копия `value` (а не `len` ссылок на один и тот же объект). Используется компилятором для конструкций вида `array[5, Point]`, где начальное значение нужно размножить по всем ячейкам.

**Разбор реализации.** Наивная реализация "заполнить одним и тем же значением" была бы неверна для составных типов — все ячейки указывали бы на один объект, и изменение одной "просвечивало" бы в остальные. Поэтому на каждой итерации вызывается `nimCopy(null, value, typ)`, создающий независимую копию.

**Список параметров.**
* `len: int` — длина создаваемого массива.
* `value: JSRef` — образец значения, копируемый в каждую ячейку.
* `typ: PNimType` — RTTI-тип значения, передаваемый в `nimCopy` для выбора стратегии копирования.

**Примеры.**

```nim
type Point = object
  x, y: int

var arr = arrayConstr(3, Point(x: 1, y: 1), typeof(Point))
# каждый элемент arr — независимая копия Point(x: 1, y: 1)
```

## IX. Проверка индексов, диапазонов и типов объектов

### 1. `chckIndx` / `chckRange`

```nim
proc chckIndx(i, a, b: int): int {.compilerproc.}
proc chckRange(i, a, b: int): int {.compilerproc.}
```

**Что делает.** Обе процедуры проверяют, что `i` лежит в границах `a..b`, и возвращают `i` без изменений, если проверка пройдена. Отличаются только тем, какое исключение поднимают при нарушении: `chckIndx` — `IndexDefect` (для индексации контейнеров), `chckRange` — `RangeDefect` (для приведения к диапазонному типу вроде `range[0..10]`).

**Разбор реализации.** Компилятор вставляет вызов одной из этих функций перед каждой операцией, для которой включена соответствующая проверка (`--boundChecks`/`--rangeChecks`), оборачивая исходное выражение индекса. Возврат самого `i` в случае успеха позволяет использовать вызов "прозрачно", подставляя его прямо на место исходного индекса в сгенерированном коде.

**Список параметров.**
* `i: int` — проверяемое значение.
* `a, b: int` — допустимые нижняя и верхняя границы (включительно).

**Примеры.**

```nim
var arr = [10, 20, 30]
echo arr[chckIndx(1, 0, 2)]  # выводит 20 — так компилятор проверяет arr[1]
```

```nim
# Ошибочный случай: индекс вне границ
doAssertRaises(IndexDefect):
  discard chckIndx(5, 0, 2)
```

### 2. `chckObj` / `isObj`

```nim
proc chckObj(obj, subclass: PNimType)
proc isObj(obj, subclass: PNimType): bool
```

**Что делает.** Проверяют отношение "является подтипом" между RTTI-описаниями типов объектов. `isObj` возвращает булев результат проверки; `chckObj` делает ту же проверку, но вместо булева результата поднимает `ObjectConversionDefect`, если проверка не пройдена — это то, что стоит за оператором приведения типов объектов `Foo(x)`.

**Разбор реализации.** Обе процедуры поднимаются по цепочке `base` от `obj` вверх по иерархии наследования, сравнивая с `subclass` на каждом шаге; есть быстрый путь для точного совпадения без обхода иерархии. Сложность — O(глубина иерархии наследования).

**Список параметров.**
* `obj: PNimType` — RTTI фактического (динамического) типа значения.
* `subclass: PNimType` — RTTI типа, к которому выполняется проверка/приведение.

**Примеры.**

```nim
type
  Animal = ref object of RootObj
  Dog = ref object of Animal

let a: Animal = Dog()
echo isObj(a.type, Dog.type)  # выводит true — динамический тип a это Dog (иллюстративно)
```

```nim
# Ошибочный случай: приведение к несовместимому типу поднимает ObjectConversionDefect
```

### 3. `chckNilDisp`

```nim
proc chckNilDisp(p: JSRef) {.compilerproc.}
```

**Что делает.** Проверяет, что диспетчер виртуального вызова (`p`, указатель на таблицу методов) не `nil` перед динамической диспетчеризацией метода — то есть защищает от вызова метода на объекте, у которого некорректно инициализирован диспетчер.

**Разбор реализации.** Простая проверка на `nil` с поднятием `NilAccessDefect`, если диспетчер отсутствует — предотвращает менее понятную ошибку доступа к `undefined`-полю глубже внутри JS-движка.

**Список параметров.**
* `p: JSRef` — указатель-диспетчер, чья валидность проверяется.

## X. Вывод (`echo`) и добавление в строку

### 1. `rawEcho`

```nim
proc rawEcho() {.compilerproc.}
```

**Что делает.** Низкоуровневая реализация оператора `echo` — печатает переданные аргументы (уже приведённые к строкам через `toJSStr`), разделяя их и завершая строку переводом строки в зависимости от окружения выполнения.

**Разбор реализации.** У процедуры три альтернативные реализации, выбираемые условной компиляцией под конкретную среду выполнения:
- под флагом `kwin` — вывод через глобальную функцию `print` (среда KWin/Plasma);
- по умолчанию (браузер/Node.js) — через `console.log`;
- под флагом `nimOldEcho` — старый способ вывода прямо в DOM, добавлением текстовых узлов и `<br>` в `<body>`, с явной проверкой, что `<body>` уже существует (иначе поднимается исключение — вывод до готовности DOM невозможен).

Как исключение из общего правила префиксной формы вызовов, сам `echo` используется без скобок и точки — таково соглашение оформления кода в этом справочнике (см. раздел "Требования к оформлению кода" в шаблоне).

**Список параметров.** Принимает произвольное число аргументов (`varargs`) — значения для печати, уже сериализованные в `cstring`.

**Примеры.**

```nim
echo "Значение: ", 42  # выводит "Значение: 42" в консоль
```

---

### 2. `addChar` / `nimAddStrStr`

```nim
proc addChar(x: string, c: char) {.compilerproc, asmNoStackFrame.}
proc nimAddStrStr(x, y: string) {.compilerproc, asmNoStackFrame.}
```

**Что делает.** `addChar` дописывает один символ в конец строки `x` на месте (изменяющая операция). `nimAddStrStr` дописывает в конец `x` все символы строки `y`, тоже изменяя `x` на месте. Обе процедуры реализуют оператор `&=`/встроенную `add` для строк на уровне бэкенда.

**Разбор реализации.** Строка в JS-бэкенде представлена как массив кодов символов, поэтому "добавление" — это просто `push` в существующий массив, без пересоздания строки целиком; `nimAddStrStr` делает это в цикле по всем элементам `y`. Сложность обеих — соответственно O(1) амортизированно и O(длина `y`).

**Список параметров.**
* `x: string` — строка-приёмник, изменяемая на месте.
* `c: char` — добавляемый символ.
* `y: string` — строка, чьё содержимое дописывается к `x`.

**Примеры.**

```nim
var s = "Hello"
add(s, ", мир!")
echo s  # выводит строку "Hello, мир!"
```

## XI. Разбор чисел с плавающей точкой

### 1. `parseFloatNative`

```nim
proc parseFloatNative(a: openarray[char]): float
```

**Что делает.** Разбирает срез символов как число с плавающей точкой, используя встроенный в JavaScript конструктор `Number` — то есть весь синтаксический разбор фактически делегируется движку JS, а не реализуется вручную в Nim.

**Разбор реализации.** Символы сначала собираются в обычную Nim-строку, затем приводятся к `cstring` и передаются в `Number(...)`. Это самый простой путь получить `float`, но он не даёт Nim-у контроля над деталями синтаксиса (например, поддержкой `_` как разделителя разрядов) — этим занимается вызывающая процедура `nimParseBiggestFloat`, которая уже очищает строку перед передачей сюда.

**Список параметров.**
* `a: openarray[char]` — срез символов, представляющий число.

---

### 2. `nimParseBiggestFloat`

```nim
proc nimParseBiggestFloat(s: openarray[char], number: var BiggestFloat): int {.compilerproc.}
```

**Что делает.** Полноценный разбор числа с плавающей точкой из среза символов `s`, с поддержкой знака, специальных значений `nan`/`inf`, разделителей разрядов (`_`) и экспоненциальной записи. Записывает результат в `number` (параметр вывода) и возвращает количество разобранных символов; возвращает `0`, если разбор не удался (строка не является корректным числом).

**Разбор реализации.** Функция вручную идёт по символам `s`, накапливая "очищенную" версию числа в `buf` (убирая при этом разделители `_`) и одновременно продвигая индекс `i`. Особые случаи `nan`/`inf`/`-inf` распознаются по первым буквам без обращения к `parseFloatNative`. Для обычных чисел сначала читается целая часть, затем (если есть точка) — дробная, затем (если есть `e`/`E`) — экспонента; на каждом шаге проверяется, что после этого шага строка всё ещё выглядит как валидное число, иначе разбор прерывается с результатом `0`. Итоговая очищенная строка передаётся в `parseFloatNative`.

**Список параметров.**
* `s: openarray[char]` — исходный срез символов для разбора.
* `number: var BiggestFloat` — параметр вывода: сюда записывается результат при успешном разборе.

**Примеры.**

```nim
var num: float
let consumed = nimParseBiggestFloat("3.14", num)
echo num       # выводит 3.14
echo consumed  # выводит 4 — разобраны все 4 символа
```

```nim
# Практический сценарий: разделители разрядов и экспонента
var big: float
discard nimParseBiggestFloat("1_000.5e2", big)
echo big  # выводит 100050.0
```

```nim
# Граничный случай: специальное значение
var n: float
discard nimParseBiggestFloat("nan", n)
echo n  # выводит nan
```

## XII. Практические рецепты

### Безопасное чтение сообщения об ошибке произвольного происхождения

```nim
proc describeFailure(action: proc()): string =
  ## Выполняет action и возвращает человекочитаемое описание сбоя,
  ## независимо от того, брошено ли Nim-исключение или сырая ошибка JS.
  try:
    action()
    result = "выполнено без ошибок"
  except:
    result = "ошибка: " & getCurrentExceptionMsg()

echo describeFailure(proc() = raise newException(ValueError, "неверные данные"))
# выводит "ошибка: неверные данные"
```

### Диагностика сбоя с полной трассировкой стека

```nim
proc withTrace(action: proc()) =
  ## Ловит исключение, печатает сообщение и сохранённую в исключении
  ## трассировку стека — удобно для логирования в продакшн-коде.
  try:
    action()
  except:
    let e = getCurrentException()
    echo "Сбой: ", e.msg
    echo getStackTrace(e)

proc risky() = raise newException(IOError, "нет доступа к ресурсу")
withTrace(proc() = risky())
```

### Целочисленный счётчик с явной защитой от переполнения

```nim
proc safeAccumulate(values: openarray[int]): int =
  ## Складывает значения, используя addInt напрямую, чтобы получить
  ## контролируемое исключение вместо тихого искажения результата.
  result = 0
  for v in values:
    result = addInt(result, v)

doAssertRaises(OverflowDefect):
  discard safeAccumulate([2147483647, 1])
```

### Сравнение множеств доступа с понятной диагностикой

```nim
proc describeAccessDiff(required, granted: set[0..31]): string =
  ## Показывает, каких прав не хватает, используя SetMinus напрямую —
  ## как если бы нужно было явно объяснить разницу пользователю.
  let missing = required - granted
  if SetCard(cast[int](missing)) == 0:
    result = "все права предоставлены"
  else:
    result = "не хватает " & $SetCard(cast[int](missing)) & " прав"

echo describeAccessDiff({1, 2, 5}, {1, 5})  # выводит "не хватает 1 прав"
```

### Устойчивый парсинг числовых настроек из строкового конфига

```nim
proc readNumericSetting(raw: string, default: float): float =
  ## Разбирает значение настройки, при некорректном формате
  ## (0 разобранных символов) возвращает значение по умолчанию.
  var value: float
  let consumed = nimParseBiggestFloat(raw, value)
  result = if consumed == 0: default else: value

echo readNumericSetting("2_500.75", 0.0)   # выводит 2500.75
echo readNumericSetting("не число", 10.0)  # выводит 10.0 — разбор не удался
```

## XIV. Сводка: какую процедуру выбрать

- Нужно узнать текст ошибки в `except`-блоке → используйте `getCurrentExceptionMsg`.
- Нужен сам объект исключения (например, чтобы проверить его тип) → используйте `getCurrentException`.
- Нужно залогировать не только сообщение, но и путь вызовов → используйте `getStackTrace(e)`.
- Нужно перевыбросить исключение, не создавая новое → это стандартный `raise` без аргументов (`reraiseException` под капотом).
- Нужна арифметика, которая гарантированно не "молчит" при переполнении → используйте `addInt`/`subInt`/`mulInt`/`divInt`/`modInt` (или их `Int64`-варианты) напрямую, если пишете низкоуровневый код.
- Нужно узнать, сколько элементов в множестве → используйте `SetCard`.
- Нужно понять разницу между двумя наборами прав/флагов → используйте `SetMinus` (то, что есть в одном, но нет в другом) или `SetXor` (то, что отличается в обе стороны).
- Нужно скопировать составное значение так, чтобы изменения копии не влияли на оригинал → это делает `nimCopy`, вызываемый компилятором на присваивании — вручную дёргать не нужно, если только не пишете код, тесно интегрированный с рантаймом.
- Нужно превратить строку из конфига/пользовательского ввода в число, не падая на мусорных данных → используйте `nimParseBiggestFloat` и проверяйте возвращаемое количество разобранных символов на `0`.
- Нужно проверить, что объект — экземпляр нужного подтипа, перед приведением → используйте `isObj` для мягкой проверки или полагайтесь на встроенное приведение типов (`chckObj` внутри) для проверки с исключением.
