
# Переменные и типы данных в Nim: содержательная справка

Язык Nim обладает строгой, но гибкой системой типов и управления памятью. Для разработчиков, переходящих с C, C++, Python или Rust, некоторые концепции Nim могут показаться непривычными.

Ниже представлено подробное пояснение различий между способами объявления переменных, типами объектов, указателями и другими связанными концепциями («и пр.»).

Весь код в этой справке написан в единой стилистике:
- вызовы процедур — в функциональной форме: `len(A)`, `startsWith(s, x)`, `add(seq, x)`, `close(f)`; точка используется **только** для доступа к полям структур/объектов (`p.x`) и для индексации (`a[0]`);
- исключение — `echo`, который всегда пишется как `echo "текст"`, без скобок вокруг аргумента;
- если объявляется два и более `let`/`var`/`const` подряд — используется блочная форма (ключевое слово один раз, ниже — с отступом каждая переменная);
- `import` — через запятую в одну строку, либо сгруппированный `std/[...]` синтаксис, если импорты логически связаны.

## 1. Объявление переменных: `let`, `var`, `const`

Эти три ключевых слова определяют **изменяемость** (mutability) и **время вычисления** переменной.

### `let` (неизменяемая переменная)
* **Суть:** Объявляет переменную, значение которой **нельзя изменить** после инициализации (single assignment).
* **Время вычисления:** Вычисляется во время выполнения (runtime), но компилятор может оптимизировать его в константу, если значение известно заранее.
* **Аналог:** `const` в C++ (для локальных переменных), `final` в Java, `let` в JavaScript/Rust.

```nim
let x = 10
# x = 20  # Ошибка компиляции: нельзя переприсвоить значение let-переменной
```

**Простой пример на ключевую особенность — компилятор ловит попытку изменения на этапе компиляции, а не в рантайме:**

```nim
let userName = "Мария"
# userName = "Диана"  # <-- закомментировано намеренно:
                       #     если раскомментировать, получим ошибку компиляции
                       #     "userName" cannot be assigned to
echo userName          # "Мария" — единственное присваивание, дальше только чтение
```

Если объявляется несколько `let` подряд — используем блочную форму, а не повтор ключевого слова:

```nim
let
  width = 1920   # ширина экрана, px
  height = 1080  # высота экрана, px
  ratio = width / height  # можно ссылаться на уже объявленные выше let в этом же блоке
```

### `var` (изменяемая переменная)
* **Суть:** Объявляет классическую изменяемую переменную. Её значение можно менять в процессе выполнения программы.
* **Время вычисления:** Во время выполнения (runtime).
* **Аналог:** Обычные переменные в C/C++/Python.

```nim
var y = 10
y = 20 # Разрешено
```

**Пример ключевой особенности — var можно объявить без начального значения, если тип указан явно:**

```nim
var counter: int  # без инициализации — Nim заполнит значением по умолчанию (0 для int)
echo counter        # 0
counter = counter + 1
echo counter        # 1
```

Блочная форма для нескольких `var`:

```nim
var
  attempts: int      # счётчик попыток, по умолчанию 0
  isRunning: bool    # флаг активности процесса, по умолчанию false
  logLine: string    # накопительный буфер строки лога, по умолчанию ""
```

### `const` (константа времени компиляции)
* **Суть:** Значение должно быть **вычислено на этапе компиляции**. Нельзя использовать результаты вызовов функций (если они не помечены как `static`), значения других переменных и т.д.
* **Особенность:** `const` не занимает места в памяти как переменная; компилятор просто подставляет её значение (inlining).

```nim
const Pi = 3.14159
const MaxSize = 100
# const runtimeVal = getCurrentTime() # Ошибка: нельзя вычислить во время компиляции
```

**Простой пример ключевой особенности — const можно использовать прямо в объявлении типов (например, размер массива), а var — нельзя:**

```nim
const BufferSize = 256   # известно заранее, на этапе компиляции

type
  Buffer = object
    data: array[BufferSize, byte]  # OK: BufferSize — const, компилятор знает размер заранее

# var runtimeSize = 256
# type BadBuffer = object
#   data: array[runtimeSize, byte]  # Ошибка: var нельзя использовать как размер array
```

Блочная форма для нескольких `const`:

```nim
const
  AppName = "Monolit"     # имя приложения
  AppVersion = "1.3"      # текущая версия
  MaxThreads = 4          # ограничение на число потоков обработки
```

## 2. Объекты: `object` и `ref object`

Это фундаментальное различие в Nim, определяющее **семантику памяти** (копирование vs ссылка) и **аллокацию** (стек vs куча).

### `object` (Значение / Структура)
* **Суть:** Тип-значение (value type). При присваивании или передаче в функцию **копируется** целиком.
* **Память:** Обычно размещается в стеке (или inline внутри другого объекта).
* **Аналог:** `struct` в C/C++/Rust.
* **Управление памятью:** Не требует сборки мусора (GC), очищается автоматически при выходе из области видимости.

```nim
type
  Point = object
    x, y: int

var p1 = Point(x: 1, y: 2)
var p2 = p1  # Происходит полное копирование данных!
p2.x = 10
echo p1.x    # Выведет 1 (p1 не изменился)
```

### `ref object` (ссылка / Класс)
* **Суть:** Ссылочный тип (reference type). При присваивании копируется **только ссылка** (указатель), а не сами данные.
* **Память:** Данные всегда выделяются в **куче** (heap).
* **Аналог:** Классы в Java/C#/Python, `class` в C++.
* **Управление памятью:** Отслеживается сборщиком мусора (ARC/ORC в современном Nim).

```nim
type
  Node = ref object
    value: int
    next: Node

var n1 = Node(value: 1)
var n2 = n1  # Копируется только ссылка!
n2.value = 99
echo n1.value # Выведет 99 (n1 и n2 указывают на одни и те же данные)
```

**Наглядное отличие через процедуру** (без `var` в параметрах — см. раздел 5):

```nim
proc tryModify(p: Point) =
  var localP = p
  localP.x = 999   # Меняется только локальная копия внутри процедуры

proc tryModifyRef(n: Node) =
  n.value = 999    # А тут меняются данные, на которые указывает n — они общие!

var p = Point(x: 1, y: 1)
tryModify(p)
echo p.x            # 1 — object никак не изменился снаружи

var n = Node(value: 1)
tryModifyRef(n)
echo n.value         # 999 — ref object изменился, хотя параметр передан "по значению"
```

Это ключевой источник путаницы для новичков: даже без `var` в сигнатуре процедуры, `ref object` позволяет менять данные снаружи, потому что копируется только ссылка, а не сам объект в куче.

**Ещё один простой пример — проверка на `nil`, характерная только для `ref object` (у обычного `object` такого понятия нет):**

```nim
type
  Task = ref object
    title: string

var t: Task  # ref-переменная без инициализации — по умолчанию равна nil
echo isNil(t)  # true — ссылка ни на что не указывает

t = Task(title: "Проверить HSE-план подрядчика")
echo isNil(t)  # false — теперь t указывает на реальные данные в куче

# t.title сработает только после проверки/присвоения — иначе обращение
# к полю nil-ссылки приведёт к падению программы во время выполнения
```

## 3. Указатели и адреса: `addr`, `ptr`, `ref`

Эти концепции работают с физическими адресами в памяти и ссылками.

### `addr` (оператор взятия адреса)
* **Суть:** Это **оператор** (как `&` в C++), который возвращает физический адрес переменной в памяти.
* **Возвращает:** Тип `ptr[T]`.
* **Правило:** Можно брать адрес только у `var` (или у `let`, если вы не планируете менять данные по этому адресу).

```nim
var num = 42
let numAddr = addr num # numAddr имеет тип ptr int
echo numAddr[]         # Выведет 42 (разыменование указателя)
```

**Простой пример ключевой особенности — через `ptr` можно изменить исходную переменную в обход обычного присваивания:**

```nim
var original = 5
let p = addr original
p[] = 100          # разыменование ptr и запись нового значения по адресу
echo original       # 100 — исходная переменная изменилась через указатель
```

### `ptr` (неуправляемый указатель)
* **Суть:** "Сырой" указатель, аналогичный указателям в C. **Не отслеживается сборщиком мусора**.
* **Использование:** Взаимодействие с C (FFI), написание высокопроизводительного кода, работа с `addr`.
* **Опасность:** Может привести к утечкам памяти или segfault, если память освобождена вручную, а вы всё ещё обращаетесь по указателю.

```nim
type
  CPointer = ptr int

var x = 10
var p: CPointer = addr x
```

### `ref` (управляемая ссылка)
* **Суть:** Это не оператор, а **модификатор типа**. Он создает ссылку на объект, которая **отслеживается сборщиком мусора**.
* **Использование:** Используется только при объявлении типов (`ref object`). Вы не можете написать `ref int` (для этого есть `ptr int` или `var`).

```nim
# Правильно:
type MyRef = ref MyObject

# Неправильно:
# var x: ref int  # Ошибка!
```

## 4. Взаимодействие с C и `struct`

**Важно:** В Nim **нет ключевого слова `struct`**.
Роль структур в Nim полностью выполняет `object`.

Однако, если вам нужно работать со структурами из языка C (через FFI), вы используете `object` с прагмами `{.importc.}` и `{.bycopy.}`.

```nim
# Как выглядит "struct" из C в Nim:
type
  CStruct {.importc: "my_c_struct", bycopy.} = object
    field1: cint
    field2: cstring

# Прагма {.bycopy.} говорит компилятору передавать этот объект
# по значению (как struct в C), а не по скрытому указателю.
```

## 5. Параметры процедур: `var` в сигнатуре

Ключевое слово `var` используется не только для объявления переменных, но и для **передачи параметров по ссылке**.

* **Без `var`:** Параметр передается по значению (копируется). *Примечание: компилятор Nim автоматически оптимизирует передачу больших объектов по ссылке, если видит, что вы их не меняете, но семантически это копия.*
* **С `var`:** Параметр передается по ссылке. Изменение параметра внутри процедуры изменит оригинальную переменную.

```nim
proc incrementByValue(x: int) =
  x = x + 1 # Изменяется только локальная копия

proc incrementByRef(x: var int) =
  x = x + 1 # Изменяется оригинальная переменная!

var myNum = 5
incrementByValue(myNum)
echo myNum # 5

incrementByRef(myNum)
echo myNum # 6
```

**Простой пример ключевой особенности — `var`-параметр работает и с полями объекта, что удобно для процедур-мутаторов:**

```nim
type
  Counter = object
    value: int

proc bump(c: var Counter) =
  # без "var" здесь пришлось бы возвращать новый Counter и переприсваивать
  c.value = c.value + 1

var counter = Counter(value: 0)
bump(counter)
bump(counter)
echo counter.value  # 2 — обе мутации применились к оригиналу
```

## 6. Другие важные типы

### `seq` (последовательности / динамические массивы)
* **Суть:** Динамический массив.
* **Семантика:** Формально это тип-значение (копируется при присваивании), но благодаря оптимизации **Copy-on-Write** (копирование при записи) в старых версиях или строгим правилам в Nim 2.0, он ведет себя предсказуемо.

```nim
var s: seq[int] = @[1, 2, 3]
add(s, 4)
```

**Простой пример ключевой особенности — `seq` копируется целиком при обычном присваивании (в отличие от `ref object`):**

```nim
var original = @[1, 2, 3]
var copy = original   # полное копирование содержимого, а не ссылки
add(copy, 4)
echo len(original)     # 3 — оригинал не затронут
echo len(copy)         # 4 — изменился только copy
```

Полезные функциональные вызовы для `seq` (в прежней, а не точечной форме):

```nim
var numbers = @[5, 3, 1, 4, 2]
echo len(numbers)        # 5 — длина последовательности
echo contains(numbers, 3) # true — проверка на вхождение элемента
delete(numbers, 0)        # удаляет элемент по индексу — теперь @[3, 1, 4, 2]
```

### `string` (строки)
* **Суть:** В Nim строки — это **изменяемые** последовательности символов (в отличие от Python/Java, где они неизменяемы).
* **Семантика:** Строки передаются по значению, но внутри они представлены как массивы байтов с нулевым терминатором (для совместимости с C). В Nim 2.0 строки имеют строгую семантику значений и не используют Copy-on-Write, что делает их потокобезопасными.

```nim
var str = "Hello"
add(str, " World") # Строки изменяемы!
```

**Простой пример ключевой особенности — часто используемые строковые процедуры в функциональной форме (из `std/strutils`):**

```nim
import std/strutils

let path = "  /home/maria/Monolit.nim  "
echo strip(path)               # обрезает пробелы по краям
echo startsWith(path, "  /home") # true — проверка префикса, без .startsWith()
echo toUpperAscii("nim")         # "NIM"
echo split("a,b,c", ',')         # @["a", "b", "c"]
```

## 7. Массивы: `array` (статический, фиксированного размера)

* **Суть:** Массив фиксированной длины, известной **на этапе компиляции**. В отличие от `seq`, размер нельзя изменить после создания.
* **Память:** Размещается на стеке (если это локальная переменная), без обращения к куче и без GC.
* **Аналог:** `T arr[N]` в C/C++, `[T; N]` в Rust.
* **Семантика:** Тип-значение — копируется целиком при присваивании, как `object`.

```nim
var a: array[3, int] = [1, 2, 3]
var b = a        # Полная копия, не ссылка
b[0] = 100
echo a[0]         # Выведет 1 (a не изменился)

# Индексация не обязана начинаться с 0:
var days: array[1..7, string] = ["Пн","Вт","Ср","Чт","Пт","Сб","Вс"]
echo days[1]      # "Пн"
```

**`array` vs `seq` — когда что использовать:**

| | `array[N, T]` | `seq[T]` |
| :--- | :--- | :--- |
| Размер | Фиксирован на этапе компиляции | Динамический (может расти/уменьшаться) |
| Память | Стек (обычно) | Куча |
| Копирование | Всегда полное | Полное (значение), но управляется GC |
| Когда использовать | Размер известен заранее, нужна максимальная скорость | Размер меняется во время выполнения |

## 8. Кортежи: `tuple`

* **Суть:** Группа значений разных типов. В отличие от `object`, не требует отдельного объявления `type`, хотя это возможно.
* **Семантика:** Тип-значение, копируется целиком, как `object`.
* **Отличие от `object`:** Два кортежа с одинаковым набором полей считаются одним и тем же типом (структурная эквивалентность), а не по имени.

```nim
# Безымянный (позиционный) кортеж:
var point = (1, 2)
echo point[0]        # 1

# Именованный кортеж — читается как object, но остаётся tuple:
var p2 = (x: 1, y: 2)
echo p2.x             # 1
p2.x = 10             # Поля кортежа можно менять, если сам tuple - var

# Два tuple с одинаковой структурой полей считаются одним типом:
type Coord = tuple[x, y: int]
var c: Coord = (x: 5, y: 5)
```

**Простой пример ключевой особенности — удобный способ вернуть несколько значений из процедуры и сразу распаковать их:**

```nim
proc minMax(numbers: seq[int]): tuple[minVal, maxVal: int] =
  # процедура возвращает именованный tuple — два значения одним вызовом
  result = (minVal: numbers[0], maxVal: numbers[0])
  for n in numbers:
    if n < result.minVal:
      result.minVal = n
    if n > result.maxVal:
      result.maxVal = n

let
  data = @[7, 2, 9, 4]
  (lo, hi) = minMax(data)  # распаковка tuple сразу в две отдельные переменные

echo lo   # 2
echo hi   # 9
```

## 9. Множества и перечисления: `set` и `enum`

### `enum` (перечисление)
* **Суть:** Именованный набор целочисленных констант. В Nim, в отличие от C, `enum` — это полноценный отдельный тип, а не просто `int`.

```nim
type
  Color = enum
    cRed, cGreen, cBlue

var favorite = cGreen
echo ord(favorite)   # 1 (порядковый номер значения)
```

**Простой пример ключевой особенности — `enum` можно безопасно использовать в `case`, и компилятор проверит полноту перебора вариантов:**

```nim
type
  HseStatus = enum
    hsCompliant, hsMinorIssue, hsCritical

proc describe(status: HseStatus): string =
  case status
  of hsCompliant: "Соответствует требованиям"
  of hsMinorIssue: "Незначительное замечание"
  of hsCritical: "Критическое нарушение"
  # если забыть один из вариантов enum — компилятор выдаст ошибку:
  # "not all cases are covered"

echo describe(hsCritical)  # "Критическое нарушение"
```

### `set` (битовое множество)
* **Суть:** Компактное множество значений **ординарного типа** (enum, char, диапазон малых int). Реализовано как битовая маска — очень быстрые операции проверки принадлежности и объединения.
* **Ограничение:** Базовый тип должен быть небольшим (обычно до 2^16 возможных значений), иначе компилятор откажется строить set.

```nim
type
  Direction = enum
    dNorth, dEast, dSouth, dWest

var allowed: set[Direction] = {dNorth, dEast}
incl(allowed, dSouth)
echo dWest in allowed   # false
echo dNorth in allowed  # true
```

**Простой пример ключевой особенности — `set` поддерживает алгебру множеств (объединение, пересечение) напрямую операторами:**

```nim
type
  Weekday = enum
    moMon, moTue, moWed, moThu, moFri, moSat, moSun

let
  workDays: set[Weekday] = {moMon, moTue, moWed, moThu, moFri}
  weekend: set[Weekday] = {moSat, moSun}
  allDays = workDays + weekend      # объединение множеств
  noOverlap = workDays * weekend    # пересечение — в данном случае пустое множество

echo card(allDays)    # 7 — card() возвращает количество элементов множества
echo card(noOverlap)  # 0 — будни и выходные не пересекаются
```

| **Неизменяемость** | `let` | Значение | Стек / Регистр | `const T x` (локальный) |
| **Изменяемость** | `var` | Значение | Стек / Куча | `T x` |
| **Константа** | `const` | Вычисление на этапе компиляции | Нет (inline) | `#define` / `constexpr` |
| **Структура** | `object` | Значение (копируется) | Стек | `struct` |
| **Класс** | `ref object` | Ссылка (копируется указатель) | Куча (GC) | `class` (с GC) |
| **Взятие адреса** | `addr` | Оператор | Возвращает адрес | `&x` |
| **Сырой указатель** | `ptr` | Ссылка (без GC) | Любой | `T*` |
| **Умная ссылка** | `ref` | Ссылка (с GC) | Куча | `std::shared_ptr` (грубо) |
| **Передача по ссылке**| `var` (в параметрах) | Ссылка | Зависит от переменной | `T&` |
| **Статический массив** | `array[N, T]` | Значение (копируется) | Стек | `T arr[N]` |
| **Динамический массив** | `seq[T]` | Значение (с GC) | Куча | `std::vector<T>` |
| **Кортеж** | `tuple` | Значение (структурная эквивалентность) | Стек | `std::tuple` / анонимный `struct` |
| **Перечисление** | `enum` | Значение (целочисленное) | Стек | `enum` |
| **Битовое множество** | `set[T]` | Значение | Стек | `std::bitset` (грубо) |

### Резюме для принятия решений:
1. Используйте **`let`** по умолчанию для всех переменных.
2. Используйте **`var`** только тогда, когда значение действительно нужно менять.
3. Используйте **`object`**, если данные небольшие и их логично копировать (координаты, цвета, конфигурации).
4. Используйте **`ref object`**, если данные большие, имеют сложный жизненный цикл или образуют графы/деревья (узлы дерева, состояния игры).
5. Используйте **`ptr`** и **`addr`** только при низкоуровневом программировании или FFI (взаимодействии с C).
6. Используйте **`array`**, если размер коллекции известен заранее и не меняется; используйте **`seq`**, если размер динамический.
7. Используйте **`tuple`**, если нужно быстро сгруппировать несколько значений без объявления отдельного типа (например, вернуть 2-3 значения из процедуры); используйте **`object`**, если структура достаточно важна, чтобы иметь собственное имя и методы.
8. Используйте **`enum`** для именованных наборов состояний вместо «магических» целых чисел; используйте **`set`** для компактного хранения и быстрой проверки комбинаций enum-значений.
9. Вызовы процедур пишите в функциональной форме — **`len(x)`, `close(f)`, `add(s, v)`**, а не `x.len()`, `f.close()`, `s.add(v)`. Точечную нотацию оставляйте только для доступа к полям (`p.x`) и индексации (`a[0]`).
10. Несколько `let`/`var`/`const` подряд объявляйте блоком (ключевое слово один раз, ниже — с отступом), а не повторяя ключевое слово на каждой строке.
11. `import` пишите через запятую в одну строку либо группируйте логически связанные модули через `std/[...]`.
