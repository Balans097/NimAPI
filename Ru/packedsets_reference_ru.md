# packedsets — справочник модуля

> **Импорт:** `import std/packedsets`
> **Область применения:** эффективное множество значений произвольного `Ordinal`-типа, реализованное как разреженный битовый набор (sparse bit set).

Модуль `packedsets` решает ту же задачу, что и `std/sets` (хранение уникальных значений с быстрой проверкой принадлежности), но ориентирован на плотные диапазоны порядковых значений — целые числа, `enum`, `char`, `distinct int` и т.п. Вместо хеш-таблицы отдельных значений модуль использует гибридное представление: небольшие множества (до 34 элементов) хранятся линейным массивом без единой аллокации, а после превышения этого порога структура автоматически переключается на разреженный битовый набор — хеш-таблицу «блоков» (`Trunk`), каждый из которых битовым вектором покрывает 512 последовательных значений. Благодаря этому модуль экономит память там, где `std/sets` тратил бы её на хранение хешей отдельных чисел.

По всему справочнику используется единая терминология: **режим малого множества** (small-set mode, до 34 элементов, линейный массив `a`) и **режим битового набора** (bitset mode, блоки `Trunk` с битовыми векторами). Переход между режимами необратим: после превышения порога множество никогда не возвращается в режим малого множества, даже если из него удалить элементы.

## I. Тип `PackedSet` и создание множества

### `PackedSet[A]`

```nim
type
  PackedSet*[A: Ordinal] = object
```

**Что делает.** Обобщённый тип множества, параметризованный порядковым типом `A` (`int`, `enum`, `char`, `distinct int` и т.п.). Значение этого типа хранится по значению (не по ссылке), но внутри может содержать ссылочные узлы — из-за этого модулю пришлось определить собственный хук `` `=copy` `` (см. раздел IV.5), чтобы присваивание `b = a` не приводило к опасному совместному владению внутренними структурами.

**Разбор реализации.** Тип объединяет две представления в одной структуре:

- поле `a: array[0..33, int]` вместе со счётчиком `elems` — «встроенный» линейный буфер на 34 значения. Пока `elems <= 34`, все операции работают с этим массивом простым перебором, не выделяя память в куче;
- поля `head: Trunk`, `data: seq[Trunk]`, `counter`, `max` — разреженный битовый набор. `data` — хеш-таблица с открытой адресацией (пробирование по схеме, аналогичной словарям Python: `((5*h) + 1 + perturb) and maxHash`), где ключом блока служит `key shr TrunkShift`, то есть номер группы из 512 последовательных значений. Каждый `Trunk` хранит битовый вектор `bits` длиной `IntsPerTrunk` машинных слов, где каждый бит отвечает за одно значение внутри группы. `head` — отдельный односвязный список тех же самых блоков, используемый только для последовательного перебора (см. `items`), не для поиска.

Порог в 34 элемента выбран, по комментарию в исходном коде, на основе профилирования — это компромисс между размером структуры на стеке и стоимостью перехода к хеш-таблице.

**Параметры.**
- `A: Ordinal` — тип элементов множества; должен поддерживать `ord()`.

**Примеры.**

```nim
type Id = distinct int

var
  ints: PackedSet[int]
  ids: PackedSet[Id]
```

### `initPackedSet`

```nim
proc initPackedSet*[A]: PackedSet[A]
```

**Что делает.** Возвращает пустое множество типа `PackedSet[A]`, готовое к использованию сразу после объявления через `var`, без промежуточных шагов инициализации.

**Разбор реализации.** Явно обнуляет все поля режима битового набора (`elems`, `counter`, `max`, `head`, `data`); поле малого буфера `a` не заполняется — оно значения не имеет, пока `elems == 0`.

**Параметры.** Нет (тип `A` выводится из контекста использования или указывается явно, `initPackedSet[int]()`).

**Примеры.**

```nim
let a = initPackedSet[int]()
assert len(a) == 0

type Id = distinct int
var ids = initPackedSet[Id]()
incl(ids, 3.Id)
assert len(ids) == 1
```

---

### `toPackedSet`

```nim
proc toPackedSet*[A](x: openArray[A]): PackedSet[A] {.since: (1, 3).}
```

**Что делает.** Строит новое множество из массива, `seq` или другого `openArray`. Повторяющиеся значения автоматически схлопываются в одно вхождение.

**Разбор реализации.** Тривиальная обёртка: создаёт пустое множество через `initPackedSet` и включает в него по очереди каждый элемент `x` вызовом `incl`. Сложность — O(n) обращений к `incl`, где n — длина `x` (сама вставка при этом амортизированно быстрая, см. разбор `incl`).

**Параметры.**
- `x: openArray[A]` — исходная последовательность значений, не изменяется.

**Примеры.**

```nim
let a = toPackedSet([5, 6, 7, 8, 8])
assert len(a) == 4          # дубликат "8" учтён один раз
assert $a == "{5, 6, 7, 8}"

let empty = toPackedSet(newSeq[int]())  # граничный случай: пустой массив
assert len(empty) == 0
```

## II. Проверка и добавление одиночных элементов

### `contains` / `in`

```nim
proc contains*[A](s: PackedSet[A], key: A): bool
```

**Что делает.** Проверяет, входит ли `key` в множество `s`. Используется как обычная процедура, так и через операторы `in` / `notin`.

**Разбор реализации.** Ветвление по текущему режиму хранения:

- в режиме малого множества (`elems <= len(s.a)`) — линейный перебор массива `a`, сравнение `ord(key)` с каждым элементом, O(k), где k ≤ 34;
- в режиме битового набора — вычисляется номер блока `ord(key) shr TrunkShift`, блок ищется в хеш-таблице `data` тем же пробированием, что и при вставке, после чего проверяется единственный бит `ord(key) and TrunkMask` внутри блока. В среднем O(1).

**Параметры.**
- `s: PackedSet[A]` — множество, не изменяется.
- `key: A` — проверяемое значение.

**Примеры.**

```nim
type ABCD = enum A, B, C, D

let a = toPackedSet([1, 3, 5])
assert contains(a, 3)
assert 3 in a
assert not contains(a, 8)
assert 8 notin a

let letters = toPackedSet([A, C])
assert A in letters
assert C in letters
assert B notin letters

let empty = initPackedSet[int]()   # граничный случай: пустое множество
assert not contains(empty, 0)
```

### `incl` (элемент)

```nim
proc incl*[A](s: var PackedSet[A], key: A)
```

**Что делает.** Добавляет `key` в множество. Если `key` уже присутствует — ничего не происходит (операция идемпотентна).

**Разбор реализации.** Это ключевая процедура, отвечающая за переход между режимами хранения:

1. Пока `elems <= len(s.a)` (34), сначала выполняется линейный поиск: если значение уже есть в буфере — процедура завершается без изменений.
2. Если значения нет и в буфере ещё есть свободное место (`elems < len(s.a)`) — значение дописывается в конец буфера, `elems` увеличивается на единицу.
3. Если свободного места в буфере уже нет — происходит одноразовый переход в режим битового набора: выделяется таблица `data` начального размера `InitIntSetSize` (8), и все 34 уже накопленных значения из `a` переносятся в неё через внутреннюю процедуру `bitincl`. Только после этого «проваливания» (fall through, как отмечено комментарием в исходнике) в набор добавляется и новый `key`.

Внутри режима битового набора вставка (`intSetPut`) при необходимости увеличивает таблицу вдвое (`intSetEnlarge`), когда коэффициент заполнения превышает 2/3 или свободных слотов остаётся меньше четырёх — классическая стратегия рехеширования открытой адресации.

**Параметры.**
- `s: var PackedSet[A]` — изменяемое множество.
- `key: A` — добавляемое значение.

**Примеры.**

```nim
var a = initPackedSet[int]()
incl(a, 3)
incl(a, 3)                 # повторное включение — не создаёт дубликат
assert len(a) == 1

var big = initPackedSet[int]()
for i in 0..<100:           # граничный случай: переход через порог в 34 элемента
  incl(big, i)
assert len(big) == 100      # переход в режим битового набора произошёл прозрачно
```

### `containsOrIncl`

```nim
proc containsOrIncl*[A](s: var PackedSet[A], key: A): bool
```

**Что делает.** Совмещает проверку и вставку за один проход: включает `key` в множество и возвращает, было ли значение уже в нём **до** вызова. Позволяет избежать двойного поиска (`contains` + `incl`) в коде, где нужно и то, и другое.

**Разбор реализации.** Повторяет ветвление `incl`, но по пути запоминает и возвращает результат проверки: в режиме малого множества — по итогам линейного перебора; в режиме битового набора — по значению бита до его установки. В отличие от `incl`, при первом переходе через порог 34 эта процедура делегирует вставку обычному `incl` (то есть не дублирует логику рехеширования).

**Параметры.**
- `s: var PackedSet[A]` — изменяемое множество.
- `key: A` — проверяемое и добавляемое значение.

**Примеры.**

```nim
var a = initPackedSet[int]()
assert containsOrIncl(a, 3) == false   # значения не было — добавлено
assert containsOrIncl(a, 3) == true    # значение уже было
assert containsOrIncl(a, 4) == false
assert len(a) == 2
```

## III. Удаление одиночных элементов

### `excl` (элемент)

```nim
proc excl*[A](s: var PackedSet[A], key: A)
```

**Что делает.** Удаляет `key` из множества. Если значения там не было — операция ничего не делает и исключения не поднимает.

**Разбор реализации.** В режиме малого множества удаление выполняется перестановкой с последним элементом буфера (swap-remove): найденный элемент заменяется последним активным элементом массива, `elems` уменьшается на единицу — O(k), без сохранения порядка вставки. В режиме битового набора — просто сбрасывается соответствующий бит внутри найденного блока `Trunk`; сам блок из связного списка `head` и из таблицы `data` не удаляется, даже если все его биты становятся нулевыми. Это важное следствие: **память, однажды выделенная под режим битового набора, не сокращается** — ни при удалении отдельных элементов, ни при опустошении целого блока.

**Параметры.**
- `s: var PackedSet[A]` — изменяемое множество.
- `key: A` — удаляемое значение.

**Примеры.**

```nim
var a = toPackedSet([3])
excl(a, 3)
excl(a, 3)                 # повторное удаление — не ошибка
excl(a, 99)                # удаление отсутствующего значения — не ошибка
assert len(a) == 0
```

---

### `missingOrExcl`

```nim
proc missingOrExcl*[A](s: var PackedSet[A], key: A): bool
```

**Что делает.** Удаляет `key` из множества и сообщает, отсутствовал ли он **до** вызова. Обратите внимание на направление в отличие от `containsOrIncl`: здесь `true` означает «значения не было», а не «значение было».

**Разбор реализации.** Замеряет `len(s)` до удаления и после, сравнивая их: если длина не изменилась — значит, элемент отсутствовал и удалять было нечего. Важная особенность производительности: в режиме битового набора `len` не хранится отдельным счётчиком, а вычисляется полным проходом по `items` (см. раздел VII.1) — то есть `missingOrExcl` в этом режиме стоит O(n), а не O(1), как можно было бы ожидать от простого сравнения счётчиков.

**Параметры.**
- `s: var PackedSet[A]` — изменяемое множество.
- `key: A` — проверяемое и удаляемое значение.

**Примеры.**

```nim
var a = toPackedSet([5])
assert missingOrExcl(a, 5) == false   # значение было и удалено
assert missingOrExcl(a, 5) == true    # значения уже не было
```

## IV. Операции над множеством как единым целым

### `incl` (множество)

```nim
proc incl*[A](s: var PackedSet[A], other: PackedSet[A])
```

**Что делает.** Добавляет в `s` все элементы `other` — вставка «на месте» (in-place версия операции объединения, см. `union`).

**Разбор реализации.** Простой перебор `other` через `items` с вызовом одиночного `incl(s, item)` на каждой итерации — O(m) вставок, где m = `len(other)`.

**Параметры.**
- `s: var PackedSet[A]` — множество, в которое добавляются элементы.
- `other: PackedSet[A]` — источник элементов, не изменяется.

**Примеры.**

```nim
var a = toPackedSet([1])
incl(a, toPackedSet([5]))
assert len(a) == 2
assert 5 in a
```

---

### `excl` (множество)

```nim
proc excl*[A](s: var PackedSet[A], other: PackedSet[A])
```

**Что делает.** Удаляет из `s` все элементы, присутствующие в `other` (in-place версия разности, см. `difference`).

**Разбор реализации.** Зеркально предыдущей процедуре: перебор `other` через `items` с вызовом одиночного `excl(s, item)`.

**Параметры.**
- `s: var PackedSet[A]` — множество, из которого удаляются элементы.
- `other: PackedSet[A]` — множество удаляемых значений, не изменяется.

**Примеры.**

```nim
var a = toPackedSet([1, 5])
excl(a, toPackedSet([5]))
assert len(a) == 1
assert 5 notin a
```

### `clear`

```nim
proc clear*[A](result: var PackedSet[A])
```

**Что делает.** Возвращает множество в пустое состояние, освобождая внутренние структуры режима битового набора (в отличие от `excl`, здесь память действительно освобождается).

**Разбор реализации.** Присваивает всем полям исходные пустые значения: `data` становится пустым `seq`, `max` и `counter` обнуляются, `head` — `nil`, `elems` — `0`. В исходном коде закомментирован более старый вариант реализации (через `setLen` с ручным обнулением ячеек `data`) — текущий вариант проще и полностью пересоздаёт структуры при следующей вставке.

**Параметры.**
- `result: var PackedSet[A]` — очищаемое множество (имя параметра в сигнатуре модуля — `result`, это не специальное значение, а обычный параметр).

**Примеры.**

```nim
var a = toPackedSet([5, 7])
clear(a)
assert len(a) == 0
```

### `isNil`

```nim
proc isNil*[A](x: PackedSet[A]): bool
```

**Что делает.** Возвращает `true`, если множество пусто. Название сохранено по историческим причинам (от более старой реализации через указатели) — `PackedSet` является типом-значением, и речь не о указателе `nil` в обычном смысле.

**Разбор реализации.** Условие — `x.head == nil` **и** `x.elems == 0`. Оба условия нужны одновременно: в режиме малого множества `head` всегда `nil` (блоки ещё не создавались), поэтому опустошение проверяется через `elems`; в режиме битового набора `elems` уже не актуален, и пустота определяется по `head`. Отсюда важная граничная особенность: если множество однажды перешло в режим битового набора, а затем все его элементы были удалены через `excl`, блок `Trunk` из связного списка `head` не удаляется (см. разбор `excl`) — значит, `isNil` в этом случае вернёт `false`, даже когда `len(x) == 0`. Для больших множеств проверку пустоты надёжнее делать через `len(x) == 0`, а не через `isNil`.

**Параметры.**
- `x: PackedSet[A]` — проверяемое множество.

**Примеры.**

```nim
var a = initPackedSet[int]()
assert isNil(a)
incl(a, 2)
assert not isNil(a)
excl(a, 2)
assert isNil(a)             # верно, пока множество не покидало режим малого набора
```

### `` `=copy` `` / `assign`

```nim
proc `=copy`*[A](dest: var PackedSet[A], src: PackedSet[A])
proc assign*[A](dest: var PackedSet[A], src: PackedSet[A]) {.deprecated.}
```

**Что делает.** Копирует содержимое `src` в `dest` независимой копией. `assign` — устаревший псевдоним, оставленный для обратной совместимости и внутри просто вызывающий `` `=copy` ``.

**Разбор реализации.** Это переопределённый хук присваивания Nim (`=copy`), который автоматически вызывается компилятором при обычном `dest = src`, если `dest` ещё не является `src` же самим объектом. Необходимость в нём объясняется внутренним устройством типа: в режиме битового набора `PackedSet` содержит ссылочные узлы `Trunk`, и наивное побитовое копирование привело бы к тому, что `dest` и `src` делили бы одни и те же изменяемые блоки — изменение одного повлияло бы на другое. Поэтому реализация ветвится:

- если `src` в режиме малого множества — достаточно скопировать простые поля и массив `a` (массив копируется по значению, аренды памяти нет);
- если `src` в режиме битового набора — выделяется новая таблица `data` того же размера, и каждый узел `Trunk` из связного списка `src.head` клонируется заново (`new(n)`, копирование `key` и `bits`) и заново вставляется в `dest.data` тем же алгоритмом пробирования, что и при обычной вставке.

**Параметры.**
- `dest: var PackedSet[A]` — приёмник; не обязан быть предварительно инициализирован через `initPackedSet`.
- `src: PackedSet[A]` — источник, не изменяется.

**Примеры.**

```nim
var
  a = initPackedSet[int]()
  b = initPackedSet[int]()
incl(b, 5)
incl(b, 7)
assign(a, b)                # то же самое, что "a = b" — вызывается автоматически =copy
assert len(a) == 2

incl(a, 9)
assert 9 notin b             # копия независима — изменение a не затронуло b
```

## V. Теоретико-множественные операции

### `union` / `+`

```nim
proc union*[A](s1, s2: PackedSet[A]): PackedSet[A]
proc `+`*[A](s1, s2: PackedSet[A]): PackedSet[A] {.inline.}
```

**Что делает.** Возвращает новое множество, содержащее все элементы `s1` и `s2` вместе. Оператор `+` — точный синоним `union`.

**Разбор реализации.** `result` инициализируется как независимая копия `s1` (через `assign`, см. выше — важно именно копирование, а не совместное владение), после чего в неё включаются элементы `s2` через `incl` (множество). Сложность — O(|s1| + |s2|).

**Параметры.**
- `s1, s2: PackedSet[A]` — исходные множества, не изменяются.

**Примеры.**

```nim
let
  a = toPackedSet([1, 2, 3])
  b = toPackedSet([3, 4, 5])
  c = union(a, b)
assert len(c) == 5
assert c == toPackedSet([1, 2, 3, 4, 5])
assert (a + b) == c          # оператор-синоним
```

---

### `intersection` / `*`

```nim
proc intersection*[A](s1, s2: PackedSet[A]): PackedSet[A]
proc `*`*[A](s1, s2: PackedSet[A]): PackedSet[A] {.inline.}
```

**Что делает.** Возвращает новое множество из элементов, присутствующих одновременно в `s1` и `s2`.

**Разбор реализации.** Начинает с пустого множества и перебирает элементы `s1`, добавляя в результат только те, что также найдены в `s2` через `contains`. Сложность — O(|s1|) проверок принадлежности.

**Параметры.**
- `s1, s2: PackedSet[A]` — исходные множества, не изменяются.

**Примеры.**

```nim
let
  a = toPackedSet([1, 2, 3])
  b = toPackedSet([3, 4, 5])
  c = intersection(a, b)
assert len(c) == 1
assert c == toPackedSet([3])
```

---

### `difference` / `-`

```nim
proc difference*[A](s1, s2: PackedSet[A]): PackedSet[A]
proc `-`*[A](s1, s2: PackedSet[A]): PackedSet[A] {.inline.}
```

**Что делает.** Возвращает новое множество из элементов `s1`, отсутствующих в `s2`.

**Разбор реализации.** Зеркально `intersection`: перебор `s1`, но в результат включаются элементы, для которых `contains(s2, item)` ложно.

**Параметры.**
- `s1, s2: PackedSet[A]` — исходные множества, не изменяются.

**Примеры.**

```nim
let
  a = toPackedSet([1, 2, 3])
  b = toPackedSet([3, 4, 5])
  c = difference(a, b)
assert len(c) == 2
assert c == toPackedSet([1, 2])
```

---

### `symmetricDifference`

```nim
proc symmetricDifference*[A](s1, s2: PackedSet[A]): PackedSet[A]
```

**Что делает.** Возвращает элементы, входящие ровно в одно из двух множеств (аналог операции «исключающее или» для множеств).

**Разбор реализации.** Приём, экономящий отдельный проход: `result` начинается как копия `s1`, а затем для каждого элемента `s2` вызывается `containsOrIncl(result, item)`. Если элемент уже был в `result` (то есть он был и в `s1`, и в `s2`) — он тут же удаляется через `excl`, поскольку в симметрической разности общие элементы участвовать не должны. Если элемент был добавлен впервые (значит, он был только в `s2`) — он остаётся в результате. Итог за один проход по `s2` совмещает и объединение, и удаление общей части.

**Параметры.**
- `s1, s2: PackedSet[A]` — исходные множества, не изменяются.

**Примеры.**

```nim
let
  a = toPackedSet([1, 2, 3])
  b = toPackedSet([3, 4, 5])
  c = symmetricDifference(a, b)
assert len(c) == 4
assert c == toPackedSet([1, 2, 4, 5])   # "3" встречается в обоих и исключено
```

## VI. Сравнение множеств

### `<=` (подмножество)

```nim
proc `<=`*[A](s1, s2: PackedSet[A]): bool
```

**Что делает.** Возвращает `true`, если каждый элемент `s1` также присутствует в `s2`. Равные множества считаются подмножествами друг друга.

**Разбор реализации.** Перебор `s1` с проверкой `contains(s2, item)` на каждом шаге; при первом же несовпадении процедура сразу возвращает `false` (короткое замыкание) — O(|s1|) в худшем случае, но обычно быстрее.

**Параметры.**
- `s1, s2: PackedSet[A]` — сравниваемые множества.

**Примеры.**

```nim
let
  a = toPackedSet([1])
  b = toPackedSet([1, 2])
  c = toPackedSet([1, 3])
assert a <= b
assert b <= b                # множество является подмножеством самого себя
assert not (c <= b)
```

---

### `<` (строгое подмножество)

```nim
proc `<`*[A](s1, s2: PackedSet[A]): bool
```

**Что делает.** Возвращает `true`, если `s1` — подмножество `s2`, но не равно ему (в `s2` есть хотя бы один элемент сверх `s1`).

**Разбор реализации.** Выражается через уже определённый `<=`: `s1 <= s2 and not (s2 <= s1)` — то есть до двух проходов проверки подмножества.

**Параметры.**
- `s1, s2: PackedSet[A]` — сравниваемые множества.

**Примеры.**

```nim
let
  a = toPackedSet([1])
  b = toPackedSet([1, 2])
  c = toPackedSet([1, 3])
assert a < b
assert not (b < b)           # множество не является строгим подмножеством самого себя
assert not (c < b)
```

---

### `==` (равенство)

```nim
proc `==`*[A](s1, s2: PackedSet[A]): bool
```

**Что делает.** Возвращает `true`, если оба множества содержат в точности одни и те же элементы (без учёта порядка вставки и внутреннего представления — режим малого множества и режим битового набора с одинаковым составом равны).

**Разбор реализации.** Взаимная проверка подмножества в обе стороны: `s1 <= s2 and s2 <= s1`.

**Параметры.**
- `s1, s2: PackedSet[A]` — сравниваемые множества.

**Примеры.**

```nim
assert toPackedSet([1, 2]) == toPackedSet([2, 1])
assert toPackedSet([1, 2]) == toPackedSet([2, 1, 2])   # дубликат при построении не влияет
```

---

### `disjoint`

```nim
proc disjoint*[A](s1, s2: PackedSet[A]): bool
```

**Что делает.** Возвращает `true`, если у `s1` и `s2` нет ни одного общего элемента.

**Разбор реализации.** Перебор `s1` с проверкой `contains(s2, item)`; при первом найденном совпадении сразу возвращается `false` (короткое замыкание).

**Параметры.**
- `s1, s2: PackedSet[A]` — сравниваемые множества.

**Примеры.**

```nim
let
  a = toPackedSet([1, 2])
  b = toPackedSet([2, 3])
  c = toPackedSet([3, 4])
assert disjoint(a, b) == false
assert disjoint(a, c) == true
```

---

### `card`

```nim
proc card*[A](s: PackedSet[A]): int {.inline.}
```

**Что делает.** Синоним `len` — количество элементов множества. Название отсылает к математическому термину «мощность множества» (cardinality).

**Разбор реализации.** Прямая передача вызова в `len(s)`, без дополнительной логики.

**Параметры.**
- `s: PackedSet[A]` — множество.

**Примеры.**

```nim
let a = toPackedSet([1, 3, 5])
assert card(a) == 3
assert card(a) == len(a)
```

## VII. Перебор и вывод

### `items`

```nim
iterator items*[A](s: PackedSet[A]): A {.inline.}
```

**Что делает.** Перебирает все элементы множества `s` — базовый итератор, на котором построены `len`, `$`, теоретико-множественные операции и операции сравнения. Работает с обычным `for value in s`.

**Разбор реализации.** Ветвится по режиму хранения:

- в режиме малого множества — простой линейный проход по активной части массива `a` (`0 ..< elems`) с приведением обратно к типу `A`;
- в режиме битового набора — обход связного списка блоков через `head` (а не через хеш-таблицу `data` — список `head` предназначен именно для последовательного перебора, тогда как `data` служит для быстрого поиска по ключу). Внутри каждого блока перебираются все машинные слова битового вектора `bits`; для каждого ненулевого слова его биты извлекаются поочерёдно сдвигом вправо (`w shr 1`) с проверкой младшего бита, а исходное значение восстанавливается по формуле `(trunk.key shl TrunkShift) or (индекс_слова shl IntShift + индекс_бита)`.

**Важная оговорка о порядке.** Итерация **не гарантирует** возрастающий порядок значений: в режиме малого множества порядок — это порядок вставки (после swap-remove при удалении порядок может дополнительно нарушиться); в режиме битового набора порядок определяется порядком блоков в связном списке `head` (обычно обратным порядку их создания) и лишь внутри одного блока значения идут по возрастанию бит.

**Параметры.**
- `s: PackedSet[A]` — перебираемое множество, не изменяется. Изменять `s` во время итерации нельзя — исходный код отдельно отмечает, что копия слова битов внутри цикла корректна именно потому, что модифицирующие операции во время обхода запрещены.

**Примеры.**

```nim
let a = toPackedSet([10, 20, 30])
var total = 0
for value in a:               # порядок не гарантирован, но каждое значение встретится ровно раз
  total = total + value
assert total == 60

let empty = initPackedSet[int]()   # граничный случай: пустое множество
for value in empty:
  assert false                      # тело цикла не выполнится ни разу
```

### `` `$` ``

```nim
proc `$`*[A](s: PackedSet[A]): string
```

**Что делает.** Строковое представление множества в виде `{a, b, c}`.

**Разбор реализации.** Реализовано через внутренний шаблон `dollarImpl`, который опирается на тот же итератор `items` — соответственно, порядок элементов в строке подчиняется тем же правилам (не гарантированно возрастающий), что описаны выше. То, что для малых множеств чисел вывод обычно выглядит отсортированным, — побочный эффект сохранения порядка вставки в режиме малого множества, а не гарантия модуля.

**Параметры.**
- `s: PackedSet[A]` — представляемое множество.

**Примеры.**

```nim
let a = toPackedSet([1, 2, 3])
assert $a == "{1, 2, 3}"

let empty = initPackedSet[int]()   # граничный случай: пустое множество
assert $empty == "{}"
```

## VIII. Практические рецепты

### Удаление дубликатов из списка

```nim
let raw = [7, 3, 7, 1, 3, 3, 9]
let unique = toPackedSet(raw)
echo unique                  # выводит множество без повторов, например "{7, 3, 1, 9}"
assert len(unique) == 4
```

### Обход графа с пропуском уже посещённых вершин

```nim
# граф задан списком смежности: сосед -> список соседей
let graph = @[
  @[1, 2],   # соседи вершины 0
  @[3],      # соседи вершины 1
  @[3],      # соседи вершины 2
  newSeq[int]()
]

var
  visited = initPackedSet[int]()
  queue = @[0]

while len(queue) > 0:
  let node = queue[0]
  queue.delete(0)
  # containsOrIncl сразу говорит, посещали ли вершину, и отмечает её как посещённую
  if not containsOrIncl(visited, node):
    for neighbour in graph[node]:
      if neighbour notin visited:
        queue.add(neighbour)

assert len(visited) == 4
```

### Сравнение двух наборов разрешений

```nim
let
  required = toPackedSet(["read", "write", "execute"].mapIt(ord(it[0])))
  granted = toPackedSet(["read", "write"].mapIt(ord(it[0])))

# проверяем, покрывает ли выданный набор разрешений всё необходимое
if not (required <= granted):
  let missing = difference(required, granted)
  echo missing                # какие разрешения не хватает
```

### Подсчёт изменений между двумя версиями набора идентификаторов

```nim
let
  before = toPackedSet([1, 2, 3, 4])
  after = toPackedSet([2, 3, 4, 5])
  changed = symmetricDifference(before, after)

echo card(changed)            # выводит 2: идентификаторы "1" и "5"
assert 1 in changed            # было и пропало
assert 5 in changed             # появилось
assert 2 notin changed           # осталось без изменений — не входит в разность
```

## X. Сводка: какую процедуру выбрать

- Нужно быстро создать множество из готового списка значений с удалением дублей → используйте `toPackedSet`.
- Нужно просто проверить, есть ли значение в множестве → используйте `contains` или оператор `in`.
- Нужно добавить значение и заодно узнать, было ли оно уже там (например, чтобы не обрабатывать его повторно) → используйте `containsOrIncl`, а не отдельные вызовы `contains` + `incl`.
- Нужно удалить значение и заодно узнать, отсутствовало ли оно (учитывая, что в режиме битового набора эта проверка стоит O(n)) → используйте `missingOrExcl`, но по возможности избегайте в горячих циклах над большими множествами.
- Нужно объединить, пересечь или вычесть целиком другое множество, не создавая новый объект → используйте `incl(s, other)` / `excl(s, other)` (изменяют `s` на месте).
- Нужно получить результат теоретико-множественной операции как новое множество, не трогая исходные → используйте `union` / `intersection` / `difference` / `symmetricDifference` (или операторы `+` / `*` / `-`).
- Нужно узнать, какие значения изменились между двумя «снимками» одного и того же множества → используйте `symmetricDifference`.
- Нужно сравнить множества между собой (включение, строгое включение, равенство, непересекаемость) → используйте `<=`, `<`, `==`, `disjoint` соответственно.
- Нужно независимо клонировать множество перед изменением копии (в силу внутренних ссылочных узлов режима битового набора, простое присваивание `=` уже вызывает `` `=copy` `` автоматически) → явный вызов `` `=copy` ``/`assign` нужен лишь в редких случаях ручного управления памятью.
- Нужно проверить пустоту множества, которое ранее могло перейти в режим битового набора и затем полностью опустеть через `excl` → предпочитайте `len(s) == 0`, а не `isNil(s)` (см. оговорку в разделе IV.4).
- Нужен предсказуемый порядок вывода (например, по возрастанию) → `packedsets` такого не гарантирует ни в `items`, ни в `` `$` ``; если порядок важен, отсортируйте результат `items` явно средствами `std/algorithm`.
