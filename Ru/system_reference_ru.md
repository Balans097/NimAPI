# system — справочник модуля

> **Импорт:** модуль подключается неявно компилятором, `import system` писать
> не нужно и нельзя объявить собственный модуль с именем `system`.
> **Область применения:** базовые типы (`seq`, `string`, `array`, `openArray`,
> диапазоны), управление памятью и владением (`addr`, `new`, `move`,
> хуки `=destroy`/`=copy`/`=sink`), интроспекция типов (`typeof`, `is`, `of`,
> `sizeof`), базовые операции над строками и последовательностями
> (`add`, `len`, `setLen`, `substr`, `&`), иерархия исключений и завершение
> программы (`quit`), а также элементарный вывод (`echo`).

Модуль `system` — это фундамент, на котором стоит весь остальной Nim: типы
`int`, `string`, `seq[T]`, `array` объявлены здесь же (в подключаемых файлах
`system/basic_types` и `system/hti`), а большинство процедур помечены
прагмой `magic` — это значит, что реальную работу выполняет не тело
процедуры, а сам компилятор, а объявление в `system.nim` служит, по сути,
типизированной подписью для документации и разрешения перегрузок.

Общие соглашения, которые стоит держать в голове при чтении этого
справочника:

- Многие процедуры объявлены **семьями перегрузок** для разных типов —
  например, `len` отдельно для `string`, `seq[T]`, `array`, `openArray`,
  `cstring`. В справочнике такие семьи разбираются одним подразделом с
  перечислением всех вариантов, а не отдельно на каждый тип.
  Многие процедуры также имеют "особый вид": `high`/`low`, принимающие
  и значение, и `typedesc` — то же правило.
- Часть объявлений скрыта за `when defined(...)` — они существуют только на
  конкретных бэкендах/сборках (JS, ORC/ARC, standalone-режим и т.п.). В
  справочнике такие места отмечены пометкой "условная компиляция".
- Все примеры в этом справочнике намеренно переписаны в префиксной форме
  (`len(a)`, а не `a.len()`), хотя в оригинальной документации Nim
  повсеместно используется точечная нотация — это единственное отличие
  примеров от исходников.

## I. Типы и метапрограммирование

### 1. `static`, `type` — мета-типы

```nim
type
  `static`*[T] {.magic: "Static".}
  `type`*[T] {.magic: "Type".}
```

**Что делает.** Это не обычные типы, а служебные конструкции компилятора.
`static[T]` описывает значения, которые обязаны быть вычислены во время
компиляции (используется как ограничение параметра генерика: `x: static int`
значит "любое целое, известное на этапе компиляции"). `type[T]` описывает
"тип самого типа" — то, что возвращает выражение `type(x)`.

- **Параметры:** `T` — тип-параметр, который описывается мета-типом; сами по
  себе `static`/`type` нигде не создаются напрямую, а используются как
  ограничения (`proc f(x: static int)`) или через coercion-синтаксис
  `static(x)` / `type(x)`.

```nim
proc repeatChar(c: static char, n: int): string =
  # `c` гарантированно известен на этапе компиляции — компилятор может
  # заинлайнить или проверить его прямо здесь
  result = newString(n)
  for i in 0 ..< n:
    result[i] = c

let s = repeatChar('x', 5)
assert s == "xxxxx"

assert type(42) is int          # `type(x)` — тип выражения `x`
assert type("привет") is string
```

### 2. `typeof`

```nim
proc typeof*(x: untyped; mode = typeOfIter): typedesc
```

**Что делает.** Возвращает тип выражения `x`, вычисляемый компилятором без
реального выполнения `x`. Параметр `mode` управляет тем, как трактовать
неоднозначные вызовы: если существуют одновременно и обычная процедура,
и итератор с одинаковым именем, `typeOfIter` (по умолчанию) предпочитает
трактовку "это вызов итератора", а `typeOfProc` — "это вызов обычной
процедуры". Само наличие двух режимов — следствие того, что в Nim имя может
быть перегружено между `proc` и `iterator` с одинаковой сигнатурой вызова.

- **Параметры:**
  - `x: untyped` — произвольное выражение, тип которого нужно определить;
    выражение не вычисляется.
  - `mode: TypeOfMode` — `typeOfProc` или `typeOfIter`, определяет
    приоритет трактовки при неоднозначности; по умолчанию `typeOfIter`.

```nim
proc myFoo(): float = 0.0
iterator myFoo(): string = yield "abc"

assert typeof(myFoo()) is string           # режим по умолчанию: как итератор
assert typeof(myFoo(), typeOfProc) is float # явно как обычный вызов процедуры
```

### 3. `or`, `and`, `not` для `typedesc`

```nim
proc `or`*(a, b: typedesc): typedesc
proc `and`*(a, b: typedesc): typedesc
proc `not`*(a: typedesc): typedesc
```

**Что делает.** Строят так называемые "мета-классы типов" — конструкции
вида `int or float`, `Ordinal and not enum`, используемые в ограничениях
типовых параметров генериков (`proc f[T: int or float](x: T)`). Реального
"типа-объединения" в рантайме не появляется — это чисто механизм разрешения
перегрузок на этапе компиляции.

- **Параметры:** `a`, `b: typedesc` — типы, участвующие в объединении,
  пересечении или отрицании ограничения.

```nim
proc describe[T: int or string](x: T): string =
  when T is int:
    "целое: " & $x
  else:
    "строка: " & x

assert describe(5) == "целое: 5"
assert describe("hi") == "строка: hi"
```

### 4. Контейнерные и служебные типы

```nim
type
  Ordinal*[T] {.magic: Ordinal.}
  range*[T] {.magic: "Range".}
  array*[I, T] {.magic: "Array".}
  openArray*[T] {.magic: "OpenArray".}
  varargs*[T] {.magic: "Varargs".}
  seq*[T] {.magic: "Seq".}
  set*[T] {.magic: "Set".}
  UncheckedArray*[T] {.magic: "UncheckedArray".}
  sink*[T] {.magic: "BuiltinType".}
  lent*[T] {.magic: "BuiltinType".}
```

**Что делает.** Это не обычные объявления типов (тела нет — только магия
компилятора), а точки, через которые компилятор регистрирует свои встроенные
контейнеры в системе типов Nim, чтобы к ним можно было применять обычные
правила генериков и разрешения перегрузок.

- `Ordinal[T]` — обобщение над "порядковыми" типами: целые, `bool`, `char`,
  перечисления и их поддиапазоны. Используется как ограничение (`high`, `low`
  принимают `Ordinal`).
- `range[T]` — конструктор типов-диапазонов (`range[0..255]`).
- `array[I, T]` — массив фиксированной длины, индексируемый типом `I`
  (обычно `range` или `Ordinal`).
- `openArray[T]` — "открытый массив": указатель на данные + длина, без
  владения памятью; общий параметр для процедур, принимающих и `seq[T]`,
  и `array`, и срез.
- `varargs[T]` — как `openArray[T]`, но позволяет вызывающей стороне
  передавать аргументы через запятую вместо явного массива.
- `seq[T]` — растущая последовательность, владеющая своей памятью.
- `set[T]` — битовое множество; `T` обязан быть порядковым типом с
  небольшим диапазоном значений.
- `UncheckedArray[T]` — массив без проверки границ; применяется в связке
  с ручным управлением памятью (`ptr UncheckedArray[T]`), когда нужно
  явно отключить проверки ради производительности или совместимости с C.
- `sink[T]` / `lent[T]` — не типы в привычном смысле, а аннотации владения
  для параметров: `sink T` говорит "эта процедура может забрать значение
  себе", `lent T` — "процедура только временно одалживает значение,
  не берёт владение".

```nim
proc sumOpen(a: openArray[int]): int =
  # openArray принимает и array, и seq одинаково
  result = 0
  for x in a:
    result += x

let arr = [1, 2, 3]
let s = @[1, 2, 3]
assert sumOpen(arr) == 6
assert sumOpen(s) == 6

type Digit = range[0..9]
var d: Digit = 7
assert d == 7
```

### 5. `is` и `of`

```nim
proc `is`*[T, S](x: T, y: S): bool
proc `of`*[T, S](x: T, y: typedesc[S]): bool
```

**Что делает.** `is` — проверка соответствия типа выражения заданному типу
или ограничению, полностью вычисляется на этапе компиляции (не тратит время
в рантайме). `of` — проверка того, что объект в динамической иерархии
наследования действительно является экземпляром `S` или его потомком;
в отличие от `is`, для объектных иерархий это рантайм-проверка, так как
факт наследования известен только по данным в объекте.

- **Параметры:**
  - `x: T` — проверяемое значение или выражение.
  - `y: S` / `y: typedesc[S]` — тип или ограничение, с которым сравнивают.

```nim
assert 5 is int
assert "abc" is string
assert not (5 is string)

type
  Animal = ref object of RootObj
  Dog = ref object of Animal

let a: Animal = Dog()
assert a of Dog     # рантайм-проверка динамического типа
assert a of Animal
```

### 6. `sizeof`, `alignof`, `offsetOf`

```nim
proc sizeof*[T](x: T): int
proc sizeof*(x: typedesc): int
proc alignof*[T](x: T): int
proc alignof*(x: typedesc): int
template offsetOf*[T](t: typedesc[T]; member: untyped): int
template offsetOf*[T](value: T; member: untyped): int
```

**Что делает.** `sizeof` возвращает размер значения или типа в байтах —
именно физический размер в памяти, а не логическую ёмкость (`sizeof(seq[int])`
вернёт размер служебной структуры `seq`, а не суммарный размер её элементов).
`alignof` возвращает требуемое выравнивание типа в байтах. `offsetOf`
возвращает смещение конкретного поля внутри объекта/структуры — полезно при
взаимодействии с C-кодом, где важна бинарная раскладка полей.

- **Параметры:**
  - `x: T` / `x: typedesc` — значение или тип, для которого считается размер
    или выравнивание.
  - `t: typedesc[T]` / `value: T` — тип или значение объекта, `member` —
    имя поля (передаётся как `untyped`, то есть без вычисления).

```nim
assert sizeof('A') == 1
assert sizeof(int) == 8      # на 64-битной платформе

type Point = object
  x, y: int32
  active: bool

assert offsetOf(Point, x) == 0
```

### 7. `default`, `zeroDefault`, `reset`

```nim
func zeroDefault*[T](_: typedesc[T]): T
proc default*[T](_: typedesc[T]): T
proc reset*[T](obj: var T)
```

**Что делает.** `zeroDefault(T)` возвращает представление типа `T` из
двоичных нулей, полностью игнорируя пользовательские значения полей по
умолчанию (`= someValue` в определении типа). `default(T)` — то же самое,
но **учитывает** пользовательские значения полей по умолчанию, если они
заданы в определении объекта. `reset(obj)` возвращает переменную `obj` к
её начальному ("нулевому"/дефолтному) состоянию — эквивалент
`obj = default(typeof(obj))`, но без промежуточного создания временного
значения.

- **Параметры:**
  - `_: typedesc[T]` — тип, для которого строится значение по умолчанию;
    параметр не используется, только определяет `T`.
  - `obj: var T` — изменяемая переменная, которую нужно сбросить.

```nim
type Config = object
  retries: int = 3      # пользовательское значение по умолчанию
  verbose: bool

assert default(Config).retries == 3       # учитывает `= 3`
assert zeroDefault(Config).retries == 0   # игнорирует, чистые нули

var counter = 42
reset(counter)
assert counter == 0
```

## II. Порядковые типы, диапазоны и индексация

### 1. `high`, `low`

```nim
proc high*[T: Ordinal|enum|range](x: typedesc[T]): T
proc high*[T](x: openArray[T]): int
proc high*[I, T](x: array[I, T]): I
proc high*(x: string): int
proc low*[T: Ordinal|enum|range](x: typedesc[T]): T
proc low*[T](x: openArray[T]): int
proc low*[I, T](x: array[I, T]): I
proc low*(x: string): int
```

**Что делает.** `high`/`low` возвращают, соответственно, наибольшее и
наименьшее допустимое значение или индекс. Есть два принципиально разных
семейства перегрузок:

1. **По типу** (`high(int)`, `high(SomeEnum)`) — возвращает границу
   диапазона значений самого типа. Например, `high(int)` — это
   `INT_MAX` платформы.
2. **По значению-контейнеру** (`high(myArray)`, `high(mySeq)`, `high(myStr)`)
   — возвращает наибольший допустимый **индекс** этого конкретного
   контейнера, что для `seq`/`string` равно `len(x) - 1`, а не некое
   абсолютное максимальное значение.

Старые перегрузки `high(value: Ordinal)` / `low(value: Ordinal)` (принимающие
конкретное значение порядкового типа, а не сам тип) помечены как
`deprecated` начиная с версии 1.4 — вместо них нужно использовать
`high(typedesc)`/`low(typedesc)`.

Для пустых массивов `high` возвращает `-1` (а `low` — `0`), поэтому
`for i in low(a)..high(a)` безопасно "не выполняется ни разу", а не
уходит в диапазон с отрицательной длиной.

- **Параметры:**
  - `x: typedesc[T]` — тип, для которого берётся граница диапазона
    значений (`T` — порядковый тип, `enum` или `range`).
  - `x: openArray[T]` / `x: array[I, T]` / `x: string` — контейнер, для
    которого берётся граница допустимых индексов.

```nim
assert high(int) == 9223372036854775807
assert low(int) == -9223372036854775808

var s = @[10, 20, 30]
assert low(s) == 0
assert high(s) == 2        # len(s) - 1, не абсолютный максимум

var empty: seq[int] = @[]
assert high(empty) == -1   # пустая последовательность — пустой диапазон

for i in low(s) .. high(s):
  echo s[i]
```

### 2. `Natural`, `Positive`

```nim
type
  Natural* = range[0..high(int)]
  Positive* = range[1..high(int)]
```

**Что делает.** Это не отдельные процедуры, а два готовых типа-диапазона,
построенных поверх `range` и `int`: `Natural` разрешает 0 и положительные
числа, `Positive` — только строго положительные. Используются в первую
очередь для документирования и статической проверки контрактов процедур
(например, `newSeq[T](len: Natural)` — длина не может быть отрицательной,
и это гарантируется типом, а не проверкой в рантайме внутри процедуры).

```nim
proc repeatWord(word: string, times: Positive): string =
  result = ""
  for i in 1 .. times:
    add(result, word)

assert repeatWord("go", 3) == "gogogo"
# repeatWord("go", 0) — не скомпилируется по значению-константе,
# либо упадёт в рантайме при передаче переменной вне диапазона
```

### 3. `..` — конструктор диапазона, `HSlice`/`Slice`

```nim
type
  HSlice*[T, U] = object
    a*: T
    b*: U
  Slice*[T] = HSlice[T, T]

proc `..`*[T, U](a: sink T, b: sink U): HSlice[T, U]
proc `..`*[T](b: sink T): HSlice[int, T]
```

**Что делает.** Оператор `..` строит значение диапазона `[a, b]`
(включительно с обеих сторон) — тип `HSlice[T, U]` хранит просто пару
границ `a`/`b`, никакого разворачивания в последовательность значений при
построении не происходит, это делается лениво при итерации `for i in a..b`.
Однопараметрический вариант `..b` строит диапазон `0..b` — сокращение,
удобное для индексирования с начала контейнера. `Slice[T]` — частный
случай `HSlice`, когда обе границы одного типа.

- **Параметры:**
  - `a: sink T`, `b: sink U` — нижняя и верхняя граница диапазона;
    `sink` означает, что процедура может забрать значение себе, если
    это дешевле копирования.

```nim
let r = 2 .. 5
assert r.a == 2
assert r.b == 5

var s = @[10, 20, 30, 40, 50]
assert s[1 .. 3] == @[20, 30, 40]
assert s[.. 2] == @[10, 20, 30]   # сокращение: 0..2
```

### 4. `contains`/`in`/`notin` для диапазона

```nim
proc contains*[U, V, W](s: HSlice[U, V], value: W): bool
template `in`*(x, y: untyped): untyped = contains(y, x)
template `notin`*(x, y: untyped): untyped = not contains(y, x)
```

**Что делает.** Проверяет, попадает ли `value` в границы диапазона `s`
(включительно). Шаблоны `in`/`notin` — просто синтаксический сахар,
переставляющий местами операнды: `x in y` разворачивается в `contains(y, x)`.
Именно поэтому `in` работает не только с диапазонами, но и с любым типом,
для которого определён `contains` (множества, таблицы, строки и т.д.) —
это общий механизм языка, а не специфика диапазонов.

- **Параметры:**
  - `s: HSlice[U, V]` — диапазон, в котором проверяется принадлежность.
  - `value: W` — проверяемое значение.

```nim
let r = 1 .. 10
assert contains(r, 5)
assert 5 in r
assert 11 notin r
```

### 5. `[]`, `[]=` — базовое индексирование

```nim
proc `[]`*[I: Ordinal; T](a: T; i: I): T
proc `[]=`*[I: Ordinal; T, S](a: T; i: I; x: sink S)
```

**Что делает.** Это компиляторная магия `ArrGet`/`ArrPut` — базовый
механизм чтения и записи по индексу, который стоит за синтаксисом
`a[i]` и `a[i] = x` для `array`, `openArray`, `seq`, `string`, `cstring`
и кортежей. Явно вызывать `` `[]`(a, i) `` вместо `a[i]` смысла нет — это
внутренний уровень, на котором компилятор реализует индексирование; в
пользовательском коде всегда используется квадратно-скобочный синтаксис.

- **Параметры:**
  - `a: T` — индексируемый контейнер.
  - `i: I` — индекс порядкового типа.
  - `x: sink S` — записываемое значение (для `[]=`).

```nim
var arr = [1, 2, 3]
assert arr[0] == 1
arr[1] = 99
assert arr == [1, 99, 3]
```

## III. Память и владение

### 1. `addr`, `unsafeAddr`

```nim
proc `addr`*[T](x: T): ptr T
proc unsafeAddr*[T](x: T): ptr T
```

**Что делает.** `addr(x)` возвращает "сырой" (нетрассируемый GC) указатель
на память, где хранится `x`. Работает для `let`-переменных и параметров —
это специально сделано для удобства взаимодействия с C: библиотеке нужен
указатель, а исходное значение объявлено как неизменяемое. `unsafeAddr` —
устаревший псевдоним `addr`, оставлен только для обратной совместимости.

- **Параметры:** `x: T` — значение, адрес которого берётся; `T` должно
  находиться в адресуемой памяти (не быть, например, временным результатом
  вычисления в регистре).

```nim
var buf: seq[char] = @['a', 'b', 'c']
let p = addr(buf[1])
assert p[] == 'b'
p[] = 'z'
assert buf == @['a', 'z', 'c']
```

---

### 2. `new`, `unsafeNew`

```nim
proc new*[T](a: var ref T, finalizer: proc (x: T) {.nimcall.})
proc unsafeNew*[T](a: var ref T, size: Natural)
```

**Что делает.** Перегрузка `new` с финализатором создаёт объект типа `T`
и записывает в `a` трассируемую (управляемую сборщиком мусора) ссылку на
него; когда сборщик мусора освобождает объект, вызывается `finalizer`.
Важная тонкость: финализатор привязан к **типу**, а не к конкретному
объекту — он будет вызван для каждого объекта данного типа, а не только
для того, что был передан в `new`. `unsafeNew` — низкоуровневый вариант,
позволяющий явно указать размер выделяемой памяти под объект; используется
для оптимизаций, когда стандартный размер по `sizeof(T)` не подходит
(например, объект с "хвостовым" массивом переменной длины).

- **Параметры:**
  - `a: var ref T` — переменная-ссылка, куда будет записан новый объект.
  - `finalizer: proc (x: T) {.nimcall.}` — процедура, вызываемая GC при
    освобождении памяти объекта; не должна сохранять ссылку на `x`.
  - `size: Natural` (для `unsafeNew`) — явный размер выделяемой памяти.

```nim
type Resource = object
  id: int

var r: ref Resource
new(r, proc (x: Resource) = echo "освобождён ресурс ", x.id)
r.id = 7
assert r.id == 7
```

---

### 3. `move`, `wasMoved`, `ensureMove`

```nim
proc move*[T](x: var T): T
proc wasMoved*[T](obj: var T)
proc ensureMove*[T](x: T): T
```

**Что делает.** `move(x)` забирает значение `x` "с концами": возвращает его
как результат, а исходную переменную `x` переводит в исходное (нулевое)
состояние через `wasMoved`, чтобы деструктор `x` при выходе из области
видимости ничего лишний раз не освобождал (оптимально его вообще
выкидывают на этапе компиляции). `wasMoved(obj)` в чистом виде — просто
сброс переменной в двоичный ноль без возврата значения, сигнал компилятору
"эта переменная больше не владеет ресурсом". `ensureMove(x)` — компилируемая
проверка: гарантирует, что `x` действительно перемещается (а не
незаметно копируется) в новое место, иначе — ошибка компиляции.

- **Параметры:**
  - `x: var T` (для `move`) / `obj: var T` (для `wasMoved`) — переменная,
    чьё содержимое забирается или сбрасывается.
  - `x: T` (для `ensureMove`) — выражение, перемещение которого должно
    быть гарантировано компилятором.

```nim
proc buildBigString(): string =
  var x = "Hello"
  let y = ensureMove(x)   # ошибка компиляции, если бы `x` использовался ещё раз
  assert y == "Hello"

buildBigString()

var big = @[1, 2, 3, 4, 5]
let moved = move(big)
assert moved == @[1, 2, 3, 4, 5]
assert big.len == 0        # `big` сброшен после перемещения
```

### 4. Хуки жизненного цикла

```nim
proc `=destroy`*[T](x: var T)
proc `=copy`*[T](dest: var T; src: T)
proc `=sink`*[T](x: var T; y: T)
proc `=dup`*[T](x: T): T
proc `=trace`*[T](x: var T; env: pointer)
```

**Что делает.** Это не процедуры для прямого вызова из пользовательского
кода, а точки расширения системы управления памятью ARC/ORC: компилятор сам
вызывает `=destroy` при выходе переменной из области видимости, `=copy` —
при явном присваивании значения, `=sink` — при перемещении (когда источник
больше не нужен), `=dup` — при необходимости получить независимую копию,
`=trace` — во время работы сборщика мусора для обхода графа ссылок.
Стандартные реализации в `system` — заглушки/поведение по умолчанию;
собственные типы могут **переопределить** их (например, чтобы освобождать
файловый дескриптор в `=destroy`), и тогда компилятор для этого типа
использует пользовательскую версию вместо системной.

- **Параметры:** каждый хук получает переменные/значения того типа, для
  которого переопределяется поведение; писать их вручную для собственных
  типов нужно только тогда, когда стандартного (побайтового/поэлементного)
  поведения недостаточно (владение внешним ресурсом, ручное управление
  памятью и т.п.).

```nim
type FileHandle = object
  fd: int

proc `=destroy`(x: var FileHandle) =
  if x.fd != 0:
    echo "закрываю дескриптор ", x.fd
    x.fd = 0

proc openFake(id: int): FileHandle =
  result = FileHandle(fd: id)

block:
  var f = openFake(42)
  assert f.fd == 42
  # при выходе из блока автоматически вызовется `=destroy`
```

### 5. `isNil`

```nim
proc isNil*[T](x: ref T): bool
proc isNil*[T](x: ptr T): bool
proc isNil*(x: pointer): bool
proc isNil*(x: cstring): bool
proc isNil*[T: proc | iterator {.closure.}](x: T): bool
```

**Что делает.** Проверяет, что ссылочное значение (управляемая ссылка,
сырой указатель, `cstring` или замыкание) не указывает ни на что —
единый способ проверки "пустоты" для всех ссылочных категорий Nim.

- **Параметры:** `x` — проверяемое значение любого из перечисленных
  ссылочных типов.

```nim
var p: ptr int = nil
assert isNil(p)

var r: ref int
assert isNil(r)
new(r)
assert not isNil(r)
```

### 6. `shallowCopy` (устарело)

```nim
proc shallowCopy*[T](x: var T, y: T)
```

**Что делает.** Присваивает `y` в `x`, но для `seq`/`string` (и типов,
содержащих их) — без глубокого копирования данных, в отличие от обычного
`=`. Доступна только при GC-моделях, отличных от ARC/ORC (`arcLikeMem`
выключен), и её использование требует осторожности: изменение через один
из "псевдонимов" после `shallowCopy` отражается и на другом, что нарушает
обычные ожидания от присваивания.

- **Параметры:** `x: var T` — приёмник, `y: T` — источник, чьи внутренние
  данные не копируются, а разделяются с `x`.

```nim
# доступно только без ARC/ORC; в современных проектах на ARC/ORC
# эта процедура попросту недоступна — используйте обычное присваивание
# или `move`, если нужно избежать копирования.
```

## IV. Последовательности: создание и изменение

### 1. `newSeq`, `newSeqOfCap`

```nim
proc newSeq*[T](s: var seq[T], len: Natural)
proc newSeq*[T](len = 0.Natural): seq[T]
proc newSeqOfCap*[T](cap: Natural): seq[T]
```

**Что делает.** Первые две перегрузки создают последовательность заданной
**длины**, заполненную нулевыми значениями элементов — это эффективнее, чем
`@[]` с последующими `len` вызовами `add`, потому что память выделяется
сразу целиком без промежуточных переалокаций. Важная тонкость: после
`newSeq(s, 3)` в `s` уже есть 3 элемента (нулевых), и обращение к ним нужно
делать через `s[i] = ...`, а не `add(s, ...)` — иначе элементы добавятся
*после* трёх существующих. `newSeqOfCap` — противоположный случай: длина
остаётся нулевой, но заранее резервируется память под `cap` элементов,
чтобы последующие вызовы `add` не переалоцировали буфер, пока не превышена
ёмкость.

- **Параметры:**
  - `s: var seq[T]` — последовательность, которая будет (пере)создана.
  - `len: Natural` — желаемая длина новой последовательности.
  - `cap: Natural` — резервируемая ёмкость без изменения длины.

```nim
var names: seq[string]
newSeq(names, 3)
assert len(names) == 3
names[0] = "первое"
names[1] = "второе"
names[2] = "третье"

var buf = newSeqOfCap[int](100)
assert len(buf) == 0
add(buf, 1)
assert len(buf) == 1   # ёмкость 100 уже выделена, переалокаций пока не будет
```

### 2. `len` (семья перегрузок)

```nim
func len*[TOpenArray: openArray|varargs](x: TOpenArray): int
func len*(x: string): int
proc len*(x: cstring): int
func len*(x: (type array)|array): int
func len*[T](x: seq[T]): int
proc len*[U: Ordinal; V: Ordinal](x: HSlice[U, V]): int
```

**Что делает.** Возвращает количество элементов контейнера. Для `array`
это фактически `high(T) - low(T) + 1`, известное на этапе компиляции. Для
`string`/`seq` — текущая длина в элементах (для строки — в байтах, не
в символах Unicode: для этого есть `runeLen` в `std/unicode`). Для
`cstring` — это операция O(n) в рантайме (кроме компиляции в JS, где
строка уже хранит длину), так как сишная строка не хранит длину явно, а
завершается нулевым байтом. Для `HSlice`/диапазона — количество целых
значений, покрываемых диапазоном.

- **Параметры:** `x` — контейнер соответствующего типа.

```nim
assert len("abc") == 3
assert len(@[1, 2, 3]) == 3
assert len([1, 2, 3, 4]) == 4
assert len(1 .. 10) == 10
```

### 3. `add`, `del`, `delete`, `insert`, `pop`

```nim
proc add*(x: var string, y: char)
proc add*(x: var string, y: string)
proc del*[T](x: var seq[T], i: Natural)
proc insert*[T](x: var seq[T], item: sink T, i = 0.Natural)
proc delete*[T](x: var seq[T], i: Natural)
proc pop*[T](s: var seq[T]): T
```

**Что делает.** `add` дописывает элемент/строку в конец. `del(x, i)`
удаляет элемент по индексу `i`, **не сохраняя порядок**: элемент
"с конца" последовательности перемещается на место удалённого — это O(1)
вместо O(n), но порядок оставшихся элементов меняется. `delete(x, i)` —
наоборот, удаляет с сохранением порядка, сдвигая все последующие элементы
на одну позицию влево — это O(n), зато список остаётся отсортированным
так же, как был. `insert(x, item, i)` вставляет элемент на позицию `i`,
сдвигая последующие элементы вправо (по умолчанию `i = 0`, то есть вставка
в начало). `pop(s)` удаляет и возвращает **последний** элемент
последовательности — O(1), поскольку не требует сдвига остальных.

- **Параметры:**
  - `x: var string` / `x: var seq[T]` — изменяемый контейнер.
  - `y: char` / `y: string` — добавляемые данные.
  - `i: Natural` — индекс элемента.
  - `item: sink T` — вставляемый элемент.
  - `s: var seq[T]` — последовательность, из которой извлекается последний
    элемент.

```nim
var s = @[1, 2, 3, 4, 5]

del(s, 1)
assert s == @[1, 5, 3, 4]        # 2 удалён, 5 "с конца" встал на его место

var ordered = @[1, 2, 3, 4, 5]
delete(ordered, 1)
assert ordered == @[1, 3, 4, 5]  # порядок сохранён, сдвиг

insert(ordered, 99, 1)
assert ordered == @[1, 99, 3, 4, 5]

var stack = @[1, 2, 3]
let top = pop(stack)
assert top == 3
assert stack == @[1, 2]
```

### 4. `setLen`, `setLenUninit`

```nim
proc setLen*[T](s: var seq[T], newlen: Natural)
proc setLen*(s: var string, newlen: Natural)
func setLenUninit*(s: var string, newlen: Natural)
```

**Что делает.** Изменяет длину `s` на `newlen`: при увеличении — новые
элементы заполняются нулевым значением типа `T` (или нулевыми байтами для
строки), при уменьшении — лишние элементы с конца отбрасываются (без
освобождения самой выделенной памяти — capacity остаётся прежней).
`setLenUninit` — вариант для строк, который **не** обнуляет новые байты
при увеличении длины: он быстрее, но требует, чтобы вызывающий код сам
заполнил новые байты перед чтением — иначе там будет "мусор" из памяти.

- **Параметры:** `s` — изменяемый `seq`/`string`, `newlen: Natural` —
  новая длина.

```nim
var s = @[1, 2, 3]
setLen(s, 5)
assert s == @[1, 2, 3, 0, 0]     # новые элементы — нули

setLen(s, 2)
assert s == @[1, 2]              # лишнее отброшено

var str = "abc"
setLen(str, 5)
assert str[0..2] == "abc"        # первые 3 байта не тронуты
```

### 5. `find`, `contains` для `openArray`

```nim
proc find*[T, S](a: T, item: S): int
proc contains*[T](a: openArray[T], item: T): bool
```

**Что делает.** `find` возвращает индекс первого вхождения `item` в `a`
или `-1`, если элемент не найден — линейный поиск O(n). `contains`
построен поверх `find` и просто проверяет, что результат неотрицательный;
именно `contains` даёт возможность писать `item in a` для последовательностей
благодаря общему механизму `in` → `contains`.

- **Параметры:** `a` — контейнер для поиска, `item` — искомое значение.

```nim
let a = @[10, 20, 30]
assert find(a, 20) == 1
assert find(a, 99) == -1
assert contains(a, 30)
assert 99 notin a
```

---

### 6. `@` — массив в seq

```nim
proc `@`*[IDX, T](a: sink array[IDX, T]): seq[T]
```

**Что делает.** Префиксный оператор `@` конвертирует значение фиксированного
массива в динамическую последовательность — это ровно та операция, что
стоит за привычным литералом `@[1, 2, 3]` (компилятор сначала строит
`array`, затем применяет `@`).

- **Параметры:** `a: sink array[IDX, T]` — исходный массив; `sink`
  позволяет переиспользовать память массива вместо копирования, если
  массив больше не нужен вызывающей стороне.

```nim
let arr = [1, 2, 3]
let s = `@`(arr)
assert s == @[1, 2, 3]
assert s is seq[int]
```

---

### 7. `swap`

```nim
proc swap*[T](a, b: var T)
```

**Что делает.** Меняет местами содержимое `a` и `b` без промежуточного
копирования "по значению" в третью переменную — реализовано как обмен
внутренним представлением (для `seq`/`string`/`ref` это буквально обмен
указателями и длинами, O(1), а не поэлементное копирование).

- **Параметры:** `a`, `b: var T` — две изменяемые переменные одного типа.

```nim
var x = @[1, 2, 3]
var y = @[9, 8]
swap(x, y)
assert x == @[9, 8]
assert y == @[1, 2, 3]
```

## V. Строки

### 1. `len`, `substr`

```nim
func len*(x: string): int
proc substr*(s: string; first, last: int): string
proc substr*(s: string, first = 0): string
```

**Что делает.** `len` — длина строки в байтах (см. также раздел IV.2).
`substr` возвращает **новую** строку — копию среза от `first` до `last`
включительно (или до конца строки, если `last` не задан). Выход индексов
за границы обрабатывается мягко, без исключений: индекс `first` больше
длины строки даёт пустую строку, а отрицательный `first` тихо
"прижимается" к 0 — то есть `substr` никогда не бросает исключение из-за
некорректных границ, в отличие от оператора `[]` со срезом.

- **Параметры:**
  - `s: string` — исходная строка.
  - `first: int` — начальный индекс среза (по умолчанию 0).
  - `last: int` — конечный индекс среза включительно (по умолчанию —
    конец строки).

```nim
let a = "abcdefgh"
assert substr(a, 2) == "cdefgh"     # от индекса 2 до конца
assert substr(a, 100) == ""         # `first` вне границ — пусто, без ошибки
assert substr(a, -1) == "abcdefgh"  # отрицательный `first` прижат к 0
assert substr(a, 2, 4) == "cde"
```

### 2. `&`, `add`, `&=` — конкатенация

```nim
proc `&`*(x: string, y: char): string
proc `&`*(x, y: char): string
proc `&`*(x, y: string): string
proc `&`*(x: char, y: string): string
proc add*(x: var string, y: char)
proc add*(x: var string, y: string)
proc `&=`*(x: var string, y: string)
```

**Что делает.** `&` строит **новую** строку из двух операндов (строк
и/или символов) — используется, когда исходные строки не нужно
изменять. `add` дописывает символ или строку в конец существующей
строки **на месте**, без создания новой — эффективнее, чем
`s = s & extra`, поскольку переиспользует уже выделенный буфер, если
ёмкости достаточно. `&=` — оператор "конкатенация на месте", по сути
синоним `add`, но в форме составного присваивания.

- **Параметры:** `x`, `y` — строки/символы, которые объединяются;
  для `add`/`&=` `x: var string` изменяется на месте.

```nim
assert "abc" & "def" == "abcdef"
assert 'a' & "bc" == "abc"

var s = "Hello"
add(s, ", ")
add(s, "мир!")
assert s == "Hello, мир!"

var t = "foo"
`&=`(t, "bar")
assert t == "foobar"
```

---

### 3. `newString`, `newStringOfCap`

```nim
proc newString*(len: Natural): string
proc newStringOfCap*(cap: Natural): string
```

**Что делает.** `newString(len)` создаёт строку заданной длины,
заполненную нулевыми байтами — аналог `newSeq` для строк. `newStringOfCap`
создаёт строку нулевой длины, но с зарезервированной ёмкостью буфера —
чтобы последующие вызовы `add` не приводили к переалокациям, пока не
превышена ёмкость.

- **Параметры:** `len`/`cap: Natural` — длина или резервируемая ёмкость.

```nim
var s = newString(5)
assert len(s) == 5

var builder = newStringOfCap(256)
assert len(builder) == 0
add(builder, "начало строки")
```

### 4. `addEscapedChar`, `addQuoted`

```nim
proc addEscapedChar*(s: var string, c: char)
proc addQuoted*[T](s: var string, x: T)
```

**Что делает.** `addEscapedChar` дописывает символ `c` в `s`, экранируя
непечатаемые/специальные символы (перевод строки становится `\n`,
обратный слэш — `\\` и т.д.) — тот же принцип, что используется при
генерации представления `repr`. `addQuoted` — более общая процедура:
дописывает "закавыченное" (в стиле литерала Nim) представление значения
`x` произвольного типа `T`, используя `addEscapedChar` внутри для
символьных/строковых данных.

- **Параметры:** `s: var string` — накопительный буфер, `c: char` —
  символ для экранирования, `x: T` — произвольное значение для
  закавыченного представления.

```nim
var s = ""
addEscapedChar(s, '\n')
assert s == "\\n"

var buf = ""
addQuoted(buf, "hi\nthere")
assert buf == "\"hi\\nthere\""
```

### 5. `toOpenArray`, `toOpenArrayByte`, `toOpenArrayChar`

```nim
proc toOpenArray*[T](x: seq[T]; first, last: int): openArray[T]
proc toOpenArray*(x: string; first, last: int): openArray[char]
proc toOpenArrayByte*(x: string; first, last: int): openArray[byte]
proc toOpenArrayChar*(x: openArray[byte]; first, last: int): openArray[char]
```

**Что делает.** Строит **невладеющий срез** (`view`) исходных данных от
`first` до `last` включительно — в отличие от `substr`/`[]` со срезом,
здесь **не происходит копирования**: `openArray` — это просто указатель
плюс длина поверх памяти исходного контейнера. Это дешевле, чем
передавать копию среза, когда данные нужны только для чтения внутри
вызываемой процедуры. `toOpenArrayByte`/`toOpenArrayChar` дают тот же
срез, но трактуют байты как `byte`/`char` соответственно — удобно при
работе с бинарными данными поверх строк.

- **Параметры:** `x` — исходные данные, `first`, `last: int` — границы
  среза включительно.

```nim
proc sumBytes(a: openArray[byte]): int =
  result = 0
  for b in a:
    result += int(b)

let data = "abcde"
let view = toOpenArrayByte(data, 1, 3)
assert sumBytes(view) == int('b') + int('c') + int('d')
```

## VI. Числа

### 1. `toFloat`, `toBiggestFloat`, `toInt`, `toBiggestInt`

```nim
proc toFloat*(i: int): float
proc toBiggestFloat*(i: BiggestInt): BiggestFloat
proc toInt*(f: float): int
proc toBiggestInt*(f: BiggestFloat): BiggestInt
```

**Что делает.** Явные преобразования между целыми и числами с плавающей
точкой (в дополнение к обычным конверсиям вида `float(i)`/`int(f)`).
`toInt`/`toBiggestInt` округляют дробную часть к ближайшему целому
(округление, а не отбрасывание дробной части, как это делает прямое
приведение типа `int(f)`).

- **Параметры:** `i` — целое число, `f` — число с плавающей точкой.

```nim
assert toFloat(5) == 5.0
assert toInt(2.7) == 3      # округление, а не усечение
assert toInt(2.4) == 2
```

### 2. `/` для `int`

```nim
proc `/`*(x, y: int): float
```

**Что делает.** Оператор деления `int / int` возвращает `float`, а не
целочисленное деление — сделано так, чтобы `5 / 2` давало `2.5`, а не `2`,
как было бы при обычной семантике целочисленного деления в других языках.
Для целочисленного деления в Nim есть отдельные операторы `div`/`mod`.

- **Параметры:** `x`, `y: int` — делимое и делитель.

```nim
assert `/`(5, 2) == 2.5
assert `/`(4, 2) == 2.0
```

### 3. `abs`

```nim
proc abs*[T: float64 | float32](x: T): T
func abs*(x: int): int
func abs*(x: int8): int8
func abs*(x: int16): int16
func abs*(x: int32): int32
func abs*(x: int64): int64
```

**Что делает.** Возвращает модуль (абсолютное значение) числа — отдельные
перегрузки под каждый целочисленный тип нужны, чтобы результат оставался
того же типа, что и вход (не расширяясь неявно до `int64`).

- **Параметры:** `x` — число любого из поддерживаемых числовых типов.

```nim
assert abs(-5) == 5
assert abs(5) == 5
assert abs(-3.14) == 3.14
```

---

### 4. `ord`, `chr`

```nim
func ord*[T: Ordinal|enum](x: T): int
func chr*(u: range[0..255]): char
```

**Что делает.** `ord` возвращает целочисленное порядковое значение
порядкового типа или перечисления (для `char` — код символа, для `enum` —
номер варианта). `chr` — обратная операция: строит символ по коду
`0..255`.

- **Параметры:** `x` — значение порядкового типа, `u` — код символа в
  диапазоне `0..255`.

```nim
assert ord('A') == 65
assert chr(65) == 'A'

type Color = enum red, green, blue
assert ord(green) == 1
```

---

### 5. `cmp`

```nim
proc cmp*[T](x, y: T): int
proc cmp*(x, y: string): int
```

**Что делает.** Универсальная трёхзначная функция сравнения: возвращает
отрицательное число, если `x < y`, ноль при равенстве, положительное —
если `x > y`. Используется как базовый строительный блок для сортировок и
других алгоритмов, которым нужен единый компаратор, а не отдельно `<` и
`==`. Перегрузка для `string` — отдельная, поскольку сравнение строк
обычно делается через специализированный посимвольный алгоритм, а не через
обобщённую `<`/`==` реализацию для generic `T`.

- **Параметры:** `x`, `y: T` — два сравниваемых значения одного типа.

```nim
assert cmp(1, 2) < 0
assert cmp(2, 2) == 0
assert cmp(3, 2) > 0
assert cmp("abc", "abd") < 0
```

## VII. Сравнение кортежей и объектов

### 1. `==`, `<=`, `<` для `tuple`/`object`

```nim
proc `==`*[T: tuple|object](x, y: T): bool
proc `<=`*[T: tuple](x, y: T): bool
proc `<`*[T: tuple](x, y: T): bool
```

**Что делает.** Стандартная (генерируемая компилятором для любого
`tuple`/`object`, если явно не переопределена) реализация сравнения:
`==` сравнивает объекты/кортежи **поэлементно, по всем полям**. Для
кортежей `<=`/`<` сравнивают поля **лексикографически** — как строки
сравниваются посимвольно: первое несовпадающее поле определяет результат.
Заметьте, что для `object` операторы `<`/`<=` **не** генерируются
автоматически — они определены только для `tuple`, поскольку у объектов
нет единого "естественного" порядка полей, подразумеваемого пользователем.

- **Параметры:** `x`, `y: T` — два кортежа или объекта одного типа.

```nim
assert (1, "a") == (1, "a")
assert (1, "a") != (1, "b")

assert (1, 2) < (1, 3)     # первое поле равно, решает второе
assert (1, 5) < (2, 0)     # первое поле уже решает всё
```

## VIII. Исключения и завершение программы

### 1. Иерархия исключений

```nim
type
  Exception* = object of RootObj
    parent*: ref Exception
    name*: cstring
    msg*: string
    trace*: seq[StackTraceEntry]
  Defect* = object of Exception
  CatchableError* = object of Exception
```

**Что делает.** Корень исключений в Nim — `Exception`. От него наследуются
две ветви с разным смыслом: `Defect` — для ошибок, которые сигнализируют
о программных багах и, как правило, не предназначены для перехвата в
обычном потоке управления (несовпадение индексов, деление на ноль и
т.п. — в релизной сборке такие ошибки могут быть скомпилированы как
неперехватываемые и вести к аварийному завершению); `CatchableError` —
базовый класс для исключений, которые ожидаемо перехватываются в
пользовательском коде (`IOError`, `ValueError` и т.д. из других модулей
наследуются именно от неё). Поле `trace` хранит стек вызовов на момент
создания исключения — используется при выводе сообщения об
необработанном исключении.

- **Поля:** `parent` — исключение, обёрнутое текущим (стек причин),
  `name` — имя типа исключения (заполняется автоматически при `raise`),
  `msg` — текст сообщения, `trace` — снимок стека вызовов.

```nim
type MyError = object of CatchableError
  code: int

try:
  raise newException(MyError, "что-то пошло не так")
except MyError as e:
  assert e.msg == "что-то пошло не так"
  assert e.name == "MyError"
```

---

### 2. `newException`

```nim
template newException*(exceptn: typedesc, message: string): untyped
```

**Что делает.** Создаёт и возвращает новый экземпляр исключения заданного
типа с уже заполненным полем `msg` — сокращение вместо ручного
`var e = new(exceptn); e.msg = message`.

- **Параметры:** `exceptn: typedesc` — тип исключения (потомок
  `Exception`), `message: string` — текст сообщения.

```nim
type ConfigError = object of ValueError

proc loadConfig(path: string) =
  if len(path) == 0:
    raise newException(ConfigError, "путь к конфигу пуст")

try:
  loadConfig("")
except ConfigError as e:
  assert e.msg == "путь к конфигу пуст"
```

### 3. `quit`

```nim
proc quit*(errormsg: string, errorcode = QuitFailure) {.noreturn.}
```

**Что делает.** Печатает `errormsg` и немедленно завершает программу с
кодом возврата `errorcode` — в отличие от исключения, `quit` не
разворачивает стек и не вызывает деструкторы объектов, ещё живущих на
момент вызова (это осознанный компромисс: аварийное завершение должно
быть быстрым и безусловным).

- **Параметры:** `errormsg: string` — сообщение, выводимое перед выходом,
  `errorcode` — код возврата процесса (по умолчанию `QuitFailure`).

```nim
# quit("критическая ошибка конфигурации") — завершит процесс немедленно;
# в примерах справочника не вызывается, чтобы не прерывать проверку assert
```

---

### 4. `instantiationInfo`

```nim
proc instantiationInfo*(index = -1, fullPaths = false): tuple[
  filename: string, line: int, column: int]
```

**Что делает.** Возвращает информацию о месте вызова (файл, строка,
колонка) — но не текущей процедуры, а места, откуда была инстанцирована
конструкция, вызвавшая её (используется преимущественно внутри шаблонов и
макросов, чтобы сообщения об ошибках указывали на код пользователя,
вызвавшего шаблон, а не на тело самого шаблона).

- **Параметры:** `index` — насколько "вверх" по стеку инстанцирования
  подниматься (`-1` — непосредственный вызывающий), `fullPaths` — выводить
  ли полный путь к файлу.

```nim
template checkPositive(x: int) =
  let info = instantiationInfo()
  if x <= 0:
    echo "проверка на строке ", info.line, " провалена"

# checkPositive(-1) укажет строку вызова `checkPositive`, а не строку
# внутри тела самого шаблона
```

### 5. `procCall`

```nim
proc procCall*(x: untyped) {.compileTime.}
```

**Что делает.** Внутри переопределённого метода вызывает версию метода из
родительского типа — аналог `super()` в объектно-ориентированных языках.
Работает только для процедур, использующих механизм диспетчеризации по
типу (`method`), не для обычных `proc`.

- **Параметры:** `x: untyped` — выражение вызова метода родителя
  (например, `procCall(baseMethod(self))`).

```nim
type
  Animal = ref object of RootObj
  Dog = ref object of Animal

method speak(a: Animal): string {.base.} = "..."
method speak(d: Dog): string =
  # вызываем реализацию из Animal и дополняем её
  procCall(speak(Animal(d))) & " Гав!"
```

## IX. Вывод и отладка

### 1. `echo`, `debugEcho`

```nim
proc echo*(x: varargs[typed, `$`]) {.magic: "Echo", gcsafe, sideEffect.}
proc debugEcho*(x: varargs[typed, `$`]) {.magic: "Echo", noSideEffect.}
```

**Что делает.** `echo` печатает в стандартный вывод строковое
представление (`$`) каждого аргумента, разделённых пробелами, с переводом
строки в конце. `debugEcho` делает то же самое, но помечен как
`noSideEffect` — это позволяет вставлять отладочный вывод даже в места,
формально запрещающие побочные эффекты (например, внутри `func`), не меняя
сигнатуру эффектов основной процедуры; предназначена исключительно для
временной отладки, не для использования в продакшен-коде.

- **Параметры:** `x: varargs[typed, `$`]` — произвольное число значений
  любых типов, для которых определено преобразование `$` в строку.

```nim
echo "Значение x = ", 42, ", готово: ", true
```

---

### 2. `repr` для `HSlice`

```nim
proc repr*[T, U](x: HSlice[T, U]): string
```

**Что делает.** Строит подробное строковое представление диапазона в виде
`a..b`, используя `repr` для каждой границы — отличается от `$` тем, что
`repr` в общем случае показывает внутреннюю структуру значения подробнее,
чем "человекочитаемое" представление `$`.

- **Параметры:** `x: HSlice[T, U]` — диапазон, который нужно представить
  строкой.

```nim
let r = 1 .. 5
assert repr(r) == "1 .. 5"
```

---

### 3. `locals`

```nim
proc locals*(): RootObj {.magic: "Plugin".}
```

**Что делает.** Возвращает псевдо-объект, содержащий все локальные
переменные, видимые в точке вызова — служебная возможность для
отладочных инструментов и REPL; не предназначена для использования в
обычном прикладном коде из-за нестабильного и специфичного для
компилятора представления результата.

```nim
proc demo() =
  let a = 1
  let b = "two"
  let vars = locals()
  # `vars` содержит `a` и `b` в виде, пригодном для отладочной печати
```

## X. Прочие утилиты

### 1. `likely`, `unlikely`

```nim
template likely*(val: bool): bool
template unlikely*(val: bool): bool
```

**Что делает.** Подсказки компилятору/процессору о вероятном исходе
условия — используются для расстановки "холодных" веток кода (обработка
ошибок, редкие случаи) так, чтобы основной, "горячий" путь исполнения
предсказывался процессором лучше. Семантически `likely(val)` и `val`
эквивалентны — это влияет только на генерируемый машинный код, не на
логику программы.

- **Параметры:** `val: bool` — условие, для которого даётся подсказка о
  вероятности.

```nim
proc process(x: int): string =
  if unlikely(x < 0):
    return "ошибка: отрицательное значение"
  "ok: " & $x

assert process(5) == "ok: 5"
```

---

### 2. `once`, `closureScope`, `disarm`

```nim
template once*(body: untyped): untyped
template closureScope*(body: untyped): untyped
template disarm*(x: typed)
```

**Что делает.** `once(body)` гарантирует, что `body` будет выполнен ровно
один раз за всё время работы программы, даже если обрамляющий код
(например, тело цикла) выполняется многократно — реализовано через
скрытый статический флаг "уже выполнялось". `closureScope(body)`
оборачивает `body` в отдельную область видимости для замыканий — типичная
проблема без него: замыкания, создаваемые в цикле, все "видят" одну и ту
же переменную цикла на момент её финального значения; `closureScope`
даёт каждой итерации свою копию нужных переменных. `disarm(x)` "обезвреживает"
объект перед его ручным освобождением, чтобы деструктор впоследствии не
попытался освободить его повторно.

- **Параметры:** `body: untyped` — блок кода, `x: typed` — переменная,
  которую нужно обезвредить перед освобождением.

```nim
for i in 1 .. 3:
  once:
    echo "это выведется только один раз, при i == 1"

var closures: seq[proc(): int]
for i in 0 .. 2:
  closureScope:
    let captured = i
    add(closures, proc(): int = captured)

assert closures[0]() == 0
assert closures[1]() == 1
assert closures[2]() == 2
```

---

### 3. `finished`

```nim
proc finished*[T: iterator {.closure.}](x: T): bool
```

**Что делает.** Проверяет, завершил ли итератор-замыкание (`closure
iterator`) свою работу — то есть исчерпаны ли из него значения. Полезно
при ручном управлении итераторами (не через `for`), когда нужно явно
проверять, стоит ли запрашивать следующее значение.

- **Параметры:** `x` — итератор-замыкание.

```nim
iterator countTo(n: int): int {.closure.} =
  for i in 1 .. n:
    yield i

var it = countTo
while not finished(it):
  let v = it()
  if not finished(it):
    echo v
```

---

### 4. `arrayWith`, `arrayWithDefault`

```nim
proc arrayWith*[T](y: T, size: static int): array[size, T]
proc arrayWithDefault*[T](size: static int): array[size, T]
```

**Что делает.** `arrayWith(y, size)` строит массив фиксированного размера
`size`, заполненный `size` копиями значения `y` (каждый элемент получает
собственную независимую копию через `=dup`, а не одну и ту же ссылку).
`arrayWithDefault(size)` строит массив того же размера, заполненный
`default(T)` для каждого элемента.

- **Параметры:** `y: T` — значение-заполнитель, `size: static int` —
  размер массива, известный на этапе компиляции.

```nim
let filled = arrayWith(7, 4)
assert filled == [7, 7, 7, 7]

let zeros = arrayWithDefault[int](3)
assert zeros == [0, 0, 0]
```

## XI. Практические рецепты

### 1. Безопасное построение seq фиксированного размера

Если заранее известна длина результата, `newSeq` + запись по индексу
эффективнее многократного `add`, а `newSeqOfCap` — если известна лишь
верхняя оценка размера:

```nim
proc squares(n: Natural): seq[int] =
  newSeq(result, n)
  for i in 0 ..< n:
    result[i] = i * i

assert squares(5) == @[0, 1, 4, 9, 16]

proc collectEven(upTo: int): seq[int] =
  result = newSeqOfCap[int](upTo div 2 + 1)
  for i in 0 .. upTo:
    if i mod 2 == 0:
      add(result, i)

assert collectEven(10) == @[0, 2, 4, 6, 8, 10]
```

---

### 2. Удаление элемента без сохранения порядка vs с сохранением порядка

```nim
proc removeFast[T](s: var seq[T], i: Natural) =
  # порядок неважен — используем O(1) удаление
  del(s, i)

proc removeStable[T](s: var seq[T], i: Natural) =
  # порядок важен — используем O(n) удаление со сдвигом
  delete(s, i)

var unordered = @[1, 2, 3, 4, 5]
removeFast(unordered, 1)
assert unordered == @[1, 5, 3, 4]

var ordered = @[1, 2, 3, 4, 5]
removeStable(ordered, 1)
assert ordered == @[1, 3, 4, 5]
```

### 3. Свой тип исключения с контекстом

Комбинация иерархии исключений и `newException` для передачи
дополнительного контекста ошибки, а не только текста сообщения:

```nim
type
  ParseError = object of CatchableError
    lineNumber: int

proc parseLine(line: string, num: int) =
  if len(line) == 0:
    var e = newException(ParseError, "пустая строка ввода")
    e.lineNumber = num
    raise e

try:
  parseLine("", 42)
except ParseError as e:
  assert e.lineNumber == 42
  assert e.msg == "пустая строка ввода"
```

---

### 4. Перемещение вместо копирования в цикле накопления

Когда промежуточные большие значения (строки, `seq`) нужно перекладывать
из одной переменной в другую без лишнего копирования:

```nim
proc drainInto(source: var seq[string], sink_: var seq[string]) =
  while len(source) > 0:
    let item = move(pop(source))
    add(sink_, item)

var src = @["a", "b", "c"]
var dst: seq[string] = @[]
drainInto(src, dst)
assert dst == @["c", "b", "a"]
assert len(src) == 0
```

---

### 5. Работа со срезом строки без лишних аллокаций

Когда нужно только прочитать часть строки (например, передать в
процедуру, суммирующую байты), `toOpenArrayByte` избавляет от копирования,
которое сделал бы `substr`:

```nim
proc checksum(data: openArray[byte]): int =
  result = 0
  for b in data:
    result += int(b)

let payload = "header:body:footer"
let bodyView = toOpenArrayByte(payload, 7, 10)  # "body" без копирования
assert checksum(bodyView) == checksum(@[byte('b'), byte('o'), byte('d'), byte('y')])
```

## XIII. Сводка: какую процедуру выбрать

- Нужно узнать длину контейнера → `len(x)`.
- Нужны границы для ручного цикла `for i in ... ` → `low(x) .. high(x)`,
  а не `0 ..< len(x)` — так корректно работает и для нестандартных
  индексных типов массива.
- Нужно построить последовательность известной длины → `newSeq[T](n)`,
  затем присваивание по индексу — быстрее, чем `add` в цикле.
- Нужно только зарезервировать память под будущий рост через `add` →
  `newSeqOfCap[T](cap)`.
- Нужно удалить элемент и порядок не важен → `del(x, i)` (O(1)).
- Нужно удалить элемент, порядок важен → `delete(x, i)` (O(n)).
- Нужно прочитать кусок строки, не копируя его → `toOpenArray`/
  `toOpenArrayByte`, а не `substr`.
- Нужно получить копию куска строки, которую можно свободно менять →
  `substr(s, first, last)`.
- Нужно передать большое значение дальше и исходная переменная больше не
  нужна → `move(x)`, а не обычное присваивание.
- Нужно проверить тип на этапе компиляции (обычные типы, generic-код) →
  `x is T`.
- Нужно проверить динамический тип объекта в иерархии наследования →
  `x of T`.
- Нужно значение "по умолчанию" с учётом пользовательских `= value` в
  определении объекта → `default(T)`; если нужны именно двоичные нули,
  игнорируя эти значения → `zeroDefault(T)`.
- Нужно своё исключение с дополнительными полями → объявить тип-потомок
  `CatchableError`, создавать через `newException`, при необходимости
  дозаполнять поля до `raise`.
- Нужно вывести значение для отладки, не нарушая `noSideEffect` окружающей
  процедуры → `debugEcho`, а не `echo`.
