
# 📘 Документация пакета `db_mysql`

## 🔍 Введение
`db_mysql` — высокоуровневая обёртка над нативной библиотекой `libmysqlclient` для СУБД MySQL в языке Nim. Модуль предоставляет унифицированный API для работы с реляционными данными, поддерживает параметризованные запросы через маркер `?`, безопасные и быстрые итераторы, а также автоматическое приведение всех значений к строковому представлению.

> **Примечание:** Модуль не реализует ORM-механизмы. Для сохранения максимальной близости к C-API MySQL и упрощения сериализации, все строки возвращаются как `seq[string]`, а значения `NULL` преобразуются в пустые строки `""`. В отличие от `db_postgres` и `db_sqlite`, данный модуль не поддерживает подготовленные выражения (`SqlPrepared`), полагаясь на клиентскую параметризацию.

## 📦 Установка
Для использования модуля необходимо установить пакет `db_connector`:
```bash
nimble install db_connector
```

## 🧱 Основные типы данных

| Тип | Описание | Назначение |
|-----|----------|------------|
| `DbConn` | `distinct PMySQL` | Дескриптор активного соединения с сервером MySQL. |
| `Row` | `seq[string]` | Представляет одну строку результата запроса. Все значения приводятся к строковому типу. |
| `InstantRow` | `object { row: cstringArray, len: int }` | Лёгкий дескриптор, содержащий указатель на массив строк результата. Позволяет извлекать столбцы «по требованию» без аллокаций. |
| `DbType` | Структура | Содержит метаданные типа столбца: `kind` (категория), `size`, `name` (имя типа), `notNull`, `primaryKey`, `tableName` и др. |
| `DbColumns` | `seq[DbType]` | Коллекция метаданных всех столбцов, возвращаемых запросом. |

## ⚙️ Базовый API

### 🔌 Управление соединением
- `open(connection, user, password, database): DbConn` — открывает соединение. Поддерживает указание порта через синтаксис `host:port` в параметре `connection`.
- `close(db: DbConn)` — безопасно закрывает соединение и освобождает ресурсы `libmysqlclient`.
- `setEncoding(connection: DbConn, encoding: string): bool` — устанавливает кодировку клиентского соединения.

### 📝 Выполнение запросов
- `exec(db, query, args)` — выполняет запрос. При ошибке выбрасывает `DbError`.
- `tryExec(db, query, args): bool` — выполняет запрос, возвращает `true` при успехе, `false` при ошибке.
- `execAffectedRows(db, query, args): int64` — выполняет запрос и возвращает количество изменённых строк (для `UPDATE`/`DELETE`).

### 🔍 Выборка данных
- `fastRows(db, query, args): iterator Row` — быстрый итератор. **Внимание:** прерывание цикла (`break`) приведёт к ошибке `Commands out of sync` при следующем запросе.
- `rows(db, query, args): iterator Row` — безопасный итератор (загружает все строки в память перед итерацией, позволяет использовать `break`).
- `instantRows(db, query, args): iterator InstantRow` — возвращает дескриптор строки для ленивого доступа.
- `instantRows(db, columns, query, args): iterator InstantRow` — дополнительно заполняет `columns` метаданными о типах столбцов.
- `getRow(db, query, args): Row` — возвращает первую строку результата.
- `getAllRows(db, query, args): seq[Row]` — возвращает все строки в виде последовательности.
- `getValue(db, query, args): string` — возвращает значение первого столбца первой строки.

### 📊 Вставка и возврат идентификаторов
- `tryInsertId(db, query, args): int64` — выполняет `INSERT` и возвращает `AUTO_INCREMENT` ID через вызов `LAST_INSERT_ID()`. Возвращает `-1` при ошибке.
- `insertId(db, query, args): int64` — аналогично, но выбрасывает `DbError` при ошибке.
- `tryInsert(db, query, pkName, args): int64` — псевдоним для `tryInsertId`. Параметр `pkName` игнорируется, но сохранён для совместимости с общим API `db_common`.
- `insert(db, query, pkName, args): int64` — псевдоним для `insertId`.

### 🛡 Утилиты
- `dbQuote(s: string): string` — экранирует специальные символы для MySQL (`'`, `"`, `\`, `\0`, `\b`, `\t`, `\n`, `\r`, `\x1a`).
- `dbError(db: DbConn)` — явно вызывает исключение с текстом ошибки от `mysql.error()`.

## 💻 Примеры использования

### 1. Подключение, создание таблицы и вставка данных
```nim
import
  db_connector/db_mysql
  std/math
  std/assertions

let
  # Открываем соединение к локальному серверу MySQL.
  # Параметры: host[:port], user, password, database name.
  db = open("localhost", "root", "secret", "store_db")

# Удаляем таблицу, если она существует, для чистоты эксперимента
exec(db, sql"DROP TABLE IF EXISTS products")

# Создаём таблицу с типичной структурой интернет-магазина
exec(db, sql"""
  CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(100) NOT NULL,
    price DECIMAL(10, 2),
    stock_count INT DEFAULT 0
  )
""")

# Вставка одной записи с автоподстановкой параметров через ?
exec(db, sql"INSERT INTO products (title, price, stock_count) VALUES (?, ?, ?)",
     "Widget Alpha", 19.99, 100)

# Пакетная вставка внутри транзакции для повышения производительности
exec(db, sql"START TRANSACTION")
for i in 1 .. 5:
  let
    prodName = "Item_" & $i
    prodPrice = sqrt(float(i)) * 10.0
    prodStock = i * 20
  exec(db, sql"INSERT INTO products (title, price, stock_count) VALUES (?, ?, ?)",
       prodName, prodPrice, prodStock)
exec(db, sql"COMMIT")

# Получаем ID последней вставленной строки.
# В MySQL модуль использует системную функцию LAST_INSERT_ID(),
# поэтому автоматическое добавление RETURNING не требуется.
let
  lastId = tryInsertId(db, sql"INSERT INTO products (title, price, stock_count) VALUES (?, ?, ?)",
                       "Widget Beta", 29.50, 45)

# Проверяем, что вставка прошла успешно
assert(lastId > 0, "Ошибка вставки: возвращён недопустимый ID")

# Закрываем соединение и освобождаем ресурсы libmysqlclient
close(db)
```

### 2. Выборка данных, `InstantRow` и метаданные столбцов
```nim
import
  db_connector/db_mysql
  std/strutils
  std/assertions

let
  db = open("localhost", "root", "secret", "store_db")

echo("--- Безопасный итератор (rows) ---")
# 'rows' загружает весь результат в память Nim, что безопасно для цикла с 'break'
for row in rows(db, sql"SELECT id, title, price FROM products WHERE price > ?", 20.0):
  let
    uid = parseInt(row[0])
    name = row[1]
    cost = parseFloat(row[2])
  echo("ID: " & $uid & " | Товар: " & name & " | Цена: " & $cost)

echo("\n--- Ленивый итератор (instantRows) ---")
# 'instantRows' не аллоцирует строки, указывая напрямую на буфер MySQL C API
for row in instantRows(db, sql"SELECT title, price FROM products"):
  let
    title = row[0]
    priceStr = row[1]
  # Пропускаем товары без цены или с нулевой ценой
  if len(priceStr) > 0 and parseFloat(priceStr) > 0.0:
    echo(title & " доступен по цене: " & priceStr)

echo("\n--- Получение метаданных столбцов ---")
var
  # Структура для хранения информации о типах и свойствах полей
  cols: DbColumns
# Итератор инициализирует 'cols' при первом вызове. Строки нам не нужны.
for _ in instantRows(db, cols, sql"SELECT * FROM products LIMIT 0"):
  discard

for col in cols:
  echo("Столбец: " & col.name & " | Тип MySQL: " & col.typ.name &
       " | Таблица: " & col.tableName & " | Первичный ключ: " & $col.primaryKey)

echo("\n--- Получение одиночного значения ---")
let
  firstProduct = getValue(db, sql"SELECT title FROM products ORDER BY id LIMIT 1")
echo("Первый товар в каталоге: " & firstProduct)

# Всегда закрывайте соединение после завершения работы
close(db)
```

### 3. Подсчёт изменений, ручное экранирование и обработка ошибок
```nim
import
  db_connector/db_mysql
  std/assertions

let
  db = open("localhost", "root", "secret", "store_db")

echo("--- Подсчёт строк, затронутых запросом ---")
let
  affectedCount = execAffectedRows(db, sql"UPDATE products SET stock_count = stock_count - 1 WHERE id > ?", 0)
echo("Списано единиц товара: " & $affectedCount)

echo("\n--- Безопасное ручное экранирование ---")
let
  userInput = "O'Reilly & Sons \"Special\" Ltd."
  # dbQuote заменяет одинарные/двойные кавычки и управляющие символы
  # в соответствии со стандартом экранирования MySQL
  safeInput = dbQuote(userInput)
# Динамическая сборка запроса (использовать только когда ? не подходит)
exec(db, sql"INSERT INTO products (title, price, stock_count) VALUES (" & safeInput & ", 0.0, 10)")

echo("\n--- Обработка ошибок ---")
try:
  # Попытка выполнить запрос к несуществующей таблице
  exec(db, sql"SELECT * FROM non_existent_table")
except DbError:
  let
    errMsg = getCurrentExceptionMsg()
  echo("Поймано ожидаемое исключение: " & errMsg)

# Закрываем соединение
close(db)
```

## 📖 Подробные пояснения к архитектуре

### Почему `seq[string]` для строк?
В исходном коде явно указано, что `Row` реализован как `seq[string]`. Это сделано по трём причинам:
1. **Нативность:** Ближе всего к базовому C-API MySQL (`MYSQL_ROW` — это массив `char*`), минимизируя накладные расходы на преобразование типов на стороне клиента.
2. **Абстракция:** MySQL поддерживает десятки типов (`DECIMAL`, `DATETIME`, `JSON`, `ENUM`, `SET`, `BLOB` и др.). Приведение всего к строке скрывает эту сложность от пользователя и упрощает логику драйвера.
3. **Удобство проброса:** Если данные нужно просто логировать, передать в другой запрос или сериализовать в JSON/XML, строковое представление является универсальным форматом.

### Как работает `InstantRow`?
`InstantRow` не копирует данные в память Nim при каждой итерации. Вместо этого он хранит указатель `row: cstringArray` на внутренний буфер, возвращаемый функцией `mysql_fetch_row()`. Операция `row[col]` вызывает `$row.row[col]` напрямую. Это экономит память и ускоряет чтение огромных выборок, но требует, чтобы доступ к данным происходил **только внутри тела цикла**. После завершения итерации буфер освобождается функцией `mysql_free_result()`, и попытка обратиться к `row` приведёт к неопределённому поведению или сегфолту.

### Параметризация и безопасность (`?`)
В `db_mysql` нет поддержки серверных подготовленных выражений. Все параметры подставляются на стороне клиента:
1. Запрос форматируется через `dbFormat`.
2. Каждый аргумент преобразуется в строку (`$`), а затем экранируется через `dbQuote`.
3. Итоговый SQL-запрос отправляется в `mysql_real_query`.
Это полностью исключает риск SQL-инъекций при использовании `?`, но требует выделения памяти для каждой строки запроса. Для массовых операций в высоконагруженных системах рекомендуется вручную использовать `START TRANSACTION` / `COMMIT`, как показано в примерах.

### Возврат `AUTO_INCREMENT` ID
В отличие от PostgreSQL (`RETURNING id`) или SQLite (`last_insert_rowid()`), MySQL предоставляет системную функцию `LAST_INSERT_ID()`. Модуль автоматически вызывает её после успешного `INSERT`. Поскольку значение привязано к сессии соединения, оно безопасно даже при высокой конкурентности. Параметр `pkName` в функциях `tryInsert` / `insert` сохраняется исключительно для совместимости с обобщённым интерфейсом `db_common` и в данном модуле игнорируется.

## ⚠️ Важные замечания

1. **Опасность прерывания `fastRows`:** Никогда не используйте `break` внутри `fastRows`. Клиентская библиотека MySQL оставляет результат запроса в состоянии "unfetched". Следующий вызов любого запроса завершится ошибкой `Commands out of sync`. Для безопасного прерывания используйте `rows`.
2. **Особенности `dbQuote` для MySQL:** Функция корректно экранирует не только одинарные (`'`), но и двойные кавычки (`"`), обратный слеш (`\`), а также управляющие символы (`\0`, `\b`, `\t`, `\n`, `\r`, `\x1a`). Это важно при работе с бинарными данными, случайно попавшими в текстовые поля, или при миграции из других СУБД.
3. **Отсутствие `SqlPrepared`:** Данный модуль не реализует интерфейс подготовленных выражений. Если вам критична производительность парсинга запросов на сервере, рассмотрите использование прямого C-API через `mysql_stmt_*` или перейдите на `db_postgres`/`db_sqlite`.
4. **Кодировка:** `setEncoding` вызывает `mysql_set_character_set`. Изменение применяется только к текущему соединению и влияет на то, как клиент интерпретирует входящие/исходящие данные. Существующие данные в таблицах не конвертируются автоматически.
5. **Ошибки:** Все процедуры с приставкой `try` возвращают статус успеха/ошибки или `-1` без выброса исключений. Остальные процедуры при ошибке вызывают `dbError(db)`, который выбрасывает `ref DbError` с сообщением от `mysql.error()`.
6. **Совместимость типов:** При подстановке параметров через `?` все значения автоматически приводятся к строкам. Если вы передаёте `nil` или пустую строку, убедитесь, что целевой столбец допускает `NULL`, иначе MySQL вернёт ошибку `Column cannot be null`.

## 🏁 Заключение
Пакет `db_mysql` предоставляет надёжный и простой в использовании интерфейс к MySQL. Строгое разделение на быстрые/безопасные итераторы, автоматическая работа с метаданными столбцов (`DbType`), встроенное экранирование в соответствии со стандартами MySQL и прозрачная обработка `AUTO_INCREMENT` делают его пригодным как для скриптов администрирования, так и для высоконагруженных веб-приложений на Nim.
