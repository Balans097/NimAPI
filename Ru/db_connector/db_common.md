
# 📘 Документация пакета `db_common`

## 🔍 Введение
`db_common` — фундаментальный модуль пакета `db_connector`, предоставляющий унифицированную систему типов, эффектов и исключений для всех специализированных драйверов базы данных (`db_sqlite`, `db_postgres`, `db_mysql`, `db_odbc`). Модуль гарантирует согласованность API, абстрагируя особенности конкретных СУБД за единой моделью мета-данных и строгой типизацией запросов.

> **Примечание:** Модуль не предназначен для прямого подключения в пользовательском коде в большинстве случаев. Он автоматически экспортируется драйверами через `export db_common`. Изучение этого модуля необходимо для понимания архитектуры системы типов и эффектов, используемой во всех `db_*` пакетах.

## 📦 Установка
Для использования типов модуля достаточно установить основной пакет:
```bash
nimble install db_connector
```

## 🧱 Основные типы данных

| Тип | Описание | Назначение |
|-----|----------|------------|
| `SqlQuery` | `distinct string` | Обёртка над строкой для явного обозначения SQL-запросов. Позволяет компилятору отличать запросы от обычных строк. |
| `DbTypeKind` | `enum` | Супермножество типов данных, поддерживаемых реляционными СУБД. Включает базовые (`dbInt`, `dbFloat`), строковые (`dbVarchar`), бинарные (`dbBlob`), гео-типы (`dbPoint`, `dbCircle`) и пользовательские расширения (`dbUser1`..`dbUser5`). |
| `DbType` | `object` | Описывает тип столбца или параметра. Содержит поля: `kind`, `notNull`, `name`, `size`, `maxReprLen`, `precision`, `scale`, `min`, `max`, `validValues`. |
| `DbColumn` | `object` | Мета-информация о столбце таблицы. Содержит: `name`, `tableName`, `typ` (тип `DbType`), `primaryKey`, `foreignKey`. |
| `DbColumns` | `seq[DbColumn]` | Коллекция метаданных всех столбцов, возвращаемых запросом. |

### 📊 Детальная структура `DbType`
```nim
DbType = object
  kind*: DbTypeKind       # Категория типа (см. DbTypeKind)
  notNull*: bool          # Флаг запрета значений NULL
  name*: string           # Имя типа в терминах СУБД (например, "VARCHAR", "INT8")
  size*: Natural          # Фиксированный размер типа в байтах (0 для переменных)
  maxReprLen*: Natural    # Максимальная длина строкового представления
  precision*, scale*: Natural # Точность и масштаб для чисел с фиксированной точкой
  min*, max*: BiggestInt  # Допустимый диапазон значений (для целых чисел)
  validValues*: seq[string] # Разрешённые значения для ENUM/SET
```

## ⚡ Система эффектов и исключений
Модуль расширяет стандартную систему эффектов Nim для явного отслеживания операций с БД:

| Эффект/Исключение | Описание |
|-------------------|----------|
| `DbEffect` | Базовый эффект, наследуемый от `IOEffect`. Обозначает любую операцию с базой данных. |
| `ReadDbEffect` | Обозначает операции чтения (`SELECT`, `FETCH`). Наследуется от `DbEffect`. |
| `WriteDbEffect` | Обозначает операции записи/модификации (`INSERT`, `UPDATE`, `DELETE`). Наследуется от `DbEffect`. |
| `DbError` | Исключение, наследуемое от `IOError`. Выбрасывается при любой ошибке драйвера или СУБД. |

## 🛠 Утилиты и макросы
- `sql(query: string): SqlQuery` — шаблон для преобразования строки в типизированный запрос. В будущих версиях может включать статическую проверку синтаксиса.
- `dbError(msg: string)` — процедура для явного вызова исключения `DbError` с пользовательским сообщением.

## 💻 Примеры использования

### 1. Инспекция метаданных столбцов (`DbType`, `DbColumn`)
```nim
import
  db_connector/db_sqlite  # Экспортирует db_common
  std/assertions

let
  db = open(":memory:", "", "", "")

# Создаём таблицу для демонстрации мета-данных
exec(db, sql("CREATE TABLE sensors (id SERIAL PRIMARY KEY, reading DECIMAL(10,3), active BOOL)"))

var
  cols: DbColumns

# Получаем структуру таблицы через стандартный итератор
for _ in instantRows(db, cols, sql("SELECT * FROM sensors LIMIT 0")):
  discard

# Инспектируем каждый столбец
for col in cols:
  let
    cName = col.name
    cType = col.typ
    isPK = col.primaryKey
  echo("Столбец: " & cName)
  echo("  Тип СУБД: " & cType.name)
  echo("  Категория: " & $cType.kind)
  echo("  Первичный ключ: " & $isPK)
  
  # Проверяем числовую точность для DECIMAL
  if cType.kind == dbDecimal:
    let
      prec = cType.precision
      sc = cType.scale
    echo("  Точность: " & $prec & ", Масштаб: " & $sc)

close(db)
```

### 2. Обработка ошибок и явное управление исключениями (`DbError`)
```nim
import
  db_connector/db_postgres
  std/strutils
  std/assertions

# Функция-обёртка для безопасного выполнения запросов
proc safeQuery(db: DbConn, q: SqlQuery, args: varargs[string, `$`]): bool =
  try:
    exec(db, q, args)
    return true
  except DbError:
    let
      errMsg = getCurrentExceptionMsg()
    # Логируем или обрабатываем ошибку
    echo("Ошибка БД: " & errMsg)
    return false

let
  db = open("localhost", "user", "pass", "testdb")

# Пример успешного выполнения
let
  createOk = safeQuery(db, sql("CREATE TABLE IF NOT EXISTS logs (id INT, msg TEXT)"))
assert(createOk, "Таблица должна быть создана")

# Пример явного вызова dbError в бизнес-логике
proc validateAndInsert(db: DbConn, msg: string) =
  if len(msg) == 0:
    dbError("Сообщение лога не может быть пустым")
  exec(db, sql("INSERT INTO logs (id, msg) VALUES (1, ?)"), msg)

try:
  validateAndInsert(db, "")
except DbError:
  echo("Валидация сработала: " & getCurrentExceptionMsg())

close(db)
```

### 3. Работа с `SqlQuery` и типизацией
```nim
import
  db_connector/db_mysql
  std/assertions

# Шаблон sql() маркирует строку как запрос, что полезно для статического анализа
let
  # Явное создание типизированного запроса
  userQuery = sql("SELECT username, email FROM users WHERE status = ?")
  adminEmail = sql("SELECT email FROM users WHERE role = 'admin' LIMIT 1")

# Проверка типа во время компиляции (если включены ассерты)
assert(userQuery is SqlQuery, "Переменная должна иметь тип SqlQuery")

let
  db = open("localhost", "root", "", "mydb")

# Использование в драйвере
for row in rows(db, userQuery, "active"):
  let
    name = row[0]
    email = row[1]
  echo("Пользователь: " & name & ", Почта: " & email)

close(db)
```

## 📖 Подробные пояснения к архитектуре

### Почему `SqlQuery` реализован как `distinct string`?
Использование `distinct` создаёт новый тип, несовместимый с обычным `string` на уровне системы типов. Это решает три задачи:
1. **Семантическая ясность:** Компилятор и разработчик сразу видят, где передаются сырые данные, а где SQL-инструкции.
2. **Будущая валидация:** В комментариях к коду указано, что при включённых ассертах (`assertions`) шаблон `sql` может проверять синтаксис запроса на этапе компиляции или рантайма.
3. **Защита от конкатенации:** Препятствует случайному склеиванию запросов через `&` без явного приведения типов, снижая риск ошибок форматирования.

### Супермножество `DbTypeKind`
Реляционные СУБД имеют радикально разные системы типов. Например, в PostgreSQL есть `JSONB` и `INET`, в SQLite их нет, а в MySQL есть `ENUM` и `SET`. `DbTypeKind` выступает как унифицированный словарь:
- Базовые типы (`dbInt`, `dbFloat`, `dbVarchar`) отображаются напрямую.
- Специфичные типы (`dbUuid`, `dbGeometry`, `dbTimestamp`) охватывают наиболее распространённые расширения.
- Пользовательские слоты (`dbUser1`..`dbUser5`)预留 для кастомных драйверов или плагинов, позволяя расширять систему без нарушения обратной совместимости.

### Система эффектов (`ReadDbEffect`, `WriteDbEffect`)
Nim поддерживает строгий трекинг побочных эффектов. Разделение на `Read` и `Write` позволяет:
- Компилятору оптимизировать код, зная, что функция только читает данные.
- Разработчикам помечать функции как `.raises: [DbError]` или `.tags: [ReadDbEffect]`, гарантируя прозрачность потоков данных.
- Статическим анализаторам находить места, где чистые функции неожиданно вызывают запись в БД.

## ⚠️ Важные замечания

1. **Импортирование:** Вам не нужно писать `import db_common` вручную. Любой драйвер (`db_sqlite`, `db_postgres` и т.д.) автоматически экспортирует его содержимое через `export db_common`.
2. **NULL-значения в мета-данных:** Поля `min`, `max`, `validValues` заполняются только для соответствующих типов (`dbInt`, `dbEnum` и т.д.). Для строковых или бинарных типов они остаются пустыми. Всегда проверяйте `kind` перед чтением специфичных полей.
3. `SqlQuery` **не экранирует данные:** Шаблон `sql()` лишь маркирует строку. Подстановка параметров по-прежнему должна выполняться через `?` и механизмы драйвера (`dbFormat`, `dbQuote`). Никогда не конкатенируйте пользовательский ввод внутри `sql("...")` напрямую.
4. **Совместимость версий:** Поля `DbType` (такие как `precision`, `scale`, `foreignKey`) могут быть не заполнены старыми драйверами или версиями СУБД, которые не предоставляют соответствующие мета-данные через свои C-API. В таких случаях поля принимают значения по умолчанию (`0`, `""`, `false`).

## 🏁 Заключение
`db_common` является архитектурным ядром пакета `db_connector`, обеспечивающим строгую типизацию, единообразную обработку ошибок и прозрачное отслеживание эффектов доступа к данным. Понимание структуры `DbType`, `DbColumn` и системы эффектов позволяет писать переносимый, безопасный и высокопроизводительный код, работающий с любой поддерживаемой СУБД без изменения бизнес-логики.
