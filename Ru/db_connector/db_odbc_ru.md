
# 📘 Документация пакета `db_odbc`

## 🔍 Введение
`db_odbc` — высокоуровневая обёртка над стандартным интерфейсом ODBC (Open Database Connectivity) для языка программирования Nim. Модуль предоставляет унифицированный API для работы с реляционными данными и позволяет подключаться к любой СУБД, имеющей установленный ODBC-драйвер (Microsoft SQL Server, Oracle, PostgreSQL, MySQL, SQLite и др.). Поддерживается клиентская подстановка параметров через маркер `?`, а также безопасные и быстрые итераторы для выборки строк.

> **Примечание:** Модуль не реализует ORM-механизмы. Для сохранения универсальности и максимальной совместимости с разнородными драйверами, все строки возвращаются как `seq[string]`, а значения `NULL` преобразуются в пустые строки `""`. Серверные подготовленные выражения (`SqlPrepared`) в данной реализации не поддерживаются.

## 📦 Установка
Для использования модуля необходимо установить пакет `db_connector`:
```bash
nimble install db_connector
```

## 🧱 Основные типы данных

| Тип | Описание | Назначение |
|-----|----------|------------|
| `DbConn` | `tuple[hDb, env, stmt]` | Дескриптор активного соединения. Содержит указатели на окружение, соединение и текущий оператор ODBC. |
| `Row` | `seq[string]` | Представляет одну строку результата запроса. Все значения приводятся к строковому типу. |
| `InstantRow` | `tuple[row, len]` | Лёгкий дескриптор, содержащий срез данных строки и количество столбцов. Позволяет извлекать значения «по требованию» внутри итератора. |
| `DbType` | Структура | Содержит метаданные типа столбца (`kind`, `size`, `name`, `tableName` и др.). Экспортируется из `db_common`. |
| `DbColumns` | `seq[DbType]` | Коллекция метаданных столбцов. В `db_odbc` автоматическое заполнение не реализовано, тип доступен для ручной обработки. |

## ⚙️ Базовый API

### 🔌 Управление соединением
- `open(connection, user, password, database): DbConn` — открывает соединение. **Важно:** параметр `database` игнорируется драйвером ODBC; имя БД указывается в строке `connection` (через DSN или connection string).
- `close(db: DbConn)` — безопасно закрывает соединение, освобождает дескрипторы `env`, `hDb` и `stmt`.
- `setEncoding(db: DbConn, encoding: string): bool` — **не реализован** для ODBC. При вызове генерируется ошибка.

### 📝 Выполнение запросов
- `exec(db, query, args)` — выполняет запрос. При ошибке выбрасывает `DbError`.
- `tryExec(db, query, args): bool` — выполняет запрос, возвращает `true` при успехе, `false` при ошибке (без выброса исключений).
- `execAffectedRows(db, query, args): int64` — выполняет запрос и возвращает количество изменённых строк через вызов `SQLRowCount`.

### 🔍 Выборка данных
- `fastRows(db, query, args): iterator Row` — быстрый потоковый итератор. **Внимание:** прерывание цикла (`break`) оставляет дескриптор в неопределённом состоянии и вызовет ошибку при следующем запросе.
- `rows(db, query, args): iterator Row` — безопасный итератор. Загружает все строки в память перед итерацией, позволяет использовать `break`.
- `instantRows(db, query, args): iterator InstantRow` — возвращает дескриптор строки для ленивого доступа к столбцам.
- `getRow(db, query, args): Row` — возвращает первую строку результата. Если строк нет, возвращает пустой `Row`.
- `getAllRows(db, query, args): seq[Row]` — возвращает все строки результата в виде последовательности.
- `getValue(db, query, args): string` — возвращает значение первого столбца первой строки. При отсутствии данных возвращает `""`.

### 📊 Вставка и возврат идентификаторов
- `tryInsertId(db, query, args): int64` — выполняет `INSERT` и пытается получить сгенерированный `ID`. Модуль определяет тип СУБД через ODBC-метаданные и выполняет соответствующий запрос (`LASTVAL()`, `LAST_INSERT_ID()` и т.д.). Возвращает `-1` при ошибке или если СУБД не распознана.
- `insertId(db, query, args): int64` — аналогично, но выбрасывает `DbError` при ошибке.
- `tryInsert(db, query, pkName, args): int64` — псевдоним для `tryInsertId`. Параметр `pkName` игнорируется, сохранён для совместимости с `db_common`.
- `insert(db, query, pkName, args): int64` — псевдоним для `insertId`.

### 🛡 Утилиты
- `dbQuote(s: string): string` — экранирует одинарные кавычки (`'` → `''`) для безопасной вставки в `VARCHAR`.
- `dbError(db: DbConn)` — явно вызывает исключение `ref DbError` с текстом ошибки, полученным через `SQLErr`.
- `sqlGetDBMS(db: DbConn): string` — внутренняя утилита, возвращающая имя СУБД (используется в `tryInsertId`).

## 💻 Примеры использования

### 1. Подключение, создание таблицы и транзакционная вставка
```nim
import
  db_connector/db_odbc
  std/math
  std/assertions

let
  # Открываем соединение. Для ODBC в 'connection' передаётся DSN или строка подключения.
  # Параметры user/password/database передаются драйверу, но 'database' часто игнорируется.
  db = open("my_dsn_name", "app_user", "secret_pass", "")

# Очищаем окружение и создаём таблицу
exec(db, sql"DROP TABLE IF EXISTS inventory")
exec(db, sql"""
  CREATE TABLE inventory (
    item_id INT PRIMARY KEY,
    item_name VARCHAR(100) NOT NULL,
    price DECIMAL(10, 2)
  )
""")

# Одиночная вставка с подстановкой параметров
exec(db, sql"INSERT INTO inventory (item_id, item_name, price) VALUES (?, ?, ?)",
     101, "Steel Gear", 45.50)

# Пакетная вставка внутри транзакции для производительности
exec(db, sql"BEGIN")
for i in 1 .. 5:
  let
    code = 100 + i
    label = "Component_" & $i
    cost = sqrt(float(i)) * 12.5
  exec(db, sql"INSERT INTO inventory (item_id, item_name, price) VALUES (?, ?, ?)",
       code, label, cost)
exec(db, sql"COMMIT")

# Попытка получить ID (работает только если драйвер вернул поддерживаемое имя СУБД)
let
  newId = tryInsertId(db, sql"INSERT INTO inventory (item_id, item_name, price) VALUES (?, ?, ?)",
                      200, "Final Assembly", 120.00)
if newId >= 0:
  echo("Успешно вставлен элемент. Возвращённый ID: " & $newId)
else:
  echo("Получение ID не поддерживается данной СУБД или произошла ошибка")

# Корректное освобождение ресурсов
close(db)
```

### 2. Выборка данных и ленивый доступ через `InstantRow`
```nim
import
  db_connector/db_odbc
  std/strutils
  std/assertions

let
  db = open("my_dsn_name", "app_user", "secret_pass", "")

echo("--- Безопасный итератор (rows) ---")
# 'rows' загружает весь набор в память, позволяя безопасно использовать 'break'
for row in rows(db, sql"SELECT item_id, item_name, price FROM inventory WHERE price > ?", 20.00):
  let
    uid = parseInt(row[0])
    name = row[1]
    cost = parseFloat(row[2])
  echo("ID: " & $uid & " | Наименование: " & name & " | Цена: " & $cost)

echo("\n--- Ленивый итератор (instantRows) ---")
# 'instantRows' возвращает кортеж (row: seq[string], len: int)
for row in instantRows(db, sql"SELECT item_name, price FROM inventory"):
  # Доступ к столбцам по индексу. Дескриптор валиден только внутри цикла.
  let
    itemName = row[0]
    priceStr = row[1]
  if len(priceStr) > 0 and parseFloat(priceStr) > 0.0:
    echo(itemName & " доступен в наличии.")

echo("\n--- Получение одиночного значения ---")
let
  firstItem = getValue(db, sql"SELECT item_name FROM inventory ORDER BY item_id LIMIT 1")
echo("Первый элемент: " & firstItem)

close(db)
```

### 3. Подсчёт изменений, ручное экранирование и обработка ошибок
```nim
import
  db_connector/db_odbc
  std/assertions

let
  db = open("my_dsn_name", "app_user", "secret_pass", "")

echo("--- Подсчёт строк, затронутых запросом ---")
let
  affectedCount = execAffectedRows(db, sql"UPDATE inventory SET price = price * 1.05 WHERE item_id > ?", 100)
echo("Цены обновлены для записей: " & $affectedCount)

echo("\n--- Безопасное ручное экранирование ---")
let
  userInput = "Special 'Sale' Item"
  # dbQuote заменяет одинарные кавычки на две, соответствуя SQL-стандарту
  safeInput = dbQuote(userInput)
# Динамическая сборка (использовать только когда параметризация '?' невозможна)
exec(db, sql"INSERT INTO inventory (item_id, item_name, price) VALUES (999, " & safeInput & ", 0.00)")

echo("\n--- Обработка исключений ---")
try:
  # Попытка выполнить некорректный запрос
  exec(db, sql"SELECT * FROM nonexistent_table WHERE id = 1")
except DbError:
  let
    errMsg = getCurrentExceptionMsg()
  echo("Поймано ожидаемое исключение БД: " & errMsg)

close(db)
```

## 📖 Подробные пояснения к архитектуре

### Почему `seq[string]` для строк?
В исходном коде `Row` реализован как `seq[string]`. Это обусловлено природой ODBC:
1. **Универсальность:** ODBC абстрагирует десятки разных СУБД с несовместимыми системами типов. Приведение всех значений к строке на стороне клиента (`SQL_C_CHAR`) гарантирует, что модуль не будет зависеть от специфичных бинарных форматов драйверов.
2. **Минимизация зависимостей:** Отсутствие необходимости линковаться с дополнительными библиотеками конвертации типов (например, для `DECIMAL` или `DATETIME`).
3. **Проброс данных:** Строковое представление идеально подходит для логирования, сериализации в JSON/CSV или передачи в текстовые поля других запросов.

### Как работает `InstantRow` в ODBC?
В отличие от драйверов, возвращающих указатели на сырые буферы (`PStmt` или `PPGresult`), `db_odbc` определяет `InstantRow` как кортеж `tuple[row: seq[string], len: int]`. При каждой итерации модуль вызывает `SQLGetData` для каждого столбца, заполняет временный `seq[string]` и передаёт его копию в кортеж. Это делает работу с `InstantRow` относительно безопасной, но всё же требует, чтобы обращение к данным происходило **только внутри тела итератора**, так как внутренний буфер драйвера может быть переиспользован при следующем `SQLFetch`.

### Параметризация и безопасность (`?`)
Модуль не поддерживает серверные подготовленные выражения. Все параметры подставляются на стороне клиента:
1. Запрос форматируется через `dbFormat`.
2. Каждый аргумент преобразуется в строку (`$`), затем экранируется через `dbQuote`.
3. Итоговый SQL передаётся в `SQLExecDirect` или `SQLPrepare` + `SQLExecute`.
При использовании `?` риск SQL-инъекций полностью исключён. Для массовых операций настоятельно рекомендуется оборачивать вставки в `BEGIN` / `COMMIT`, чтобы минимизировать накладные расходы на транзакции.

### Механизм получения `AUTO_INCREMENT` / `SEQUENCE` ID
Функция `tryInsertId` использует мета-запрос ODBC `SQL_DBMS_NAME` для определения имени СУБД. На основе ответа выполняется соответствующий SQL-запрос:
- `postgresql` → `SELECT LASTVAL();`
- `mysql` → `SELECT LAST_INSERT_ID();`
- `sqlite` → `SELECT LAST_INSERT_ROWID();`
- `microsoft sql server` → `SELECT SCOPE_IDENTITY();`
- `oracle` → `SELECT id.currval FROM DUAL;`
Если имя СУБД не совпадает с ожидаемым или запрос завершается ошибкой, функция возвращает `-1`. Это элегантный способ кросс-платформенной совместимости, но он требует дополнительных сетевых раунд-трипов.

## ⚠️ Важные замечания

1. **Опасность прерывания `fastRows`:** Никогда не используйте `break` внутри `fastRows`. Драйвер ODBC оставляет курсор в состоянии "частично вычитано", и следующий вызов `exec` или `tryExec` завершится ошибкой синхронизации команд. Для безопасного выхода из цикла используйте `rows`.
2. **Игнорирование параметра `database` в `open`:** В `db_odbc` четвёртый аргумент `open()` зарезервирован для сигнатурной совместимости с другими модулями. Имя базы данных должно быть указано в строке `connection` (например, `DRIVER={SQL Server};SERVER=.;DATABASE=MyDB;`).
3. **Отсутствие `setEncoding`:** Функция явно не реализована, так как управление кодировкой в ODBC делегируется самому драйверу и настройкам DSN. Вызов функции приведёт к выбросу `DbError`.
4. **Экранирование в `dbQuote`:** Обрабатывает **только** одинарные кавычки (`'` → `''`). Остальные спецсимволы (управляющие символы, обратный слеш) не экранируются автоматически. Всегда предпочитайте параметризацию через `?` для строк, содержащих пользовательский ввод.
5. `NULL` **в строках:** Все `NULL`-значения из базы данных преобразуются в пустые строки `""`. При парсинге чисел или дат из таких полей необходимо явно проверять `len(row[col]) > 0`.
6. **Обработка ошибок:** Процедуры с префиксом `try` поглощают исключения `DbError` и возвращают статусный код (`bool` или `-1`). Остальные процедуры при ошибке вызывают `dbError()`, которая собирает информацию через `SQLErr` (State, NativeError, Message) и выбрасывает `ref DbError`.

## 🏁 Заключение
Пакет `db_odbc` предоставляет надежный, кросс-платформенный интерфейс для работы с гетерогенными базами данных через стандарт ODBC. Строгое разделение на быстрые/безопасные итераторы, автоматическое определение СУБД для получения `ID` и унифицированная строковая модель данных делают его идеальным решением для корпоративных приложений на Nim, где требуется поддержка множества различных бэкендов без изменения бизнес-логики доступа к данным.
